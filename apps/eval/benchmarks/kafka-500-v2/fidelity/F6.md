# Arm `F6` — agent-curated from empty, free structure

Source: Zhou et al. §3: *"Agent-curated store is built from empty over the stream by the management
agent of Equation 1, which decides both what to write and how to organize it; unlike the constrained
variants above, it varies content and organization together."* App. A.1 prompt. Plan row F6:
*"Curated free-form — empty store, no seeded layout, only the goal in CLAUDE.md; the agent invents its
own structure; whether our layout helps or hinders the agent."* Implementation:
`stores/llm_files.py:388-389`; prompt `prompts.py:122-123`. Shared decisions: [README.md](README.md).

F6 is the arm **closest to the paper's headline variant**. The A.1 fidelity table in
[F4-fact.md](F4-fact.md) applies in full; only the differences specific to F6 are listed here.

## What an examiner should know

- F6 vs F5 is the plan's question *"whether our layout helps or hinders the agent"*; F6 vs
  F4-fact/entity/topic asks whether *any* prescribed granularity beats a free one.
- Because nothing is prescribed, F6 is where the builder-model confound and the window size matter
  most: a weaker builder (Haiku 4.5 vs the paper's gpt-5.4-mini at high effort) and larger chunks
  both push toward the paper's observed erosion. Do not read an F6 loss as "free structure is bad"
  without the model/window caveat.
- Nothing about F6's tree is verified except the shared checks; `_unprocessed/` may appear
  (README §5) and is, by the prompt, off-limits to the builder — so a failed window's events are
  never integrated into F6's own structure later (same as F4/F5).
- All F6 store states are reproducible from the transcripts (`llm_files.py:236-243`) — every file
  can be traced to the turn that wrote it.
