# Arm `F0` — verbatim dump, one file per event

Source: Zhou et al. §3: *"Verbatim dump copies the stream into the store wholesale: one file per
session, content verbatim, each file's description stating only the session's number, date, and
speakers; a deterministic flat store built at zero model cost, the zero-curation baseline."*
Plan row F0: *"events/YYYY/MM/DD/<id>.md, one file per event, frontmatter = event metadata; commit
per fold."* Implementation: `stores/deterministic.py:15-23`, `stores/base.py:69-81`.
Shared decisions: [README.md](README.md).

| paper / plan says | what the code does | deviation (and why) |
|---|---|---|
| One file per **session**, content verbatim. | One file per **event** (`deterministic.py:20-23`): `events/YYYY/MM/DD/<safe-id>.md` (`base.py:79-81`), body = `event.text` verbatim after a YAML frontmatter (`base.py:74-76`). | Unit is the event, not a session, because the stream has no sessions (plan row F0 already says one file per event). 629k files at the last checkpoint. |
| Description states *"only the session's number, date, and speakers"*. | Frontmatter = `id, time, type, entities, actor, title` (`base.py:69-71`). | `title` and `entities` are more than the paper's minimal description — they are the event's own metadata, not synthesis. No `name`/`description` keys: F0 does not follow the A.1 frontmatter contract (it is the zero-curation baseline, not a curated store). |
| Flat store. | Date-partitioned folders (`YYYY/MM/DD`). | A flat directory of 629k files is unusable for `ls`; the date tree is the minimum structure that carries no content signal beyond the timestamp already in frontmatter. |
| Zero model cost, deterministic. | Code only; 1000 events per commit (`base.py:217`); commit dates and identities derive from the events so a resumed build reproduces the same hashes (`base.py:1-9`, `32-37`, `301-303`). | none |
| Reader: Zhou's file tools (view, grep, toc, section read). | Harnext's research agent via `context_research` (`mcp_server.py` kind `research`; `harnext_mcp/research.py`), read-only Claude Code tools (Read, Glob, Grep, LS) on Haiku 4.5. | Shared with all file arms; the reader is the product's, not the paper's; see F4-entity.md. |

## What an examiner should know

- F0 is the substrate of F2 (moved intact) and F3 (`_intake/`), and the exact content of every
  `_unprocessed/` fallback in the LLM arms: the `render()` function is shared (`base.py:74`).
- `safe_id` (`base.py:53-57`) slugs ids that contain characters outside `[A-Za-z0-9._-]` and
  appends an 8-hex hash; the frontmatter `id` keeps the original, so grep for an exact id must
  target the frontmatter, not the filename.
- Text is leak-safe by construction of the stream (`stream.py` renderers whitelist fields;
  "`text` must not contain anything later than `time`", E2-V2-DESIGN); F0 adds nothing.
- Extraction size: ≈1 GB / 630k files per checkout (E2-V2-DESIGN "Checkouts"), which is why file
  arms are extracted on demand and LRU-evicted rather than exported per checkpoint.
- F0's answerable set equals `S-tools`' in content; the difference under test is access (grep over
  markdown vs structured CLIs over SQLite).
