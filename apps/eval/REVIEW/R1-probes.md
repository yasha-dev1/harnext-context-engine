# R1 — E2/E4 probes, gold, snapshots, and leakage review

1. **Blocker — `apps/eval/src/harnext_eval/probes/gen.py:29-46`, `apps/eval/src/harnext_eval/probes/schema.py:14-17`, `apps/eval/src/harnext_eval/types.py:21-30`.** **Spec:** §7 E2 defines 300 probes per corpus, 60 in each of five families; code localisation is a variation within multi-source, so `macro_acc` is the mean of five family scores. **Code:** it creates and independently samples six families, including a separate `code_location` family, so the default is 360 probes and multi-source receives twice the sampling weight. **Minimal fix:** sample 60 total multi-source probes with an explicit link/code subtype, retain exactly five `family` values, and reject a frozen set that is not 300 probes.

2. **Major — `apps/eval/src/harnext_eval/probes/gen.py:21-49`, `apps/eval/src/harnext_eval/probes/schema.py:62-101`, `apps/eval/tests/test_probes/test_generators.py:35-47`.** **Spec:** §7 E2 requires at least 150 entities as well as 60 probes per family. **Code:** no global entity-cardinality check exists; round-robin sampling can repeatedly use a small set, and the test accepts only two entities per family. **Minimal fix:** enforce `len({p.entity}) >= 150` on the complete 300-probe set and test the exact population constraints.

3. **Blocker — `apps/eval/src/harnext_eval/probes/gold.py:41-85`, `apps/eval/src/harnext_eval/probes/gen_extraction.py:25-42`.** **Spec:** §4 says state gold includes JIRA initial/current fields, PR merged/closed state, KIP vote outcome and thread-answer state; Corpus S comes from the world-state dump at T. **Code:** `PythonGold` only records changelog/direct `{field,to}` transitions, and every extraction generator uses it for every corpus. Initial issue fields, PR/KIP/mail state, plans, and OrgForge world-state dumps have no derivation path. **Minimal fix:** implement corpus-specific gold readers covering every catalogue quantity, including initial values and world-state snapshots, and generate/validate probes from those readers.

4. **Major — `apps/eval/src/harnext_eval/probes/gold.py:88-177`.** **Spec:** §7 E2 requires two independent temporal/update derivations: Python changelog replay and SQL over the raw JIRA export. **Code:** the SQL database is populated by serialising the same already-normalised `EvalEvent` objects used by Python, with substantially duplicated canonicalisation/transition semantics. This is not SQL over the raw export and common normalisation bugs will agree. **Minimal fix:** load the untouched JIRA export into an independently defined SQL schema/query and compare it with the EvalEvent/Python replay.

5. **Major — `apps/eval/src/harnext_eval/probes/gen_extraction.py:37-42`, `apps/eval/src/harnext_eval/probes/gen_temporal.py:41-44`, `apps/eval/src/harnext_eval/probes/gen_update.py:38-41`.** **Spec:** disagreements between the two gold implementations are resolved before keeping a probe, and G1 requires/report two-way agreement of at least 98%. **Code:** disagreement candidates are silently skipped; no denominator, disagreement list, corrected-probe list, or agreement rate is emitted. **Minimal fix:** persist both derivations and every disagreement, resolve or explicitly exclude them, report the rate, and stop generation below 98%.

6. **Blocker — `apps/eval/src/harnext_eval/probes/gen_code_location.py:23-45`, `apps/eval/src/harnext_eval/probes/gen_code_location.py:56-84`.** **Spec:** E2 multi-source(code) asks about files/modules at a T after the linked PR merged (§7 lines 288-289), while future-within-14-days localisation is E4 action gold. **Code:** E2 `code_location` probes deliberately choose T before the merge and derive gold from `(T, T+14d]`; all `source_event_ids` and the answer are post-T and unavailable to every E2 arm. **Minimal fix:** split the generators: E2 chooses T after qualifying merges and uses visible history; E4 alone may derive future action/localisation gold.

7. **Major — `apps/eval/src/harnext_eval/probes/gen_multisource.py:13-59`.** **Spec:** §4 mandates regex joins on issue/KIP keys in commits, threads and PR titles, with join precision/recall reported; E2 asks which PR/thread/ticket relates to the entity. **Code:** it emits only PR numbers, mail thread IDs, or issue-link keys; commits and tickets are omitted. It accepts keys from subject, body and structured `issue_key`, not the mandated PR-title/thread/commit key locations, and no join precision/recall is produced. **Minimal fix:** implement exactly the preregistered joins and target types, retain join provenance, and report audited precision/recall.

8. **Major — `apps/eval/src/harnext_eval/probes/gen_abstention.py:21-55`.** **Spec:** abstention probes concern a field or entity genuinely absent from the evaluation window and must pass the non-triviality floors. **Code:** entities are named `MISSING-<seed>-<index>` and fields `absent_field_<index>`, making the intended answer explicit in the question and allowing a model-prior shortcut; absence is not checked against aliases or realistic schema. **Minimal fix:** sample plausible held-out real/simulated entities and valid field names absent at T, verify absence across all sources, and discard sets that fail the A0 floor.

9. **Minor — `apps/eval/src/harnext_eval/probes/gen.py:52-62`.** **Spec:** §3.3/§7 freezes the probe hash in `PREREG.md`. **Code:** generation writes only a `.sha256` sidecar and never records or verifies the preregistered hash. **Minimal fix:** require an expected prereg hash or emit a manifest entry that the preregistration workflow must atomically accept before any run.

**Verdict:** The experiment is not faithful to the specification and current E2/E4 results cannot be trusted. The blockers are not cosmetic: the E2 population/gold includes impossible post-T code answers and omits large parts of both corpora's state oracle; the leakage gate is supplied evidence that makes its core assertion true by construction; the registered provider paths are fake; Corpus S E4 gold is not world-state gold; batch E4 is only an input substring check; and the reported primary contrasts do not implement the specified estimands or clustered 10,000-resample inference. Before results are usable, the team must rebuild corpus-specific/two-way gold, generate the exact frozen populations, use ledger-verified snapshots and a single fail-closed gate, run pinned real providers with exact token budgets, implement the actual E4 batch/judge/tool paths, enforce every validity gate, and add literal formula/leakage tests rather than existence tests.
