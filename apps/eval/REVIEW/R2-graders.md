Findings 8/9 have the correct equal-family implementation, but the cited test does not independently lock the 10,000-draw requirement or the insufficient-cluster failure. Claimed fixes 4, 5, 6, and 11 are incomplete or false for the reasons below. I also ran `make eval-smoke`; the completed run is `apps/eval/out/20260830T212125Z-baseline-minimal`. 1. **blocker — `apps/eval/src/harnext_eval/cli.py:580-586`; `apps/eval/src/harnext_eval/e2/run.py:836-850`; `apps/eval/out/20260830T212125Z-baseline-minimal/e2/seed-1/metrics.csv:32-37`; `apps/eval/tests/test_e2e3/test_e2e3.py:609-638`**  
   **Spec:** E2 A4 must read the curated S3 store and the smoke profile must exercise the same A4-versus-A3 plumbing as the real profile (§7 E2 conditions/exact score).  
   **Code:** the CLI supplies both `meta["store"]` (the configured baseline layout, S0 in smoke) and `meta["store_handle"]` (S3), but `E2Experiment.run` reads only `meta["store"]`. `evaluate_e2` then relabels A4 to that layout. The fresh mandated smoke run contains an `S0` arm, no A4 arm, and an empty `contrasts.csv`; its primary has no A4-A3 estimate. The cited R1 test calls `evaluate_e2` directly with an S3 handle, so it cannot fail on this registry integration bug. This also makes the fake-provider smoke comparison vacuous for the headline arm: it measures the dump store instead of curated context.  
   **Minimal fix:** have the E2 adapter require/select `store_handle` for A4 (and assert `layout == "S3"`), keep the configured baseline store separate, fail if the A4-A3 row is absent, and add a registry/CLI smoke test asserting an A4 row and non-empty paired contrast.

2. **blocker — `apps/eval/src/harnext_eval/config.py:67-69`; `apps/eval/src/harnext_eval/providers/factory.py:93-103`; `apps/eval/configs/s3-curated.yaml:11-13`; `apps/eval/src/harnext_eval/e2/run.py:502-509`; `apps/eval/tests/test_e2e3/test_e2e3.py:609-637`**

3. **blocker — `apps/eval/src/harnext_eval/e2/run.py:725-742,767-777,836-855`; `apps/eval/src/harnext_eval/grade/claims.py:158-168`**

4. **major — `apps/eval/src/harnext_eval/grade/action.py:95-106`; `apps/eval/tests/test_grade/test_localisation_action.py:61-98`**  
   **Spec:** literally, `Q = mean(field_em, id_cov)`; tasks lacking either primary component are invalid, not reweighted (§7 E4 Exact scores).  
   **Code:** the shared grader removes `None` components and averages what remains, so a prediction with one correct component and no required IDs receives Q=1.0. E4's runner has separately reimplemented the correct fail-closed formula at `apps/eval/src/harnext_eval/e4/run.py:113-155`, leaving two inconsistent action graders. Tests cover a complete two-component case and unavailable gold groups but never call the shared grader with a missing `field_em` or `id_cov`.  
   **Minimal fix:** make `grade_action` reject/return an invalid grade unless both components exist, compute exactly `(field_em + id_cov) / 2`, make E4 call this single implementation, and add missing-component tests.

5. **major — `apps/eval/src/harnext_eval/grade/links.py:12-22,35-52`; `apps/eval/tests/test_grade/test_exact_links.py:36-51`**  
   **Spec:** link-set grading must accept the canonical identifiers the catalogue defines, including the explicit thread example `thread:CA+abc@mail`, and calculate set P/R/F1 (§4, §7 E2).  
   **Code:** the thread character class excludes `+`; in mixed free text, `thread:CA+abc@mail` is partially captured as `thread:ca` while other matches suppress fallback parsing. The R1 test uses only `thread:dev@kafka.apache.org/root.vote`, so it does not exercise the spec's literal identifier and would not catch the truncation. Thus R1 fix 11 is not genuine for the specified dialect.  
   **Minimal fix:** parse canonical IDs with a delimiter-aware grammar that preserves RFC-style message IDs (at least `+`, and preferably the full admitted message-id character set), reject partial matches, and add a mixed-answer exact P/R/F1 case using the spec example.

6. **major — `apps/eval/src/harnext_eval/e2/run.py:95-115`; `apps/eval/tests/test_e2e3/test_e2e3.py:532-557`**  
   **Spec:** the code multi-source subtype is graded with file precision/recall and module hit, while multi-source contributes its specified set score to the family macro (§7 E2 probe table and Exact scores).  
   **Code:** the dispatcher computes localisation metrics but replaces the scalar grade with an unregistered all-or-nothing `exact_file_set`. Partial file retrieval therefore contributes 0 to macro accuracy even though the specified file precision/recall are non-zero. The test explicitly enshrines this stricter, non-spec scalar by asserting a one-of-two-file answer has value 0.  
   **Minimal fix:** preregister and use the specified scalar for the code subtype (normally file-set F1, with file P/R and module hit retained as named secondaries), and test its literal partial-match value and its one-family macro contribution.

7. **major — `apps/eval/src/harnext_eval/e4/run.py:329-365`; `apps/eval/tests/test_e4e5/test_runs.py:361-414`**  
   **Spec:** batch-delta quality is E2 accuracy, whose exact definition is equal-weight `macro_acc = mean over families`, not a probe micro-average (§7 E2 Exact scores; §7 E4 procedure/measurements).  
   **Code:** the newly implemented batch path averages every probe grade directly (`_mean(grades)`). Unequal family counts therefore change the score and can change envelope comparisons. The R1 covering test has one extraction probe, for which macro and micro averages are necessarily identical, so it does not verify the claimed shared E2 scoring semantics. R1 fix 5 is only partially genuine.  
   **Minimal fix:** preserve probe family in the batch outcomes and call the shared E2 five-family macro implementation (failing closed on missing families); add an unequal-family-count, five-family fixture with a literal expected macro.

## Verdict — FAIL

This experiment is not yet faithful enough for trusted grader/statistics/report results. The fresh smoke profile does not run E2 A4 at all, and the supplied real profile cannot configure a non-fake embedding model or provide two mandatory E2 validation audits, so both the smoke and real parameterisations fail the requested trust standard. In addition, the shared Q and code-location scores do not match the literal formulas, Corpus-S and batch scoring fixes remain incomplete, secondary inference is partial, and the report both hides invalid primaries and floods the checks table with non-check rows. Before results can be trusted, wire S3 into E2 A4, implement/configure pinned embeddings and validity artifacts, unify the literal graders/macros, finish world-state gold and secondary inference, and make the report render typed validity plus quality/tokens/USD/latency together. **Grade: FAIL.**
