# R2 — E2 state-fidelity review

1. **blocker — `apps/eval/src/harnext_eval/config.py:67-69`; `apps/eval/src/harnext_eval/providers/factory.py:93-103`; `apps/eval/configs/s3-curated.yaml:11-13`.** The spec requires A3 to use a pinned embedding model (`docs/evaluation-spec.md:275-277`). The only accepted/configurable embedding provider is `fake`; the factory rejects every other provider, and even the real S3 profile selects `fake`. `evaluate_e2` consequently sets every such run to `non_evidentiary_smoke` (`apps/eval/src/harnext_eval/e2/run.py:502-509`) and can never produce a valid real A4-A3 primary. This makes the claimed R1 fixes for findings 4/8/25 non-genuine for the evidentiary path. **Minimal fix:** add a real pinned embedding provider with immutable model/revision configuration and pricing, select it in the S3 profile, record it in the cache/manifest, and reserve `FakeEmbeddings` for smoke.

2. **blocker — `apps/eval/src/harnext_eval/cli.py:136-169,466-518`; `apps/eval/src/harnext_eval/probes/gen.py:35-43,50-58,100-103`.** The real E2 population must be R-H1 May-June and Corpus S, 300 probes (60 per each of five families) over at least 150 entities, including the code variation (`docs/evaluation-spec.md:267-289`). The standalone generator has an `evidentiary` mode, but the registered `run` command always calls `_generate_probes` without it, uses the replay's whole window, defaults to 10 per family, supplies no raw-JIRA/resolution/join/A0 audits, and therefore defaults `multisource_code_count` to zero. There is no real-profile configuration path that assembles the specified population. The R1 claim that the full real-corpus run is supported is therefore false for the actual experiment entrypoint. **Minimal fix:** put corpus/window, exact family counts/code allocation, minimum entities, and frozen gold/join/pilot artifacts in the real profile; make `run` invoke evidentiary generation and fail closed on any population violation.

3. **blocker — `apps/eval/src/harnext_eval/probes/gen_temporal.py:36-39`; `apps/eval/src/harnext_eval/probes/gen_update.py:36-39`; `apps/eval/src/harnext_eval/probes/gen_multisource.py:61-82,143-189`.** The spec derives Corpus-S state from world-state dumps and Corpus-S links from event-graph edges (`docs/evaluation-spec.md:123-130`), and E2 applies to both corpora. Temporal and update generation explicitly reject every non-JIRA history, while multi-source generation only implements Corpus-R regex joins. `PythonGold` can parse a world-state snapshot, but the probe generators cannot create the required Corpus-S temporal/update/link families, so C2 cannot be tested on both corpora. The R1 finding-17/18 fix is only partial. **Minimal fix:** generate S temporal/update probes from successive world-state dumps/mutations, generate S multi-source gold from event-graph edges, and test a complete five-family OrgForge population.

4. **blocker — `Makefile:70-71`; `apps/eval/src/harnext_eval/cli.py:570-595`; `apps/eval/src/harnext_eval/e2/run.py:496-501,644-649`; `apps/eval/out/20260830T212314Z-baseline-minimal/e2/seed-1/results.json:52-67`.** The Round-2 focus requires a meaningful smoke run. `make eval-smoke` completed, and E2 had no rendered `False` check, but the CLI handed E2 the configured S0 store even though the same smoke run built S3. The runner relabelled the requested A4 condition as S0, `contrasts.csv` was empty, and the primary contained only `valid_primary=false`; A0, S0, and retrieve-nothing all scored the same 0.2. Thus the fake-provider smoke path is vacuous for the headline A4-A3 comparison while its checks table looks green. The cited R1 tests do not cover this integration path. **Minimal fix:** hand E2 the built S3 handle in smoke, require the A4/A3 condition matrix and a non-empty contrast as smoke checks, and show non-evidentiary status as informational rather than a passing validity check.

5. **major — `apps/eval/src/harnext_eval/e2/run.py:95-115,150-165`; `apps/eval/tests/test_e2e3/test_e2e3.py:532-557`; `apps/eval/tests/test_grade/test_exact_links.py:54-66`.** The Exact scores block literally defines exact correctness only for extraction/temporal/update/abstention, `link_F1` for multi-source, and separately names file precision/recall and module hit for the code row (`docs/evaluation-spec.md:284-291`). The code invents `exact_file_set`, makes that value the code probe's primary score, and averages it into multi-source macro accuracy. The tests assert this invented formula rather than the spec. **Minimal fix:** implement the literal registered score (or amend/preregister the spec before running); keep file P/R and module hit as named code secondaries rather than silently substituting exact-set accuracy into the primary.

6. **major — `apps/eval/src/harnext_eval/probes/gen_code_location.py:24-49,91-110`; `apps/eval/tests/test_probes/test_generators.py:146-219`.** The catalogue says qualifying PRs are merged within 14 days of T and E2 additionally requires T after merge (`docs/evaluation-spec.md:130,288`). The generator instead anchors the 14-day window to the issue's trigger, then permits T anywhere through the end of the probe period; a PR can therefore be months older than T and remain gold. The R1 test proves only that source events precede T and deliberately tests the trigger-relative implementation, so it would not catch this mismatch. **Minimal fix:** choose T after a qualifying merge and include only non-formatting title-key PRs in `[T-14d, T]`; add a regression with T more than 14 days after a merge.

7. **major — `apps/eval/src/harnext_eval/e2/arms.py:217-320,351-389`; `apps/eval/src/harnext_eval/agents/reader.py:109-159`; `apps/eval/tests/test_e2e3/test_e2e3.py:414-424`.** A4 says the fixed read agent starts at `INDEX.md`/`OVERVIEW.md` and may open files within budget (`docs/evaluation-spec.md:277,295-297`). The arm still performs a fixed heuristic traversal before the reader runs; `reader.answer` receives one already concatenated string and has no file-open tool or iterative choice. The test only asserts the heuristic's predetermined files/tool count. This is not the claimed R1 agent-navigation fix and can miss relevant files that the agent would choose from index/topic links. **Minimal fix:** give the fixed reader deterministic budgeted list/read tools, start it with the entry files, cache/log every actual tool decision, and test that question-dependent navigation can choose a relevant non-entity-path file.

8. **major — `apps/eval/src/harnext_eval/e2/arms.py:407-435`.** The retrieve-everything floor is specified as the entity's full history (`docs/evaluation-spec.md:278`). The implementation explicitly supplies the complete pre-cutoff replay for every entity. This can inflate the answerability floor with unrelated entities and does not test whether the registered entity/relationship history is sufficient. **Minimal fix:** include exact entity-owned events plus the preregistered explicit relation/join edges for that entity, without exposing unrelated replay records.

9. **major — `apps/eval/src/harnext_eval/e2/arms.py:261-273,379-389`; `apps/eval/src/harnext_eval/e2/run.py:610-625,721-778`.** Equal-budget validity must require every arm that fills the budget to land within ±10% of 8k (`docs/evaluation-spec.md:309`). `valid_primary` never includes either `budget_within_10_pct` or `budget_fill_applicable`. In addition, A4 truncates while collecting documents, then reports the already truncated selection as `original_tokens`; a near-full selection can be classified ineligible and escape the check. The R1 claim that budget failures prevent validity is false, and the budget test only proves `tokens_read <= 30` (`apps/eval/tests/test_e2e3/test_e2e3.py:331-350`). **Minimal fix:** retain eligible pre-truncation token totals/fill status per arm, require an applicable passing budget check in `valid_primary`, and add a failing A4 fill regression.

10. **major — `apps/eval/src/harnext_eval/config.py:84-93`; `apps/eval/src/harnext_eval/e2/run.py:480-512,640-649`; `apps/eval/src/harnext_eval/cli.py:589-595`.** D8 registers 2k/8k/32k read budgets, with only the 8k A4-A3 row designated primary (`docs/evaluation-spec.md:291,300,577`). E2 ignores `budgets.read_tokens`, runs only `cfg.reader.budget_tokens`, and writes no budget condition to `metrics.csv` or `contrasts.csv`. **Minimal fix:** run all registered budgets, include budget in every answer/metric/contrast key, and mark only the 8k row primary.

11. **major — `apps/eval/src/harnext_eval/cli.py:145-168`; `apps/eval/src/harnext_eval/e2/run.py:725-742,750-778,831-855`; `apps/eval/out/20260830T212314Z-baseline-minimal/e2/seed-1/results.json:16-35`.** The validity list requires independent raw-JIRA gold, a twice-run claims audit with resolutions, and a 30-probe/two-human pilot (`docs/evaluation-spec.md:304-307`). The runner accepts unauthenticated scalar values in a mapping rather than frozen audit artifacts; the registry adapter supplies only `dual_gold_agreement` and has no way to supply pilot/claims evidence. Worse, smoke derives its “SQL” side from normalized events (`source="normalised-smoke-adapter"`) but reports `dual_gold_agreement_ge_0_98` as PASS rather than not-applicable. A direct caller can make the other checks pass by passing three numbers, without any report, hash, denominator, or resolutions. **Minimal fix:** consume and hash typed gold/pilot/grader audit artifacts, validate their provenance/sample sizes/resolution rows, expose them in the real profile, and mark the normalized smoke adapter N/A.

12. **major — `apps/eval/src/harnext_eval/e2/run.py:699-714`; `apps/eval/src/harnext_eval/probes/gen.py:125-150`; `apps/eval/tests/test_probes/test_generators.py:284-294`.** The validity floor is A0 ≤0.3 on temporal/update/multi-source (`docs/evaluation-spec.md:305`). The run code micro-averages all probes across those families, so an over-threshold family can be hidden by the others, and `a0_correct.jsonl` includes extraction/abstention rather than separately flagging the specified target set. Separately, evidentiary generation incorrectly applies the 0.3 floor to abstention probes, where the exact gold is always `UNKNOWN`; the test enshrines rejection of a correctly abstaining A0. **Minimal fix:** gate and report each named target family (or an explicitly equal-weight macro), restrict A0-correct flags to that audit population, and remove abstention from the prior floor.

13. **major — `apps/eval/src/harnext_eval/probes/gen_abstention.py:52-73,105-110`; `apps/eval/tests/test_probes/test_generators.py:101-123`.** Abstention gold must be absent at the evaluated cutoff/window (`docs/evaluation-spec.md:289`). Missing-field candidates are selected because the value is absent at `probe_end`, but T is then sampled earlier without rechecking absence at T. A field that existed and was later cleared can therefore receive incorrect `UNKNOWN` gold. The test repeats the same end-of-window oracle and cannot catch the defect. **Minimal fix:** sample T first and prove the entity/field fact is absent through that T (and from the defined evaluated window), with a field-present-then-cleared regression.

14. **major — `apps/eval/src/harnext_eval/e2/run.py:364-421,640-649`; `apps/eval/src/harnext_eval/cli.py:570-595`.** Section 8 requires CIs for paired quality outputs, Holm across secondaries, cost beside every quality number, and pass^3/between-seed spread for LLM-built stores (`docs/evaluation-spec.md:503-509`). `secondary_contrasts.csv` covers only five family scores; it omits the supersession-error contrast and contains no token, dollar, tool-call, or latency columns. The primary contrast likewise has no resource/cost columns. Three configured seeds are written as isolated runs with no E2 aggregate, pass^3, or between-seed spread. This leaves the R1 finding-26 fix incomplete. **Minimal fix:** add clustered contrasts/CIs (and Holm membership) for every named quality secondary, place paired resource/cost summaries beside each quality contrast, and aggregate the three S3 seeds with pass^3/spread.

15. **major — `apps/eval/src/harnext_eval/e2/run.py:53-56,119-137,168-180`; `apps/eval/src/harnext_eval/agents/reader.py:129-136`; `apps/eval/tests/test_e2e3/test_e2e3.py:532-557`.** The spec names file precision/recall and module hit outputs for code probes (`docs/evaluation-spec.md:288-291`). They exist only inside per-answer `grade_details`; `metrics.csv` does not aggregate them or identify link-vs-code subtypes. The real reader is not asked for typed `{files, modules}` output, and the plain parser recognizes only paths containing `/` plus four hard-coded root filenames, so valid root files such as `LICENSE`, `NOTICE`, or `gradlew` are lost. The test covers only `Dockerfile` and a slash-containing extensionless path. **Minimal fix:** require a typed code response schema, parse arbitrary repository-relative paths/modules separately, add an explicit subtype column, and aggregate the three named code metrics.

16. **major — `apps/eval/src/harnext_eval/grade/links.py:12-52`; `apps/eval/tests/test_grade/test_exact_links.py:36-51`.** Corpus-R thread IDs can contain characters such as the spec's `CA+abc@mail` example (`docs/evaluation-spec.md:85`). The link regex omits `+` (and other legal Message-ID characters), so `thread:dev@kafka.apache.org/CA+abc@mail` is silently canonicalized to the collision-prone truncated ID `thread:dev@kafka.apache.org/ca`. Also, `ticket:KAFKA-2` and natural `KAFKA-2` normalize to different keys. The R1 canonical-link fix and test use only the easy `root.vote` form. **Minimal fix:** define an escaping/canonical serialization for full repository/thread/ticket IDs, parse it losslessly, and test actual Message-ID punctuation and natural ticket aliases.

17. **major — `apps/eval/configs/s3-curated.yaml:1-16`; `apps/eval/src/harnext_eval/providers/llm.py:533-582`; `apps/eval/src/harnext_eval/e2/run.py:446-477,628-693`; `apps/eval/src/harnext_eval/replay/gate.py:166-177`.** Reproducibility/output conventions require immutable model IDs/dates, prompt/schema hashes, prices, git SHA, input hashes, snapshot SHAs, and the shared `eval/out/gate.csv` (`docs/evaluation-spec.md:154,509,527,562-577`). The S3 profile has no prices; real-reader cost therefore defaults to zero. `AnthropicLLM` exposes no revision, so provider metadata records `revision="unspecified"`. The E2 manifest omits prices, git SHA, corpus/window, store snapshot SHAs, audit/join hashes, and schema hash, and the gate is written only inside the seed directory. Cached answers also reuse the original latency/usage without logging `cache_hit` in answers, so rerun latency is not the measured current-run latency. **Minimal fix:** pin/model-version and price all real providers, write the complete reproducibility manifest, append canonical gate rows to the shared ledger, and distinguish live versus replayed response latency/usage.

18. **major — `apps/eval/src/harnext_eval/e2/run.py:644-649,766-810`.** Validity failures do not propagate into the named `contrasts.csv`: its `valid` field covers only family/cluster availability, while floor, leakage, budget, audit, fake-provider, and 8k failures are added only to the separate in-memory/result `primary` object. A consumer of the spec-named contrast output can therefore read a statistically “valid” evidentiary delta from an invalid experiment. **Minimal fix:** add `valid_primary`, evidence status, and all invalid reasons/budget/provider fields to the contrast row itself, or suppress the evidentiary row when any gate fails.

19. **major — `apps/eval/tests/test_e2e3/test_e2e3.py:331-350,414-424,532-557,609-638`; `apps/eval/tests/test_probes/test_generators.py:101-123,146-219`; `apps/eval/tests/test_stores/test_layouts.py:290-333`.** The R1 “covering tests” do not verify several claimed fixes and would not fail if those claims regressed: the budget test checks only an upper bound, the A4 test tests a fixed traversal rather than agent choices, the code-score tests assert the non-spec exact-set formula, the tiny E2 test does not require `valid_primary`, budget-gate propagation, a real provider, or a non-empty A4-A3 contrast, the code-gold test does not test the 14-days-before-T boundary, the abstention test checks only end-of-window absence, and the S1/S3 fake-reader test exercises one code item rather than the five-family headline. **Minimal fix:** add mutation-sensitive tests for each validity gate and exact formula, the integrated S3 smoke condition matrix, real-profile configuration construction, Corpus-S families, and the edge cases listed above.

**R1 fix verification.** The shared ledger-backed leakage fix is genuine and its gate tests would fail without it (`apps/eval/src/harnext_eval/replay/gate.py:84-121,273-290`; `apps/eval/tests/test_replay/test_gate.py:55-170`). The A1 N=20/N=100, cutoff inclusion, exact-key selection, literal equal-family macro/10,000 resamples, provider-tokenizer seam, and complete-value supersession fixes exist and have targeted regression assertions (`apps/eval/tests/test_e2e3/test_e2e3.py:353-411,446-529,560-563`), although the tokenizer test is not an Anthropic integration test. Raw-JIRA SQL independence and Corpus-R mandated-surface joins are genuine at their narrow scope and tested (`apps/eval/tests/test_probes/test_gold.py:60-93`; `apps/eval/tests/test_probes/test_generators.py:222-257`). The remaining claimed batches are partial or not genuinely covered for the reasons in findings 1-19: notably real A3/provider pinning, true A4 agent navigation, literal code scoring, complete secondary inference/cost, validity propagation, integrated real population, Corpus-S gold, abstention, and the complete manifest.

**Verdict — FAIL.** E2 is not faithful enough for its results to be trusted. The real profile cannot construct a pinned evidentiary A3 or the registered probe/audit population, Corpus S is missing required families, the code subtype changes the literal primary formula, and validity/budget failures can be absent from the named contrast output. The smoke run is operational but not a trustworthy module smoke: it omits A4 and produces no primary contrast while presenting a green checks table. Before results can be used, the provider/profile and both-corpus population paths, literal scoring, A4 interaction, budget/validity propagation, audit artifacts, output statistics/costs, and mutation-sensitive tests above must be corrected.
