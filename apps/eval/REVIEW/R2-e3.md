# R2 review — E3 store organisation

1. **Blocker — `apps/eval/src/harnext_eval/e3/run.py:958-959, 1196-1233`**
   - **Spec:** The erosion score is the OLS slope of accuracy for one fixed, family-balanced 60-probe panel at replay weeks 1, 2, 4, 8, and end (§7 lines 336, 353, 357). Each checkpoint therefore needs a complete checkpoint-correct panel and the same estimand.
   - **Code:** `_rederive_probe` drops every probe whose original E2 `T` is after the checkpoint. The runner then scores the changing eligible subset and explicitly permits missing families with `require_all=False`. On the required R-H1 schedule, May–June E2 probes are ineligible at the January/February checkpoints. The fresh smoke run showed exactly this failure: week 1/2/4 had `eligible_at_checkpoint=0`, while slopes were still emitted from only week 8/end. `compute_erosion_slope` also returns `0.0` for fewer than two finite points (`run.py:109-113`), falsely turning missing longitudinal evidence into “no erosion.” The R1 “fixes applied” claim for findings 8–10 is therefore not genuine.
   - **Minimal fix:** Freeze 60 probe templates that can be independently instantiated and re-golded at every checkpoint, require all 60 and all five families at every point, and mark the slope invalid (not zero) if any checkpoint is incomplete or fewer than two valid points remain.

2. **Blocker — `apps/eval/src/harnext_eval/e3/run.py:813-850, 1258-1263, 1292-1344`**
   - **Spec:** Primary contrasts are valid only after the E2/E3 validity package passes: same input, answerability/prior floors, grader reproducibility, pilot evidence, 100% leakage on kept probes, equal-budget checks, S1 review, S4 fairness, seed reliability, and builder-failure remediation (§7 lines 359–366; §9 lines 518–527; G1–G3).
   - **Code:** `_primary_contrasts` defines `valid` using only same-input, finite delta, seed-spread availability, and family presence. All other checks are computed later and never feed `valid`. Thus a real three-seed run can publish `valid=true` with failed leakage/budget/floors, S4 recall below 0.7, missing S1 review or pilot/grader evidence, or failed builders. There are no E3 checks at all for exact-grader rerun identity, claims disagreement, pilot kappa, gold agreement, or S1 human review. The R1 fixes-applied claim for findings 19/22 is not genuine.
   - **Minimal fix:** Resolve every required gate before contrasts, persist externally supplied audit/review evidence, pass one consolidated validity object into `_primary_contrasts`, and fail closed with named invalid reasons whenever any applicable gate is absent or false.

3. **Blocker — `apps/eval/src/harnext_eval/config.py:67-69`, `apps/eval/src/harnext_eval/providers/factory.py:93-103`, `apps/eval/configs/s3-curated.yaml:11-13`**
   - **Spec:** S4/S5 use a stated, pinned embedding model; S4 recall@10 is a fairness gate, and the real profile must compare that retriever to the curated store (§5 line 178; §7 lines 327–330, 364; G2).
   - **Code:** `EmbeddingsConfig.provider` literally permits only `fake`, the provider factory rejects every non-fake provider, and the purported curated/evidentiary config selects fake hash embeddings. E3 can query the actual S4 snapshot now, but the real profile cannot be configured to use the specified pinned embedding model. The result table also omits embedding provider/model/revision and chunking, so the fairness result is not self-describing.
   - **Minimal fix:** Add a real pinned embedding provider/model/revision configuration, build and query S4/S5 with that exact provider, record chunking and model identity in `s4_recall.csv` and the manifest, and reject claim-bearing E3 runs that use `FakeEmbeddings`.

4. **Blocker — `apps/eval/src/harnext_eval/cli.py:127-156, 475-478, 504-517`**
   - **Spec:** E3 uses the frozen E2 populations: R-H1 has Jan–April warm-up and May–June probes; each corpus has exactly 300 probes, 60 per macro family, across at least 150 entities (§3 line 61; §7 line 317; D9).
   - **Code:** The run CLI always generates probes across the entire replay window, defaults to 10 per family, never invokes `generate_probe_set(..., evidentiary=True)`, and exposes no real-profile cutoff/population/audit configuration. Passing a real replay and `s3-curated.yaml` therefore does not produce or enforce the required E3 population. This is not merely an unexecuted large profile; the required profile is not parameterised through the run path.
   - **Minimal fix:** Accept a frozen pre-generated probe file or explicit preregistered warm-up/probe cutoffs plus evidentiary mode, require the exact 300/60/150 matrix for claim-bearing E3, and reject R-H1 runs whose probe times fall outside May–June.

5. **Blocker — `apps/eval/src/harnext_eval/cli.py:524-536`, `apps/eval/src/harnext_eval/manifest.py:52-76`**
   - **Spec:** PREREG must predate the run and hash the replay, probes, builder prompt, `CLAUDE.md`, schemas, thresholds, model/tokenizer/embedding choices, and frozen prices (§2 line 40; §7 line 335; §9 lines 520, 526–527; D11).
   - **Code:** There is no `apps/eval/PREREG.md`. Although `build_manifest` accepts `prereg_ref`, the CLI never supplies one, records the reader only as a provider name, and records no prompt, `CLAUDE.md`, schema, tokenizer, embedding-model, chunking, or threshold hashes. The smoke manifest consequently has `prereg_ref: null`; the same run path would allow an evidentiary result.
   - **Minimal fix:** Require an existing committed PREREG reference for non-smoke E3, hash/version every named input, include the resolved reader and embedding model/revision and prices, and prevent primary inference if any preregistered input is absent or changed.

6. **Major — `apps/eval/src/harnext_eval/e3/run.py:286-342`, `apps/eval/src/harnext_eval/stores/layouts.py:110-146`**
   - **Spec:** Same input must be proved by both an identical replay hash and a byte-identical complete delivered-event-ID ledger across stores (§7 line 361).
   - **Code:** E3 compares a caller-supplied `StoreCondition.replay_hash`, not a replay hash persisted by and read back from each store. Store metadata contains an ID hash and a separately accumulated event-content hash, but no manifest replay hash, and E3 ignores `events_sha256`. Two stores built from different payloads under the same event IDs can therefore pass. The covering test at `test_e2e3.py:706-738` changes an ID, not an event payload with the same ID, so it does not test this gap. The R1 finding-21 fix is only partial.
   - **Minimal fix:** Persist the manifest replay SHA in every store before folding, validate it from every immutable store, and add a same-ID/different-payload test that must invalidate the proof and contrasts.

7. **Major — `apps/eval/src/harnext_eval/health/store_health.py:104-159, 252-300, 333-376`**
   - **Spec:** Literally, `index_acc=resolving entries/entries`, `dangling=unresolved refs/refs`, and `leak_rate=entities with a superseded value in OVERVIEW/entities with >=1 supersession`, with supersession truth derived from replay/world-state mutations (§7 line 357).
   - **Code:** Index parsing accepts only Markdown table rows, treats a broken declared target as resolved if the row names an existing entity, and assigns a zero-entry index perfect `1.0`. Reference scanning omits ordinary mandated keys/IDs in prose and deduplicates wiki/named references per file, changing the denominator. Supersession numerator and denominator both come from the store's own `_meta/superseded.md`, so an omitted supersession disappears from the denominator and can produce a perfect leak rate. These R1 findings 23–25 remain unfixed.
   - **Minimal fix:** Parse every supported index form and require its declared target to resolve; use N/A for zero denominators; count every registered reference occurrence against file/entity/event registries; and pass checkpoint-specific independent supersession truth into health computation.

9. **Major — `apps/eval/src/harnext_eval/e3/run.py:356-389, 549-564, 1304-1309`**
   - **Spec:** The per-item leakage gate verifies the selected snapshot/material as well as its delivery boundary, and reports every exclusion (§4.2; §9 line 520).
   - **Code:** E3 gates only the snapshot ledger, source IDs, and question tokens before material is retrieved. It never passes the actual selected material through the shared leakage gate or checks that material provenance/content is confined to events at or before `T`, yet `checks.leakage_gate_100_pct` is reported as passed.    - **Minimal fix:** Build material first, invoke the shared `leakage_gate(..., material=material)` against the exact snapshot boundary, retain its detailed reasons, and make any failure invalidate the affected cell and primary contrast.

11. **Major — `apps/eval/src/harnext_eval/e3/run.py:199-250`, `apps/eval/src/harnext_eval/stores/layouts.py:180-201`**
    - **Spec:** `build_cost=sum(tokens_in+tokens_out)` plus dollars per 1,000 distinct events, wall time, and files touched, including embedding cost; builder failures are counted and stores over 5% are fixed and rebuilt (§7 lines 346, 354, 357, 366).

12. **Major — `apps/eval/src/harnext_eval/e3/run.py:761-854`**

The single-/degenerate-cluster fallback returns a zero-width CI equal to the point estimate (`run.py:693-696, 724-725`) rather than invalidating inference.
    - **Minimal fix:** Emit paired results and McNemar for every S3 seed plus an explicit pass^3 aggregate, Holm-adjust registered secondaries, load the practical threshold from PREREG, and mark underpowered/degenerate bootstrap cells invalid instead of fabricating zero-width CIs.

16. **Major — `apps/eval/tests/test_e2e3/test_e2e3.py:504-529, 641-703, 741-768, 803-825`**
    - **Spec:** Covering tests must fail if the claimed E3 macro/CI, longitudinal panel, multi-seed reliability, validity gates, costs, outputs, or real-profile matrix regress.
    - **Code:** The “literal macro” test calls E2 `_paired_contrast`, not E3 `_primary_contrasts`, and never asserts E3's expected delta/CI. The E3 integration uses deterministic identical fake S3 copies and checks only `valid`, counts, positive S4 accuracy, recall, and artifact names; it does not assert gate propagation, resource/cost values, pass^3, practical thresholds, or a nonzero seed spread. The erosion test explicitly asserts that pre-`T` checkpoints drop a probe, encoding finding 1 rather than detecting it. The CLI test covers only one-seed smoke and an omitted Opus registry row, not three real Sonnet builds plus Opus. Thus several R1 “covering test” citations would not fail if their claimed fixes were removed or broken.
    - **Minimal fix:** Add exact known E3 macro/BCa fixtures with unequal family sizes and multiple entities, checkpoint-complete 60-probe erosion fixtures, failing-gate propagation tests, nonzero multi-seed/pass^3 cases, exact cost/token assertions, all-identical-arm rejection, and a real-profile condition-matrix test.

R1 verification summary: genuine and materially covered fixes are condition-specific S0/S1/S3/S4/S5 retrieval (including immutable S4 vector lookup), root-level E3 CSV/PNG writing and report discovery, the 10,000-resample constant, mandatory-arm rejection, literal per-probe S4 set recall, stable condition labels, and cumulative snapshot watermark validation. The aggregate smoke focus item also passes: `make eval-smoke` completed at `apps/eval/out/20260830T212151Z-baseline-minimal`, E3 is rendered in `report.html`, and S3–S4 uses the vector arm. The fixes claimed for longitudinal erosion, full validity propagation, complete resource/cost accounting, same-payload proof, failure remediation, scientific fake-path guards, and their covering tests are partial or absent as detailed above. The targeted E3/store-health/layout suite passes (35 tests), but those passing tests do not cover the listed failures.

**Verdict — FAIL.** E3 now executes a useful, non-vacuous smoke plumbing run and renders its artifacts, but the experiment is not faithful enough for trusted smoke results because its erosion curve changes or empties the fixed panel while still reporting slopes. Claim-bearing results are additionally unsafe because required validity gates do not control primary validity, same-input proof does not bind each store to replay payloads, exact health denominators and S1 fairness remain wrong, and costs/statistics are incomplete. The real profile is not correctly parameterised: it cannot select a real pinned embedding provider, enforce the required R-H1/Corpus-S probe populations, or require the preregistration/audit package. Those blockers must be fixed before E3 results can be trusted.
