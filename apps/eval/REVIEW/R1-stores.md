# R1 — E3 store variants and store health review

1. **blocker — `apps/eval/src/harnext_eval/stores/base.py:78-95`, `apps/eval/src/harnext_eval/replay/driver.py:191-193`.** **Spec:** `snapshot(T)` must be the last cumulative commit whose delivered events are all at or before `T`, and the §4.2 firewall must exclude every post-`T` event. **Code:** each fold is labelled with only that fold's maximum event time, while final per-entity windows are committed in first-event order. Those labels can decrease: a window ending at `t=10` can be committed before one ending at `t=5`; `snapshot(t=7)` then selects the later cumulative commit labelled `t=5`, even though it already contains the `t=10` update. This was reproducible with the default 30-second gap using two interleaved entities. **Minimal fix:** make snapshot time a monotone global delivered-event high-water mark (and record the corresponding last delivered ID), or commit folds in an order that guarantees every commit contains only events at or before its label; add a regression test with overlapping entity windows.

2. **blocker — `apps/eval/src/harnext_eval/e2/arms.py:187-261`.** **Spec:** S4 is vector retrieval over raw events and S5 is retrieval over S3 files. **Code:** E3 evaluates every layout through generic A4 filesystem navigation. That function never opens `VectorIndex`; S4 has no `INDEX.md`/`OVERVIEW.md`, so it returns empty material, while S5 is read exactly like S3 and its embeddings have no effect. The S4 and S5 conditions therefore do not test the stated interventions. **Minimal fix:** dispatch by store layout: query the immutable S4/S5 index at `snapshot(T)`, materialise the retrieved raw-event/file documents, and apply the same token budget before calling the fixed reader.

3. **blocker — `apps/eval/src/harnext_eval/stores/build_s0.py:41-67`, `apps/eval/src/harnext_eval/e2/arms.py:221-243`.** **Spec:** S0 is only `events/YYYY/MM/DD/<id>.md`, one file per event, isolating “the filesystem alone.” **Code:** S0 adds and rebuilds a global `INDEX.md`, introducing organization absent from the arm definition. Worse, A4 opens the index but follows a link only when the probe entity string occurs in the target path; S0 targets are event IDs, so the raw event files normally are never read. S0 is consequently neither the specified dump nor a functioning raw-dump baseline. **Minimal fix:** remove the index from S0 and implement deterministic entity/question-relevant navigation over its raw event files (or define an equal-budget raw-event selection rule) without adding a global organization layer.

4. **blocker — `apps/builder/src/harnext_builder/harness/fake.py:25-49`, `apps/eval/src/harnext_eval/stores/build_s2.py:51-61`, `apps/eval/src/harnext_eval/stores/build_s3.py:111-118`.** **Spec:** S2 and S3 must actually curate every supplied event into current state, facts, timelines, and (for S3) global organization. **Code:** the fake builder only appends a comment to `INDEX.md` and writes `_meta/last_build.md`; it creates no entity state. S2 then deletes its temporary index, leaving no readable entity content, and S3 keeps only the empty seed index. S5 inherits the same empty “curation.” This fake-builder path makes the curated ablation vacuous. **Minimal fix:** either provide a semantic deterministic fake that implements each layout contract, or reject fake-built S2/S3/S5 as non-reportable and reserve it strictly for pipeline plumbing tests.

5. **blocker — `apps/eval/src/harnext_eval/providers/llm.py:115-129`, `apps/eval/src/harnext_eval/stores/templated.py:179-191`, `apps/eval/configs/s3-curated.yaml:10-13`.** **Spec:** all stores use the same fixed read model and should yield condition-sensitive scores. **Code:** the configured E3 reader is fake. `FakeLLM` requires the entity identifier and field name on the same line, but real S1 overviews put the entity in the heading and fields on separate bullet lines; it also cannot answer the temporal, link, or code-location families. With the actual fake-built stores, all S0-S5 arms return `UNKNOWN` for ordinary status probes, producing identical scores. The ToyStore test hides this by using the non-production line `HNX-1 status: Done`. **Minimal fix:** use the preregistered real reader for reportable E3 runs; if offline scoring is required, make the fake reader support the actual layouts and all probe families, and add an assertion that the fake path produces non-identical planted-arm scores.

6. **blocker — `apps/eval/src/harnext_eval/e3/run.py:451-463`, `apps/eval/src/harnext_eval/agents/reader.py:66-67`, `apps/eval/src/harnext_eval/providers/factory.py:28-30`, `apps/eval/src/harnext_eval/providers/factory.py:45-57`.** **Spec:** the headline S3 run must use the pinned real reader under the run's declared provider/offline policy. **Code:** the CLI passes only `EngineConfig` into E3, losing the top-level `offline: false`; the reader factory therefore defaults back to offline mode and would reject an Anthropic reader. The supplied profile avoids the crash only by configuring the non-spec fake reader. Thus switching the profile to the required real reader still cannot execute through E3. **Minimal fix:** propagate the full experiment/provider context or an already-resolved reader into E3, and add an integration test that the online S3 profile builds and reads with the pinned real models.

7. **blocker — `apps/eval/src/harnext_eval/config.py:67-69`, `apps/eval/src/harnext_eval/providers/factory.py:85-95`, `apps/eval/src/harnext_eval/stores/vector_index.py:29-32`.** **Spec:** S4/S5 use a pinned embedding model, with model and chunking stated. **Code:** configuration now permits only `provider: fake`; the factory can only construct `FakeEmbeddings`, and `VectorIndex` silently falls back to that fake. No production embedding adapter/model ID exists, so the specified S4/S5 conditions cannot be run. **Minimal fix:** implement and require the preregistered embedding provider/model for reportable S4/S5 builds and queries; persist provider, model revision, dimensions, and chunking in store/run manifests, with no silent fallback.

8. **blocker — `apps/eval/src/harnext_eval/cli.py:182-188`, `apps/eval/src/harnext_eval/e3/run.py:214-217`.** **Spec:** E3's required baseline set includes S0, S1, S3, and S4; the primary contrasts are S3-S1 and S3-S4. **Code:** selecting E3 automatically requests only S0/S1/S4; S3 is built only if the unrelated global `store.layout` happens to be S3. Missing S3 or either comparator is silently skipped, allowing an E3 run with no primary result. **Minimal fix:** make E3 request and validate all mandatory arms up front, fail closed if any primary arm is absent, and make S2/S5 the only budget-conditional arms.

9. **blocker — `apps/eval/src/harnext_eval/cli.py:383-408`, `apps/eval/src/harnext_eval/e3/run.py:206-213`.** **Spec:** S3 must be analysed across three Sonnet seeds plus a separate Opus seed-1 build, with between-seed accuracy and health spread. **Code:** the CLI builds and evaluates one seed at a time in separate directories and passes only that seed's stores to E3. `_primary_contrasts` therefore sees one S3 value and defines `seed_spread = 0`; no Opus build is scheduled or distinguished. The `seed` argument only changes paths/org IDs and is not attached to `StoreHandle` or a provider request. **Minimal fix:** build all required S3 replicates, retain seed and model-tier metadata, aggregate the three Sonnet stores in one E3 analysis, report the Opus tier separately, and refuse a seed-reliability verdict with fewer than three Sonnet builds.

10. **blocker — `apps/eval/src/harnext_eval/e3/run.py:326-358`.** **Spec:** the erosion curve uses a fixed 60-probe subset with gold correct for each checkpoint and the leakage firewall at each `T`. **Code:** the runner takes arbitrary later E2 probes, rewrites only their `T` to weeks 1/2/4/8/end, and retains their original questions, gold, superseded values, and source IDs. Early checkpoints are thus graded against future-derived gold; token-only-post-`T` questions may be excluded, while the rest can remain silently wrong. **Minimal fix:** freeze a preregistered 60-probe longitudinal panel whose questions and independently derived gold are valid at every checkpoint, or regenerate/reconcile gold and source IDs for each checkpoint and report exclusions.

11. **major — `apps/eval/src/harnext_eval/e2/run.py:66-74`, `apps/eval/src/harnext_eval/replay/gate.py:43-52`.** **Spec:** the gate must inspect the events actually delivered before the selected SHA. **Code:** E2 passes a delivery log already filtered to `event.time <= probe.T`, making the delivered-time assertion tautological; it never maps the store's delivered-ID ledger to the SHA. It also fabricates `gold_action_time = T + 1 microsecond`. This cannot detect the cumulative-commit leak in finding 1. **Minimal fix:** pass the unfiltered, SHA-associated delivery ledger, verify every delivered ID/time in that commit, and run only applicable gold-action checks with real gold metadata.

12. **major — `apps/eval/src/harnext_eval/e3/run.py:164-170`, `apps/eval/src/harnext_eval/e3/run.py:402-405`.** **Spec:** same input must be proved by both identical replay hash and identical ordered delivered-event-ID list (ledger diff). **Code:** the “ledger hash” hashes only `last_event_id` from each fold snapshot. Different events within folds, or even different replays with the same fold-ending IDs, pass; the replay hash is never compared. A false result is only emitted as a metric and does not invalidate the contrasts. **Minimal fix:** compare the manifest replay SHA-256 and the complete ordered `_meta/delivered_event_ids.jsonl` for every store, emit the diff, and abort/mark all contrasts invalid on mismatch.

13. **major — `apps/eval/src/harnext_eval/stores/templated.py:15`, `apps/eval/src/harnext_eval/stores/templated.py:91-132`.** **Spec:** S1 fairness requires every structured field from events to be present, followed by human review of 20 entity folders. **Code:** S1 hard-codes six fields and discards every other structured field; no 20-folder review artifact or gate is consumed by E3. **Minimal fix:** project all preregistered structured fields for each corpus (including source-specific fields), preserve unknown structured fields deterministically where appropriate, and require a recorded 20-folder review before enabling S1 contrasts.

14. **major — `apps/eval/src/harnext_eval/stores/build_s5.py:15-56`.** **Spec:** S5 is S3 plus embeddings over the store's files, with chunking stated. **Code:** each entire file is one document regardless of size, then extra synthetic per-event citation documents are added. Those pseudo-documents are not store files and can make exact event-ID retrieval trivial, changing more than “retrieval on top of curation”; no chunking/model metadata is written. **Minimal fix:** freeze and document a file-chunking policy, embed only those chunks, retain chunk-to-file/event provenance as metadata rather than extra searchable gold-like documents, and persist the policy hash.

15. **major — `apps/eval/src/harnext_eval/e3/run.py:173-186`.** **Spec:** S4 fairness reports recall@10 of gold `source_event_ids`. **Code:** the function rebuilds the generic A3 raw-event retriever instead of querying the built S4 snapshot, and scores a probe as 1 if *any* gold ID appears. That is hit@10, not `|retrieved gold IDs| / |gold source IDs|`. **Minimal fix:** query each actual S4 snapshot with its configured provider/chunking and average the per-probe fraction of gold source IDs retrieved in the top 10; report by family/corpus and enforce G2's 0.7 floor.

16. **major — `apps/eval/src/harnext_eval/e3/run.py:225-266`.** **Spec:** the exact effect is a paired difference in E2 `macro_acc` (equal family weighting), with entity-clustered BCa 95% CI using 10,000 resamples; McNemar applies to paired binary correctness. **Code:** the displayed delta uses macro accuracy, but the CI bootstraps the unweighted mean of per-probe grade values, so it estimates a different quantity when family counts differ. It uses 1,000 resamples. For multiple seeds it averages scores and calls only an all-seeds-perfect mean (`>=1`) “correct” for McNemar. **Minimal fix:** bootstrap the macro-over-families contrast itself with 10,000 entity-clustered resamples, and run McNemar on a clearly defined paired binary arm/seed comparison rather than averaged fractional seed scores.

17. **major — `apps/eval/src/harnext_eval/e3/run.py:212-266`, `apps/eval/src/harnext_eval/e3/run.py:377-384`.** **Spec:** primary deltas are valid only against measured between-seed spread; health-metric spread is also reported, and “significantly better” additionally needs a CI excluding zero. **Code:** one seed is treated as zero spread, `reliable_difference` checks only `abs(delta) > spread` (even for a negative delta or a CI crossing zero), and no between-seed SD is computed for any health metric. **Minimal fix:** require the three-seed set, compute accuracy and each health metric's between-seed SD, separate “spread-qualified” from direction/significance, and apply the preregistered no-reliable-difference wording and stop rule.

18. **major — `apps/eval/src/harnext_eval/providers/tokenizer.py:7-12`, `apps/eval/src/harnext_eval/agents/reader.py:33-49`.** **Spec:** 2k/8k/32k budgets are enforced and counted with the provider tokenizer. **Code:** budget enforcement uses a regex word/punctuation approximation explicitly described as approximate, not the selected model's tokenizer. Consequently arms can exceed or underfill the true provider budget and are not equal at the promised token counts. **Minimal fix:** bind token counting/truncation to the pinned reader model's tokenizer and record both selected-material and actual provider input token counts.

19. **major — `apps/eval/src/harnext_eval/e3/run.py:293-306`, `apps/eval/src/harnext_eval/e3/run.py:315-320`.** **Spec:** E2 validity floors and equal-budget checks apply to E3, exclusions are counted, and every quality number is shown beside tokens, dollars, and latency. **Code:** E3 runs only A4, discards the returned E2 validity metrics, and never runs/reports retrieve-everything or model-prior floors. It records mean `tokens_read` but not latency, tool calls, dollars, or the ±10% filled-budget result in the curve; empty S4 material can therefore look like a valid equal-budget arm. **Minimal fix:** run the required floors through the same path, propagate leakage/budget/floor checks and exclusion counts into E3 validity, fail closed when gates fail, and put token/$/latency columns next to each accuracy row.

20. **major — `apps/eval/src/harnext_eval/health/store_health.py:87-132`.** **Spec:** `index_acc = resolving INDEX entries / entries`, where entries resolve to existing files. **Code:** only Markdown table rows count; bullet-list indexes such as S0's yield zero entries and are reported as perfect (`1.0`). A row also counts as resolved merely because its entity key names an existing entity directory, even if its linked file target is missing. **Minimal fix:** parse the canonical INDEX entry forms, require each entry's declared file target to exist, and report zero-entry indexes as N/A (not 1.0), with explicit numerator/denominator tests.

21. **major — `apps/eval/src/harnext_eval/health/store_health.py:252-300`, `apps/eval/src/harnext_eval/health/store_health.py:341-376`.** **Spec:** `leak_rate` uses the external gold denominator “entities with at least one supersession” and checks whether a superseded value remains in `OVERVIEW.md`. **Code:** both denominator and values come from the store's own `_meta/superseded.md`. A builder that fails to record supersession gets denominator zero and a perfect zero leak rate, exactly masking the defect the metric should catch. **Minimal fix:** pass the replay/probe gold supersession catalogue into health analysis, derive denominator and retired values independently of the evaluated store, and treat missing expected supersession metadata as a defect.

22. **major — `apps/eval/src/harnext_eval/health/store_health.py:135-159`.** **Spec:** dangling cross-references include references to non-existent files *and IDs*. **Code:** detection covers Markdown links plus two narrow issue-key syntaxes; it does not validate canonical provenance/event citations such as `source#event_id`, general linked IDs, or topic/entity references against the delivered-ID/entity catalogues. Many dangling IDs therefore do not enter either numerator or denominator. **Minimal fix:** define and parse every allowed cross-reference/provenance form from the schema and validate IDs against the snapshot's delivered-event/entity indexes.

23. **major — `apps/eval/src/harnext_eval/health/store_health.py:319-356`.** **Spec:** `over_cap = files > 200 lines / files` for the context store. **Code:** the denominator includes every binary/vector/metadata artifact, while only UTF-8-readable files can enter the numerator. S4/S5's `.npy` and JSON index internals therefore dilute the rate even though they are not line-capped context files. **Minimal fix:** preregister the eligible context-file universe (normally durable text/Markdown files), use that same set for numerator and denominator, and report binary index size separately.

24. **major — `apps/eval/src/harnext_eval/stores/layouts.py:150-201`, `apps/eval/src/harnext_eval/e3/run.py:130-161`.** **Spec:** `build_cost = sum(tokens_in + tokens_out)` plus dollars per 1,000 events, wall time, and files touched per run, using usage records and frozen prices. **Code:** output has total provider-reported `cost_usd` but no dollars-per-1,000-events; no wall time is written by `append_usage`, so aggregation defaults to zero; files touched are collapsed to a total rather than per run. Provider `total_cost_usd` is accepted instead of recomputing from frozen prices. **Minimal fix:** log per-fold wall time and file count, calculate token and dollar rates per 1,000 events from a frozen price table, retain per-run rows, and put the frozen price/version in the manifest.

25. **major — `apps/eval/src/harnext_eval/stores/build_s3.py:81-107`, `apps/eval/src/harnext_eval/cli.py:192-208`, `apps/eval/src/harnext_eval/e3/run.py:138-161`.** **Spec:** DLQ/rolled-back folds are counted; over 5% failed folds triggers a rebuild after the cause is fixed and a logged amendment. **Code:** a builder failure is logged and then raises immediately, aborting store construction and E3 before its failure-rate table can be produced. The CLI has no catch/rebuild/amendment workflow, and the later boolean check is not an enforcement mechanism. **Minimal fix:** persist fold/DLQ outcomes independently, finish a validity report, enforce the 5% gate, and support the specified cause-fixed rebuild with an append-only amendment record.

26. **major — `apps/builder/src/harnext_builder/harness/claude_code.py:75-92`, `apps/eval/src/harnext_eval/cli.py:370-381`.** **Spec:** builder/read temperature is zero; builder prompt and `CLAUDE.md` hashes, model IDs, prices, and preregistration reference are frozen and logged, and each store script writes a manifest beside its output. **Code:** the Claude builder request sets neither temperature nor a seed; the run manifest is not passed prices or `prereg_ref`, contains no prompt/`CLAUDE.md` hashes, and the standalone `stores` command writes no manifest at all. `apps/eval/PREREG.md` is absent. Paired builds are therefore not reproducibly pinned or auditable. **Minimal fix:** enforce temperature zero (and any available deterministic seed), hash the exact system prompt, instruction template, seed `CLAUDE.md`, embedding/chunk config, and model revisions, write a manifest beside every store, populate frozen prices/prereg ref, and create the append-only preregistration before full runs.

27. **major — `apps/eval/src/harnext_eval/e3/run.py:386-441`, `apps/eval/src/harnext_eval/e3/run.py:466-488`, `apps/eval/src/harnext_eval/cli.py:404-408`.** **Spec:** named outputs are `eval/out/e3/curve.png` (both corpora), `health.csv`, `erosion.png`, `cost.csv`, and `contrasts.csv`. **Code:** `evaluate_e3` writes `curve.csv` and `erosion.csv` but no PNGs; the CLI later writes PNGs under each seed's `charts/` subdirectory, one corpus/seed at a time. There is no combined both-corpus curve or cross-seed output. **Minimal fix:** aggregate both corpora and required seeds into the final E3 result and write/register the exact named artifacts at the specified E3 output paths.

28. **major — `apps/eval/src/harnext_eval/probes/gen_temporal.py:41-44`, `apps/eval/src/harnext_eval/probes/gen_update.py:38-41`.** **Spec:** disagreements between the two independent temporal/update gold derivations are resolved before keeping probes and the evidence is reportable. **Code:** disagreements are silently skipped, with no disagreement count, resolution record, corrected-probe list, or human adjudication artifact. E3 cannot distinguish genuine agreement from discarded difficult cases. **Minimal fix:** emit the complete reconciliation table, adjudicate disagreements according to the preregistered procedure, freeze the resolved probes, and report counts/exclusions.

29. **major — `apps/eval/tests/test_stores/test_layouts.py:62-87`, `apps/eval/tests/test_e2e3/test_e2e3.py:209-237`.** **Spec/test claim:** stores must receive the same replay and E3 must exercise the actual variants and both primary contrasts. **Test:** the layout test compares each store's hash only to its own ledger and never compares ordered ledgers/replay hashes across stores. The E3 test uses two hand-written ToyStores, omits S0/S4/S5 and S3 replicates, and checks only S3-S1. It therefore passes without testing the required conditions, retrieval paths, seed rule, failure gate, or S3-S4 contrast. **Minimal fix:** add an integration test building all mandatory layouts from one frozen replay, compare complete ledgers/hashes, run the real layout-aware reader, include three S3 seeds, and assert both exact primary contrasts and validity gates.

30. **major — `apps/eval/tests/test_e2e3/test_e2e3.py:78-147`, `apps/eval/tests/test_e2e3/test_e2e3.py:225-230`.** **Spec/test claim:** E3 scoring, same-input validation, and cost accounting work end to end. **Test:** ToyStore hard-codes production-incompatible entity/field lines, gives S1 and S3 identical file topology, fabricates identical snapshot-ending IDs, and writes the same fake usage row for code-only S1 and curated S3. The test then expects same-input PASS and equal build tokens despite different store contents/statuses. This actively masks the broken ledger check, fake-reader incompatibility, and S1 zero-builder-cost requirement. **Minimal fix:** replace the doubles with actual S1/S3 stores and provider transcripts; plant a differing middle event to prove the ledger gate fails, and assert S1 has zero LLM builder tokens.

31. **major — `apps/eval/tests/test_stores/test_layouts.py:147-175`, `apps/eval/src/harnext_eval/stores/vector_index.py:131-139`.** **Spec/test claim:** S4/S5 retrieval quality is validated. **Test:** both tests query the exact event ID, while production search adds a +2 exact-ID and +1 substring bonus; success is guaranteed independently of embedding quality and does not test question-to-gold recall@10. **Minimal fix:** query natural probe questions against historical snapshots, remove gold-ID query leakage from the test, and assert the literal recall@10 formula over multi-ID gold.

32. **minor — `apps/eval/tests/test_grade/test_store_health.py:51-76`.** **Spec/test claim:** the MinHash near-duplicate detector is unit-tested on a planted near-duplicate defect at Jaccard >= 0.8. **Test:** it appends a byte-for-byte duplicate fact, so it tests exact duplication only; it never exercises near-duplicate wording, the 0.8 boundary, or provenance/date variation. It also supplies the supersession catalogue inside the store, so it cannot expose the self-reported-denominator bug. **Minimal fix:** add separate fixtures for just-above/just-below-threshold paraphrastic fact lines and inject supersession gold independently from store files.

33. **minor — `apps/eval/tests/test_stores/test_layouts.py:90-100`, `apps/eval/tests/test_stores/test_layouts.py:135-145`.** **Spec/test claim:** S0 and S2 implement their stated layouts. **Test:** the S0 test explicitly requires the forbidden global index, while the S2 test checks only that index/topics are absent and that the fake marker exists; it never asserts that an event produced an entity overview, facts, and timeline. **Minimal fix:** align S0 assertions with the event-only layout and require S2 to preserve every event in curated entity files with no global organization.

**Verdict:** The experiment is not faithful to the specification and its results are not trustworthy. The current pipeline can select snapshots containing post-`T` data, does not actually read S4/S5 through vector retrieval, makes the fake-provider path all-`UNKNOWN`, cannot execute E3 with the required pinned real reader, analyses seeds separately with zero spread, mutates checkpoint time without recomputing gold, and misimplements or fails to enforce several exact validity/health/cost formulas. Before any E3 result can be trusted, the snapshot firewall and ledger proof must be fixed first; then the six arms and pinned providers must be made genuinely distinct and runnable, all three S3 seeds plus the Opus tier must be aggregated, E2 budgets/floors/gold reconciliation must be enforced, health metrics must use the exact external denominators, and the preregistered manifests/statistics/named outputs must be produced and covered by real end-to-end tests.
