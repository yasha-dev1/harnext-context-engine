# R2 — probes, gold, replay, snapshots, and leakage gate

1. **Blocker — `apps/eval/src/harnext_eval/cli.py:136-169`, `apps/eval/src/harnext_eval/cli.py:466-517`.** **Spec:** E2's real profile is 300 probes (60 in each of five macro families, at least 150 entities), includes the multi-source(code) variation, uses raw-Jira/SQL agreement and audited joins, applies the named A0 and leakage gates, and freezes the probe hash before a result run (§7 lines 267-309; §4 lines 121-157). **Code:** the normal `harnext-eval run` path always constructs `GoldAuditTrail(source="normalised-smoke-adapter")`, passes none of `evidentiary`, `raw_jira`, join audit, A0 audit, entity minimum, or code-subtype count, and defaults to 10 probes per family even when `--smoke` is absent. It also omits the join report. Thus the standalone generator has evidentiary switches, but the configured experiment path cannot produce or validate the preregistered real population. **Minimal fix:** put all evidentiary inputs/constraints in the run configuration/CLI, require them whenever `--smoke` is false, invoke `generate_probe_set(..., evidentiary=True, per_family=60, minimum_entities=150, multisource_code_count>0, raw_jira=..., join_audit=..., a0_answers=...)`, write both audit reports, and stop before experiments on any failure.

2. **Blocker — `apps/eval/src/harnext_eval/corpus/jira.py:54-77`, `apps/eval/src/harnext_eval/probes/gold.py:178-230`, `apps/eval/src/harnext_eval/probes/gold.py:309-321`, `apps/eval/tests/test_probes/test_gold.py:20-73`.** **Spec:** Jira state gold is the true initial/current value obtained by replaying the changelog to T, and the Python and raw-SQL derivations must be independent (§4 line 126; §7 lines 284-305). **Code:** both paths treat the raw export's current `fields.status`, assignee, priority, components, and fixVersions as if they were true at `fields.created`. A real raw issue whose current status is Closed and whose changelog says Open→Closed therefore yields Closed before the transition in both oracles; their apparent 100% agreement is correlated wrong gold. The covering fixture unrealistically leaves raw `fields.status` as Open even though its changelog ends Closed, so it cannot fail on this defect. **Minimal fix:** reconstruct creation-time values from the earliest changelog `fromString`/`from` (and replay forward), treat raw current fields only as an export-time consistency check, and add a realistic current-state raw fixture that expects Open before an Open→Closed transition.

3. **Blocker — `apps/eval/src/harnext_eval/probes/gen_code_location.py:85-110`, `apps/eval/src/harnext_eval/corpus/gharchive.py:152-169`, `apps/eval/src/harnext_eval/corpus/gharchive.py:411-425`, `apps/eval/tests/test_probes/test_generators.py:146-219`.** **Spec:** E2 multi-source(code) and E4 Place gold come from `git diff --name-only` for linked merged PRs (§4 line 130; §7 lines 288 and 383). **Code:** the generator only accepts merged events already containing a non-empty `changed_files` list. The GH Archive extractor merely copies non-standard `files`/`changed_files` arrays if present; real GH Archive PullRequestEvent payloads do not provide PR file names. Even the checked-in GH fixture's merged/closed events have empty lists. The probe test manually injects `changed_files`, so it proves T placement but not that Corpus R can produce any code probe. **Minimal fix:** enrich qualifying PRs during corpus construction from a frozen repository diff or GitHub-files export, record its hash/provenance, fail evidentiary generation if the requested code stratum cannot be filled, and test the real extractor-to-generator path.

4. **Blocker — `apps/eval/src/harnext_eval/config.py:62-69`, `apps/eval/src/harnext_eval/providers/factory.py:93-103`, `apps/eval/configs/s3-curated.yaml:12-13`, `apps/eval/tests/test_e2e3/test_e2e3.py:609-638`.** **Spec:** A3 uses a pinned embedding model and result-bearing E2 uses the fixed real reader (§7 lines 271-278; D4/D8). **Code:** the schema permits only `embeddings.provider: fake`, the factory rejects every non-fake embedding provider, and the supposedly real S3 profile explicitly selects fake embeddings. The package also has no real embedding adapter. E2 correctly labels such a run non-evidentiary, which means no configuration can currently produce a valid A4−A3 result. The cited Round 1 test injects `FakeEmbeddings` and merely asserts that the result is invalid; it does not cover a configured pinned provider. **Minimal fix:** implement and dependency-pin a real embedding adapter/model/revision, allow it in config, use it in the real profile, record its identity, reject fake A3 outside smoke, and add a factory/config test that exercises the real adapter without silently falling back.

5. **Blocker — `apps/eval/src/harnext_eval/e2/run.py:95-115`, `apps/eval/tests/test_e2e3/test_e2e3.py:532-557`, `apps/eval/tests/test_grade/test_exact_links.py:54-66`.** **Spec:** the Exact scores block says multi-source contributes set F1 (`link_F1`), while code localisation reports file precision/recall and module hit (§7 lines 288-291). **Code:** for the code subtype, any partial file set is forced to zero via `exact_files = precision == recall == 1`, and that zero/one value enters macro accuracy. The tests explicitly lock in this non-spec formula by requiring a 50%-recall prediction to score 0. **Minimal fix:** use file-set F1 as the code subtype's multi-source score (retaining file precision, recall, and module hit as named details/secondaries) and replace the test with hand-calculated partial-set F1 cases.

6. **Blocker — `apps/eval/src/harnext_eval/cli.py:580-585`, `apps/eval/src/harnext_eval/e2/run.py:496-500`, `apps/eval/src/harnext_eval/e2/run.py:640-648`, `apps/eval/tests/test_e2e3/test_e2e3.py:609-638`.** **Spec:** the E2 primary is A4 curated S3 minus A3 at 8k, with a populated paired contrast (§7 lines 277, 291, 298-311). **Code:** baseline smoke passes its configured S0 as E2's store; E2 renames requested A4 to `S0`, then still computes the primary by looking for literal arm `A4`, producing an empty `contrasts.csv`. No check marks the missing primary as FAIL. In the Round 2 smoke run `20260830T212334Z-baseline-minimal`, all visible E2 checks were PASS/N/A despite that empty primary. The end-to-end test uses an S3 fixture, so it misses the actual smoke wiring. **Minimal fix:** run E2 smoke with the already-built S3 store (or make the primary arm's semantic label stable), require a non-empty valid A4−A3 contrast as an explicit check, and add a test using the baseline CLI/store selection.

7. **Major — `apps/eval/src/harnext_eval/probes/gen.py:125-150`, `apps/eval/tests/test_probes/test_generators.py:284-294`.** **Spec:** A0 must be at most 0.3 on temporal, update, and multi-source probes; abstention is not part of this anti-memory floor (§7 line 305; G1 line 533). **Code:** `validate_abstention_prior` audits only abstention probes and rejects a reader for correctly answering UNKNOWN. It never evaluates the three named families. The covering test asserts this reversed condition, so it would continue to pass while the actual A0 validity claim is absent. **Minimal fix:** run the fixed reader with no material on temporal/update/multi-source, grade those answers normally, enforce/report their combined and per-family accuracy, and only report abstention A0 separately as a diagnostic.

8. **Major — `apps/eval/src/harnext_eval/probes/gen.py:35-58`, `apps/eval/src/harnext_eval/probes/gen.py:106-122`, `apps/eval/src/harnext_eval/probes/gen.py:170-180`, `apps/eval/tests/test_probes/test_generators.py:260-281`.** **Spec:** an evidentiary set has at least 150 entities and includes every declared variation (§7 lines 267-289). **Code:** `--minimum-entities` can lower the supposedly fixed 150 threshold to any integer, and `--multisource-code-count 0` is accepted even in evidentiary mode. The population validator checks only five family totals, not presence of both link and code subtypes. The test calls the validator only at its default threshold and never exercises either bypass. **Minimal fix:** make 150 a non-relaxable floor, require a preregistered positive code/link split in evidentiary mode, record subtype counts, and add rejection tests for relaxed entity thresholds and zero-subtype sets.

9. **Major — `apps/eval/src/harnext_eval/e2/arms.py:217-320`, `apps/eval/tests/test_e2e3/test_e2e3.py:414-424`.** **Spec:** A4's fixed read agent starts at INDEX/OVERVIEW and may decide which files to open with budgeted tools (§7 line 277; §5 line 170). **Code:** `_store_documents` is still a fixed queue traversal with hard-coded filename, link, sibling, and entity-string rules; no reader model chooses or invokes a tool. `tool_calls` is the number of deterministic list/read operations. The cited test checks only the predetermined files and count, so it would pass without an agentic read policy. **Minimal fix:** expose budgeted list/read/search tools to the same fixed reader, let its tool calls select files, log actual calls/results, and test different reader decisions plus budget exhaustion.

10. **Major — `apps/eval/src/harnext_eval/replay/snapshots.py:18-49`, `apps/eval/src/harnext_eval/replay/snapshots.py:104-156`, `apps/eval/tests/test_replay/test_snapshots.py:58-89`.** **Spec:** `snapshot(T)` is safe only if the selected commit's delivered content is proved to contain no post-T event (§3.3 lines 117-118; §4.2 line 151). **Code:** standalone `snapshot()`/`SnapshotIndex` validate CSV monotonicity, SHA existence, and git ancestry but never load the delivery ledger or verify that a descendant commit with an old forged watermark lacks future deliveries. The Round 1 tests cover naive/non-monotone times only; StoreHandle's separate ledger tests do not make this public standalone API safe. **Minimal fix:** require the ledger in `SnapshotIndex`, validate each CSV row against its exact cumulative delivery boundary, or remove the standalone path and delegate to ledger-backed `StoreHandle.snapshot`; add a descendant-with-future-delivery rejection test.

11. **Major — `apps/eval/src/harnext_eval/replay/gate.py:149-163`, `apps/eval/src/harnext_eval/replay/gate.py:361-373`, `apps/eval/src/harnext_eval/e4/run.py:161-173`, `apps/eval/src/harnext_eval/e4/run.py:603-607`.** **Spec:** the complete future gold action must be absent from every envelope (§4.2 line 153). **Code:** the gate lets a caller replace `item.gold` with an arbitrary partial `gold_action`, checks only string leaves of length at least three, and E4 uses that override after deliberately dropping modules, required IDs, event IDs, and decision metadata. Short identifiers, numeric/boolean action values, modules, and partial leaked reply text can therefore pass. The Round 1 test plants one complete long phrase and does not exercise omitted/short/partial values. **Minimal fix:** derive the canonical complete set of future gold atoms inside the gate from `Task.gold`, disallow lossy overrides, include all scalar/list fields that are not known-at-T inputs, and test module, short-ID, numeric, and partial-text leakage.

12. **Major — `apps/eval/src/harnext_eval/replay/gate.py:152-157`, `apps/eval/src/harnext_eval/replay/gate.py:338-358`, `apps/eval/tests/test_replay/test_gate.py:173-204`.** **Spec:** every gold action used for an E4 task must occur after T (§4.2 line 153; §7 lines 377-386, 408, 418). **Code:** the gate passes if it finds any action timestamp and all timestamps it happened to find are after T; it does not prove that every covered gold value/group has a timestamp, and an explicit single `gold_action_time` suppresses inspection of structured task times. The test contains only one fully timestamped action. **Minimal fix:** require a time for every covered action item/group, validate all of them against T, reject explicit overrides that do not map one-to-one to the gold actions, and add mixed timed/untimed and mixed pre/post-T cases.

13. **Major — `apps/eval/src/harnext_eval/replay/gate.py:34-42`, `apps/eval/src/harnext_eval/replay/gate.py:46-60`, `apps/eval/src/harnext_eval/e2/run.py:515-544`.** **Spec:** every gate invocation is logged to the canonical run-level `eval/out/gate.csv` with item ID, T, SHA, last event ID, result, and exclusions (§4.2 lines 154-157; §11 line 558). **Code:** the gate default is repository-relative `out/gate.csv`, and experiment callers override it with separate per-experiment files. The completed Round 2 smoke run had E2/E3/E4/E5 gate files but no run-root `gate.csv`, so there is no single audit/exclusion ledger. **Minimal fix:** create one run-level gate sink/path, append the canonical schema from every experiment (adding experiment/variant columns without dropping required fields), and test that one run has exactly the expected invocation count.

14. **Major — `apps/eval/src/harnext_eval/probes/common.py:17-33`, `apps/eval/src/harnext_eval/replay/driver.py:181-189`, `apps/eval/tests/test_replay/test_driver.py:75-90`.** **Spec:** gold and every arm replay the identical frozen stream in its frozen order (§2 line 37; §3.3 line 108). **Code:** `load_replay` accepts arbitrary line order among equal timestamps, Python gold uses that input order as its tie-breaker, but `run_pipeline` silently reorders ties by event ID. Equal-time transitions can therefore be folded in a different order from the gold derivation. The driver test checks only increasing timestamps and has no equal-time conflicting transitions. **Minimal fix:** either preserve JSONL line order everywhere or require/validate one canonical `(time, tie-breaker)` order at load time and use it in both gold and replay; add a same-time conflicting-transition test.

15. **Minor — `apps/eval/src/harnext_eval/probes/gen.py:153-163`, `apps/eval/src/harnext_eval/manifest.py:61-75`.** **Spec:** the frozen probe hash is committed in PREREG before the first full run and later runs verify it (§2 line 40; §7 line 295; D11). **Code:** probe generation still writes only a `.sha256` sidecar, no `PREREG.md` exists under `apps/eval`, and the run manifest leaves `prereg_ref` unset rather than checking an expected hash/ref. This is the Round 1 item explicitly left unfixed. **Minimal fix:** require a prereg reference and expected probe hash for non-smoke runs, verify both before execution, and support an explicit append-only acceptance step before the first evidentiary run.

## Round 1 fix verification

- **Finding 10:** genuine. `a1` has explicit N=20/N=100 labels and `<= T`; the cited boundary/label test would fail if those changes were removed.
- **Finding 11:** not genuine as a complete fix. Local silent fallback was removed and fake evidence is invalidated, but config/factory cannot construct any real embedding provider; the cited test uses only fakes (finding 4 above).
- **Finding 12:** partial. An injected tokenizer controls material truncation and the cited character-counter test would catch ignoring it, but the Anthropic counter models one concatenated user message rather than the actual system-plus-user request and no installed dependency/test exercises the real path.
- **Finding 13:** not genuine. The implementation now performs real filesystem reads and counts them, but selection remains hard-coded rather than agent-decided; the cited test asserts that traversal (finding 9).
- **Finding 9 deliberately unfixed:** verified still unfixed (finding 15).
- **Replay regression 45:** partial. The new tests genuinely cover store-ledger resolution, an unresolved legacy SHA, timestamp tampering, and one complete structured gold string; they do not cover complete action-time association or omitted/short/partial gold (findings 11-12).
- **Snapshot regression 46:** partial. StoreHandle's cumulative-high-water/tamper tests and standalone monotonic/timezone tests are real and would fail without those checks, but standalone SnapshotIndex still has no ledger-backed future-content proof (finding 10).
- **Findings 1/43:** the five macro-family schema/count fix is genuine and the 15-probe tests would fail if a sixth family returned; the integrated smoke/real path nevertheless emits no code subtype (findings 1 and 6).
- **Finding 2:** the direct population validator and its default-threshold test are genuine, but the threshold is relaxable and the normal run never enables the validator (findings 1 and 8).
- **Finding 3:** not genuine for Jira initial state. Catalogue branches exist, but the test fixture hides the raw-current-versus-initial error (finding 2).
- **Findings 4/5/44:** partial. Raw-JSON SQL, reporting, the 98% stop, and the planted disagreement test are real; both oracles still share the initial-state error, and the normal run cannot supply the raw export/audit (findings 1-2).
- **Finding 6:** the post-merge T/source-ID placement is genuine and its unit test would fail under the old future-gold behavior; the real Corpus R path cannot supply merged-PR file names (finding 3).
- **Finding 7:** the restricted regex surfaces, canonical IDs, TP/FP/FN report, and unit tests are genuine; the normal experiment path neither supplies the audit nor writes its report (finding 1).
- **Finding 8:** partial at best. Natural field/entity generation replaced explicit `MISSING-*` cues and its test would catch their return, but the claimed A0 gate audits the wrong family and its test codifies that error (finding 7).

Round 2 smoke was rerun successfully with `make eval-smoke` (run `20260830T212334Z-baseline-minimal`); the report explicitly labels the small-sample E1/E2 human checks N/A, while its only literal FAIL rows are E6 generator skew and repetition stability (outside this module). For this module, however, the apparent clean E2 table masks zero code-location probes and an empty primary contrast, so smoke success is not evidence that the probe experiment is sound.

**Verdict.** The experiment is not faithful enough for its results to be trusted: real-profile generation is not wired to the evidentiary constraints, both gold implementations can agree on historically wrong Jira state, real GH Archive input cannot produce code-location gold, no pinned real embedding path exists, the code subtype uses the wrong primary score, smoke omits both code probes and the A4−A3 primary, and the standalone snapshot/gold-action gates still admit important leakage cases. Before results are trusted, the real run path must enforce and preregister the complete population/audits, reconstruct Jira history correctly, enrich PR diffs, implement pinned providers and the actual A4 tool agent, use the literal scoring formula, require ledger-backed snapshots and complete task-gold checks, and add end-to-end tests that fail on these defects. **Grade: FAIL.**
