# Round 2 review — E4 context envelope

1. **blocker — `apps/eval/src/harnext_eval/e4/run.py:785-814, 862-872`.** **Spec:** E4 must be able to falsify C4: “everything” winning, V3 failing to beat V0, or envelope choice making no difference are substantive results (§1, §7); validity checks concern leakage, gold, judge calibration, size, and balance, not whether the hypothesis wins. **Code:** `non_vacuous_arms` requires the directional result `V0 < V3` and `V6 != V3`, makes that requirement mandatory, and suppresses every primary contrast when it is false. A valid null result, V0 win, or V6 win is therefore labelled invalid instead of falsifying the claim. This is not the R1-promised constant-arm gate. **Minimal fix:** define non-vacuity only as the preregistered constant-output/plumbing failure (for example, no task-level prediction or score variation at all); always publish valid paired contrasts when a competing arm wins or ties, and label the claim falsified rather than the experiment invalid.

2. **blocker — `apps/eval/src/harnext_eval/e4/tasks.py:377-425, 418-454`; `apps/eval/src/harnext_eval/corpus/synthetic.py:817-852, 884-913`.** **Spec:** Corpus-S gold is scripted correct handling derived deterministically from the world state, and `required_ids` are world-state fact IDs (§4 lines 126, 129; §7 lines 387, 414). **Code:** the E4 loader trusts `scripted_handling.owner`, `required_ids`, and `time` from situation metadata and merely uses `world_state` as an optional owner fallback. The actual synthetic corpus exports no world-state dumps in its metadata and manufactures `required_ids` as the issue key already present in the trigger. Thus Corpus-S `id_cov` is not fact coverage against world state; the smoke run consequently has `id_cov=1.0` in every arm. R1 fix 3/15 is not genuine. **Minimal fix:** emit versioned hourly world-state snapshots with stable fact IDs, implement the preregistered deterministic situation-to-action rule over the snapshot at onset, derive all required fact IDs from that snapshot, and reject Corpus-S E4 input without those artifacts.

3. **blocker — `apps/eval/src/harnext_eval/e4/run.py:560-585, 279-328`; `apps/eval/tests/test_e4e5/test_runs.py:361-414`.** **Spec:** for a batch window, run the builder with Vx, apply that delta to a scratch copy, then measure the entity’s E2 state at the close (§7 lines 388, 410-414). **Code:** `run_e4` selects `store.snapshot(task.T)`—the fixed S3 commit that has already incorporated the closing window—and `_scratch_batch_fold` copies that post-window state before folding a synthetic envelope event. The existing correct state can therefore answer the E2 probes independently of the envelope; the test makes this vacuous by pre-folding both events and using an oracle that always returns `Open`. **Minimal fix:** copy the last snapshot before the sampled window, feed the window plus Vx to the real builder, apply only its resulting delta, and show in a test that at least one planted envelope changes a probe answer while the source and pre-window scratch base remain unchanged.

4. **major — `apps/eval/src/harnext_eval/agents/envelope.py:286-322`; `apps/eval/src/harnext_eval/e4/run.py:586-591, 647-675`; `apps/eval/src/harnext_eval/providers/llm.py:49-58`.** **Spec:** V5 is V3 plus callable just-in-time tools, isolating pull from pushed context; `tool_calls` is observed use (§7 lines 399, 410, 414). **Code:** the provider protocol has no tool interface. Before calling the model, the runner eagerly invokes the advertised tools in fixed order and appends their results to the prompt; the model cannot choose whether, when, or with what query to call them. V5 is therefore another pushed-context arm, and its call count is harness activity rather than agent tool use. The R1 test explicitly asserts three eager calls, so it would not fail if pull semantics remained absent. **Minimal fix:** add provider-level tool definitions/callback dispatch, let the model initiate calls, append only actual call transcripts under the shared budget, and test zero, selective, and repeated calls with model-chosen arguments.

5. **major — `apps/eval/src/harnext_eval/agents/envelope.py:212-218, 363-364`; `apps/builder/src/harnext_builder/agentfs/seed.py:19-28, 64-90`; `apps/eval/tests/test_e4e5/test_tasks_envelopes.py:132-180`.** **Spec:** V4 adds the agent’s own last ten actions to V3 (§7 line 398). **Code:** envelope construction looks for `actions.md`/`action_log.md`, but the production S3 schema has no action-log file and `run_e4` never persists the action agent’s outputs. V4 is V3 plus an empty heading on real stores. The test invents `entities/.../actions.md`, so it does not cover the production layout. **Minimal fix:** define and populate a snapshot-bounded action log from prior E4/action-agent decisions, add it to the S3 contract, and test continuity/idempotency against a real S3 fixture.

6. **major — `apps/eval/src/harnext_eval/agents/envelope.py:121-125, 367-368`; `apps/builder/src/harnext_builder/agentfs/seed.py:27, 43-44, 71-89`; `apps/eval/src/harnext_eval/stores/fake_curator.py:80-93`; `apps/eval/tests/test_e4e5/test_tasks_envelopes.py:153-183`.** **Spec:** V7 adds the relevant entity’s superseded bodies to V3 (§7 line 401). **Code:** the production and fake S3 layouts store superseded facts globally at `_meta/superseded.md`, while V7 searches only the entity directory. Production V7 therefore adds an empty three-token heading (as seen in the fresh smoke `sizes.csv`) and cannot test distractors. The test invents per-entity superseded files, so R1 fix 10/28 is not operational. **Minimal fix:** read the global superseded ledger at the snapshot and deterministically filter entries to the exact entity (or change the S3 schema and all builders to entity-local ledgers); test with the real S3 layout and two entities.

7. **major — `apps/eval/src/harnext_eval/agents/envelope.py:221-250, 353-385`; `apps/eval/tests/test_e4e5/test_tasks_envelopes.py:165-189`.** **Spec:** V1 contains the raw last 20 or last 100 entity events (§7 line 395), while the explicit size validity rule is V3 median ≤12k and V6 ≥3×V3 (§7 line 421). **Code:** every non-V6 arm is silently prefix-truncated to 12k. For V1-N100 this keeps the oldest prefix of the selected last-100 JSONL, not the most recent events, and can make N20 and N100 byte-identical; the fresh smoke reports equal V1-N20/V1-N100 medians and identical Q. The test checks only section names, not event identities/count/order. **Minimal fix:** preserve exact last-N semantics (or preregister a distinct token-budgeted V1 and truncate from newest backward), log delivered event IDs, and add fixtures where 20 and 100 exceed the budget.

8. **major — `apps/eval/src/harnext_eval/e4/tasks.py:68-84, 285-299, 332-364`; `apps/eval/tests/test_e4e5/test_tasks_envelopes.py:84-104`.** **Spec:** R fast tasks are new Blocker/Critical issues, `[VOTE]` threads, or CVE mentions with at least one human decision in any of the four groups (§7 lines 374-386). **Code:** `issue_creation` is substring-based and accepts types such as `issue.reopened`; CVE eligibility is arbitrarily restricted to selected shapes rather than the rules floor; and `_primary_eligible` drops tasks whose only valid human decision is Place or Text. This changes both the preregistered population and reported group coverage. The test covers only a priority transition that lacks “open” and never plants text-only/place-only tasks or reopened/CVE negatives. **Minimal fix:** use exact source/event-type predicates matching the preregistered R rules, and keep every task with any human-decision group while representing an unavailable Q component as NA under a preregistered analysis rule rather than silently changing the population.

9. **major — `apps/eval/src/harnext_eval/e4/tasks.py:196-205, 232-263`; `apps/eval/tests/test_e4e5/test_tasks_envelopes.py:64-79`.** **Spec:** People gold includes reviewers of linked PRs, and Corpus-R `required_ids` is the issue key plus linked PR/KIP keys (§7 lines 381, 414). **Code:** no PR-link map is built. A review is related only if it shares the issue subject or itself has an issue key in its title; normal review events on `pr:N` therefore do not join to the earlier title-linked PR. Required PR IDs are added only for merged PR events that also carry file lists, and KIP IDs only from those same titles, omitting opened/unmerged/fileless linked PRs and other linked KIPs. The test disguises the problem by giving its GitHub review the issue subject. **Minimal fix:** first build title-only issue/KIP↔PR joins, then attach reviews by canonical PR ID/subject and derive required IDs from every qualifying link independent of merge/file availability.

10. **major — `apps/eval/src/harnext_eval/e4/tasks.py:197-202, 265-270`; `apps/eval/tests/test_e4e5/test_tasks_envelopes.py:236-358`.** **Spec:** Text gold is the first committer comment/reply after T, with no 14-day cutoff (§4 line 129; §7 line 384). **Code:** the single derivation loop breaks after 14 days, so a first committer reply on day 15 or later is silently absent. The horizon tests cover only PR/assignee/duplicate boundaries. **Minimal fix:** derive each group on its own stated horizon and scan committer replies through the corpus window; add day-14/day-15 and later-first-reply cases.

11. **major — `apps/eval/src/harnext_eval/e4/tasks.py:140-145, 197-210`; `apps/eval/tests/test_e4e5/test_tasks_envelopes.py:329-337`.** **Spec:** only formatting-only PRs are excluded and bot-set actions are not gold (§7 lines 386, 408, 418). **Code:** a title regex alone classifies any title containing “format”, “whitespace”, or “style-only” as formatting-only, so substantive fixes such as a formatter/parser change can be dropped. Conversely, category/assignee changes with a missing actor are accepted as human because only known bot actors are rejected. The test uses an explicit `formatting_only=True` and has no unknown-actor case. **Minimal fix:** require an audited structured formatting classification/diff classifier, require an authoritative human setter for human-action fields, and preserve setter identity in loaded task gold so it can be revalidated.

12. **major — `apps/eval/src/harnext_eval/e4/run.py:113-158, 711-747`.** **Spec:** tasks without a decision in a group have no gold for that group, and group coverage is reported; localisation and reply metrics apply only where their gold exists (§7 lines 383-386, 414). **Code:** `_score_action` always calls `localisation_scores`; that grader treats absent file gold as a scored negative/empty-set case rather than NA. If judging is enabled, every fast task is also judged even when it has no Text gold. These values are then averaged per envelope, biasing secondaries by uncovered tasks. **Minimal fix:** emit NA for Place/Text scores when the corresponding coverage is false, run the judge only on covered Text tasks, and report the denominator beside each secondary.

13. **major — `apps/eval/src/harnext_eval/e4/run.py:243-252, 303-328`; `apps/eval/tests/test_e4e5/test_runs.py:361-414`.** **Spec:** `evidence_valid` requires every emitted `evidence_event_id` to exist and predate T (§7 lines 411, 414). **Code:** the runner does not parse emitted `evidence_event_ids`; it scans changed-file prose only for IDs already present in the replay index. Unknown or malformed emitted IDs disappear before `_validate_evidence`, so they can never be reported missing/malformed. It also pre-populates the synthetic builder input with the envelope’s visible IDs, making fake-builder evidence validity largely tautological. The batch test asserts neither evidence validity nor missing/post-T cases. **Minimal fix:** parse the builder delta’s evidence field/schema verbatim, validate each emitted value against the replay ID→time map, do not supply an answer-like evidence list in the input event, and test empty, unknown, malformed, and post-T IDs.

14. **major — `apps/eval/src/harnext_eval/e4/run.py:329-374, 407-474, 711-751`.** **Spec:** batch quality is E2 accuracy, whose exact score is macro accuracy over probe families (§7 lines 410-414; E2 §7 line 291), and all secondaries use paired inference/Holm where applicable (§8 lines 503-505). **Code:** batch accuracy is a flat mean over probes, so family prevalence changes the score. `_contrast_table` ignores batch rows because Q is NaN, and no paired batch-delta/evidence/pass³ contrast or uncertainty is produced. **Minimal fix:** reuse E2’s family-macro aggregation and paired entity-clustered analysis for batch rows, define batch correctness for pass³/evidence McNemar, and include these named secondaries in Holm correction.

15. **major — `apps/eval/src/harnext_eval/e4/run.py:407-474`.** **Spec:** binary comparisons use McNemar; the experiment’s named secondaries are Holm–Bonferroni adjusted; paired CIs accompany task-level effects (§7 lines 412-414; §8 lines 503-505). **Code:** McNemar dichotomises continuous Q as `Q >= 1.0`, a “perfect composite” variable not named by the spec, and Holm is applied only to V7/V8 Q tests. There are no paired CIs/tests for localisation, ROUGE-L, judge win, evidence validity, tokens, latency, or tool calls. R1 fix 5 and its test are therefore incomplete; the test asserts column presence and a resample count, not the literal inferential family. **Minimal fix:** preregister the binary outcomes to which McNemar applies, produce paired clustered contrasts for every named secondary, and apply one documented Holm family across those secondary hypotheses.

16. **major — `apps/eval/src/harnext_eval/e4/run.py:377-404, 541-547, 653-667, 954-987`; `apps/eval/src/harnext_eval/config.py:62-80`; `apps/eval/tests/test_e4e5/test_runs.py:447-488`.** **Spec:** the pairwise judge is a different model family, uses both orders, and is usable only after 200 judgements per corpus also labelled by two humans with κ≥0.6 (§7 lines 384, 419-420). **Code:** `E4Experiment` never constructs or passes a judge provider; there is no judge-provider/model configuration, so the normal CLI path can never use the feature. The direct helper skips human disagreements and can declare calibration usable with far fewer than 200 judged records, while `judge_kappa.csv` reports the input length. Runtime judging compares the candidate to `task.gold["judge_baseline"]`, which normal tasks do not derive, so it defaults to an empty response. The test only exercises manual dependency injection with unanimous booleans and does not assert runtime `judge_win`. **Minimal fix:** add a configured different-family judge path and frozen calibration-file schema, require 200 usable dual-human labels per corpus (with explicit adjudication/reliability policy), derive the intended comparator, and test the CLI path plus disagreement/shortfall/empty-baseline failures.

17. **major — `apps/eval/src/harnext_eval/e4/run.py:331-373, 638-643`; `apps/eval/src/harnext_eval/agents/reader.py:128-158`.** **Spec:** every quality result is beside provider-usage tokens, dollars, latency, and tool calls (§2 line 39; §7 line 414; §8 line 509). **Code:** batch accounting adds only `Answer.tokens_read` (selected material) to builder input, omits the reader system/question prompt and all reader output tokens, and reports only envelope tool calls—not E2 store opens or builder tool activity. Batch dollars are consequently understated even when frozen prices are supplied. **Minimal fix:** collect the reader’s reported input/output usage and retrieval calls through its accounting hook, include builder transcript usage/tool calls, and aggregate all components explicitly in batch run rows.

18. **major — `apps/eval/src/harnext_eval/e4/run.py:477-507, 855-872`; `apps/eval/tests/test_e4e5/test_runs.py:424-444`.** **Spec:** LLM-built stores use at least three seeds and report between-seed spread of accuracy and health; randomness must not be mistaken for an envelope effect (§8 lines 507, 524). **Code:** seed aggregation reads every `contrasts.csv` regardless of that seed’s `valid_primary`, reports only contrast-effect SD (not per-envelope accuracy or health), and does not feed the required-seed status back into `valid_primary`. **Verdict — FAIL.** E4 is not faithful enough for trusted results. The primary validity gate suppresses legitimate falsification, Corpus-S gold and required IDs are not world-state-derived, and the batch arm starts from already-folded state; V4, V5, and V7 are not the specified production conditions; R joins, evidence validation, secondary statistics, judge configuration, batch accounting, and seed qualification remain incomplete.
