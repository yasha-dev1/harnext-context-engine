# R2 review — E1 routing

1. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:214-224`; `apps/eval/src/harnext_eval/e1/policies.py:399-406`; `apps/eval/tests/test_e1/test_policies.py:130-143`.** **Spec:** R7 is `always-fast`, the cost ceiling. **Code:** `_admit_month` treats R7 like every ordinary ranked arm and admits only the top 1/2/5/10%; its constant scores are tie-broken by event ID. The test checks only that every R7 *score* is `1.0`, so it passes even though R7 does not admit everything. **Minimal fix:** bypass budget selection for R7 and mark every event fast; assert exact R7 admissions and its resulting recall/precision/cost floor.

2. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:205-230`; `apps/eval/src/harnext_eval/e1/policies.py:471-512`; `apps/eval/tests/test_e1/test_policies.py:116-127`.** **Spec:** every R0–R6 condition is evaluated at an admission budget, and the Exact-scores block defines `admitted_b` as the top *b* percent within the evaluation month. **Code:** every rule hit in R1/R5 is `mandatory`, so those arms may exceed the monthly capacity; the test explicitly blesses 15 admissions at a 10-event capacity. This makes the primary conditions unequally budgeted. `rules_over_budget` documents the violation but does not make the comparison valid. **Minimal fix:** preregister one total-budget rule-floor policy, enforce the same monthly capacity for all compared arms, and declare a month infeasible rather than silently exceeding it (or change the spec/preregistration before running).

3. **Major — `apps/eval/src/harnext_eval/config.py:18-36`; `apps/eval/src/harnext_eval/e1/policies.py:421-446`; `apps/eval/tests/test_e1/test_policies.py:39-50`.** **Spec:** R1's dispute threshold *N* and every threshold must be frozen in configuration/PREREG. **Code:** `RulesConfig` exposes only `enabled`; `make_policy` uses an unreachable `getattr(..., 1000)` default. The test constructs `RuleSettings` directly and therefore does not prove the experiment can configure *N*. Moreover a permitted config with `rules.enabled: false` silently turns off the defining rules in R1 and R5. **Minimal fix:** add and require `dispute_amount` in strict config, record it in the manifest, and make the fixed E1 arm definitions independent of unrelated engine-ablation flags.

4. **Blocker — `apps/eval/src/harnext_eval/e1/score.py:73-129,356-378`; `apps/eval/src/harnext_eval/e1/run.py:259,535-557`; `apps/eval/tests/test_e1/test_score_calibration.py:26-35,39-46`.** **Spec:** VUS-PR must come from the reference implementation and be validated on three hand-built series with known reference values; the random VUS floor applies to that same metric. **Code:** VUS is a local row-index soft-label/AP approximation. Reported rows use `max_buffer=5`, while `random_sanity_scorer` calls the default `max_buffer=0`, so `check.random_vus_at_prevalence` does not even validate the metric being reported. The tests contain one trivial perfect/constant-score series and derive expectations from this implementation, not three reference fixtures. The Round 2 smoke failure is therefore not interpretable as a valid VUS failure; the later small-sample bypass only hides it. **Minimal fix:** pin the reference VUS package, use timestamped ranges and one preregistered buffer setup in reporting and floors, and add three published/reference-valued fixtures.

5. **Blocker — `apps/eval/src/harnext_eval/e1/score.py:203-273,319-345`; `apps/eval/src/harnext_eval/e1/run.py:309-339`; `apps/eval/tests/test_e1/test_score_calibration.py:59-83`.** **Spec:** affiliation P/R is from the reference implementation for every scored condition, and NAB low-FN is a named secondary. **Code:** affiliation is another vendored approximation (including a three-anchor approximation for interval recall), is emitted only for R5 at 2% on sidecar situations, and has no exact reference-valued tests. NAB is not reported at all; leaving an unused `nab_low_fn_score` helper does not satisfy the named measurement. **Minimal fix:** call the pinned affiliation and NAB reference implementations on timestamped situation windows for all arms/budgets and validate three exact series.

6. **Major — `apps/eval/src/harnext_eval/e1/run.py:508-527,529-570`.** **Spec:** jitter S onsets ±5 minutes and flip 10% of R labels, then re-score; run random and always-flag scorers through every metric, and drop a broken metric that ranks a floor near R5. **Code:** label flipping recomputes only recall/precision; onset jitter changes only the delay calculation against unchanged admissions; random/always checks cover only recall, precision, and the mismatched VUS helper. 7. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:537-605,613-635`.** **Spec:** every item in E1's Validity checks is a gate, including every LF's accuracy/coverage, prior-only tuning, PREREG chronology, three reference metric series, the 100-item/two-annotator sanity sample, and required remedial actions. **Code:** zero-coverage LFs are removed before the coverage floor (`coverage > 0`), so the exact failure the floor names cannot fail the run. **Verdict.** E1 is not faithful enough for trustworthy results. The Round 2 R5=1.0 smoke result is a legitimate consequence of the single held-out, rule-negative `silent-burst` fixture being deliberately aligned with causal volume/multi-window guards—the explicit gold fields are stripped before scoring—but it is one-item plumbing evidence, not a performance result. The experiment still has blocker-level failures in R7 and equal-budget semantics, reference temporal metrics, validity/pre-registration/profile enforcement, harm execution/non-vacuity, replay integration, and real-profile scalability; NaN inference is not explicitly labelled and the nominal 2,000-event generator remains far below the specified constructed sample. These must be corrected, and the tests made discriminating, before either smoke outputs or real-profile results can be trusted. **Grade: FAIL.**
