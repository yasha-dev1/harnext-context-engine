# R1 review — E1 routing

1. **Blocker — `apps/eval/src/harnext_eval/e1/labels.py:160-167`.** **Spec:** §4.1 requires all listed JIRA, `dev@`, and GitHub revealed-urgency functions: JIRA fixVersion set to the in-flight release; `dev@` three distinct responders, cancelled/re-cast votes, and CVE/“blocker” threads; GitHub hotfix references and trunk-CI-failure/fix sequences, in addition to the functions already present. **Code:** `DEFAULT_LABELING_FUNCTIONS` contains only committer reply, resolution, priority raise, linked PR, revert, and declared priority. The omitted functions change the gold, not merely diagnostics. **Minimal fix:** implement every source-specific LF with the specified horizon/relationship checks, add all of them to the default model, and add fixtures for each positive, abstaining, and wrong-source case.

2. **Blocker — `apps/eval/src/harnext_eval/e1/labels.py:85-166`.** **Spec:** §4.1 defines source-specific human reactions or consequences. “Later” has no arbitrary 30-day cutoff, and a hotfix/linked PR must reference the candidate. **Code:** the functions do not gate on source; `committer_reply` accepts any comment/mail/message, `reverted` accepts the word “revert” in any later same-subject event, and `linked_pr` accepts a GitHub-looking event without verifying that it references the candidate. Priority and declared-priority outcomes are silently truncated at 30 days. This can label an event from an unrelated outcome or miss a valid later one. **Minimal fix:** make each LF source- and relation-aware, use the spec horizons exactly, and represent “later” through an explicitly preregistered/censorable horizon rather than a hidden constant.

3. **Major — `apps/eval/src/harnext_eval/e1/labels.py:176-189`.** **Spec:** gold is derived from post-*t* outcomes; an item without an observable full outcome horizon is not a known negative. **Code:** every event through the final replay timestamp is labelled, even when its 1 h/24 h/48 h/30 d suffix extends beyond the corpus. Missing future data becomes LF abstention and ultimately a low/negative fused label, so the final evaluation month is right-censored. **Minimal fix:** record per-LF observability, exclude or separately report candidates whose required horizon crosses the replay boundary, and report the exclusion count.

4. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:45-58,229-236`.** **Spec:** Corpus S gold comes from injected situations with onset, cost weight, scripted truth, and hard negatives; it is true by construction and must be kept outside router-visible material. **Code:** the runner guesses gold from arbitrary keys in the event payload (`urgent`, `situation_label`, `cost_weight`, etc.), treats every positive `cost_weight` as an urgent event, and otherwise falls back to the real-corpus weak label model. This neither derives situation-level gold correctly nor separates evaluation-only labels from material offered to a `RouterPolicy`. **Minimal fix:** load a typed sidecar situation manifest keyed by event/situation ID, with explicit positive and hard-negative labels, onset/end/entity/cost, and strip all gold-only fields before feature or policy evaluation.

5. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:229-241`.** **Spec:** E1 must run on Kafka R-long from 2022-01 through 2026-06, a Flink replication, and Corpus S with at least 200 situations over three seeds; rolling evaluation begins at 2022-03. **Code:** any corpus with two months is accepted, and a two-month corpus evaluates its second month. There is no validation/reporting of corpus identity, window, Flink replication, injected archetype counts, hard negatives, or three S seeds. **Minimal fix:** add corpus-specific entry points/preflight checks and condition identifiers; require the registered R-long/Flink windows and S situation/seed counts before a result can be marked valid.

6. **Major — `apps/eval/src/harnext_eval/e1/labels.py:192-242,267-277`.** **Spec:** a Snorkel-style model must report meaningful estimated LF accuracy/coverage and agreement between outcome functions and declared priority. **Code:** every shipped LF is positive-or-abstain, so class balance and LF accuracy are not identifiable from disagreements; the implementation pins them with a Beta prior and clips them above 0.501. The “agreement” calculation treats all outcome abstentions as a negative outcome and conditions only on declared priority firing. These numbers can pass/fail the validity floor without measuring LF accuracy or agreement as specified. **Minimal fix:** use a validated weak-supervision label model with identifiable positive/negative votes (or audited accuracy estimates), and compute agreement only on genuinely comparable labels while reporting the comparison population.

7. **Major — `apps/eval/src/harnext_eval/e1/features.py:167-186,203-212`.** **Spec:** 5-minute and 1-hour counts are ratios to their baselines, and robust-z uses median/MAD over a four-week rolling history in 5-minute buckets. **Code:** `count_5m_ratio` divides by `median + 1.4826*MAD`, while `count_1h_ratio` divides by `12` times that same 5-minute scale rather than an independently measured hourly baseline. R3 then learns one median/MAD over all tuning events (`policies.py:195-204`), not a rolling four-week robust-z at each decision. **Minimal fix:** maintain separate causal four-week bucket distributions for 5-minute and 1-hour baselines and compute the specified ratios/z-score from those rolling distributions.

8. **Blocker — `apps/eval/src/harnext_eval/e1/policies.py:142-183,386-405`.** **Spec:** R2 is global z-score/global HBOS with no entity keying. **Code:** `GlobalPolicy` calls the per-baseline-key extractor, fits on duplicated key-conditioned vectors, and takes the maximum key-conditioned score. Thus R2 still uses per-entity baselines and does not isolate the necessity of entity keying. The runner also always constructs the default HBOS version; its implemented `z` variation is never run. **Minimal fix:** build one genuinely global causal feature stream/model (one vector per event), and run/report the preregistered global method(s) as distinct, frozen conditions.

9. **Major — `apps/eval/src/harnext_eval/e1/policies.py:58-80,386-405`.** **Spec:** R1 is exactly declared Blocker/Critical, `[VOTE]`, CVE, the word “blocker”, dispute at preregistered threshold *N*, and on-call page. **Code:** substring matching flags `critical`/`blocker` anywhere (including strings such as “noncritical”), the dispute threshold is a hard-coded 1,000 and only checks top-level amount fields, and the E1 config has no *N*. `make_policy` therefore cannot reproduce a preregistered rules floor. R6 is also only LOF; no kNN variation is executed. **Minimal fix:** implement field-aware/boundary-aware rules, add the frozen dispute threshold to config, support nested payment shapes, and register the chosen LOF/kNN reference condition explicitly.

10. **Blocker — `apps/eval/src/harnext_eval/e1/policies.py:274-311`.** **Spec:** R5 requires an absolute-volume floor and multi-window confirmation. **Code:** the volume floor defaults to one while `count_5m` includes the current event, making the floor automatically pass in the baseline config. “Multi-window” means only that the immediately previous anomalous *event* for the key was anomalous; there is no window identity, distinct-window requirement, or reset after an intervening window. The anomaly cutoff is a fixed training 95th percentile for every admission budget. **Minimal fix:** define the preregistered absolute event-volume threshold, track anomaly confirmation by actual 5-minute/session windows, reset it correctly, and learn the budget-specific guard threshold only from months before *m*.

11. **Blocker — `apps/eval/src/harnext_eval/e1/policies.py:301-305,408-444`; `apps/eval/src/harnext_eval/e1/run.py:150-159`.** **Spec:** R5 admissions must satisfy its guards. **Code:** guard failures are converted to the finite score `-1e12`; `budgeted_decisions` always fills the requested capacity, so it admits guard-failing events whenever fewer guard-passing events exist. The recorded `admitted`/lane therefore does not represent R5. **Minimal fix:** carry an explicit eligibility bit into admission and never select ineligible rows; report unused capacity when guards leave fewer eligible events than the budget.

12. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:126-159`; `apps/eval/src/harnext_eval/e1/policies.py:427-433`.** **Spec:** literally, `admitted_b(e)` is the top *b* percent of scores **within the evaluation month**. **Code:** `_admit` allocates and rounds a separate capacity for each source. It also forces at least one admission in every non-empty small source stratum, so aggregate admissions can greatly exceed *b* percent and are not the month's global top scores. R1 ignores the budget entirely and admits every rule hit. These are not equally budgeted conditions. **Minimal fix:** rank once per month/population across all sources with a single deterministic capacity, then slice the resulting decisions for per-source reporting; define and enforce how the rules floor consumes that same total capacity.

13. **Blocker — `apps/eval/src/harnext_eval/e1/policies.py:286-311`; `apps/eval/src/harnext_eval/e1/run.py:150-159`.** **Spec:** R5 has an unconditional rules floor plus deviation/guards. **Code:** rule events receive a large score but are still passed through the same capped top-*b* selector; if rule hits exceed capacity, some rules-floor events are dropped. **Minimal fix:** reserve/charge rule admissions explicitly under the frozen total-budget policy and guarantee the floor semantics; fail/report infeasible months if rule volume itself exceeds the stated budget.

14. **Blocker — `apps/eval/src/harnext_eval/replay/driver.py:203-228`; `apps/eval/src/harnext_eval/e1/run.py:82-163`.** **Spec:** all arms replay the identical stream in order, and the RouterPolicy seam is the routing implementation used by replay. **Code:** E1 bypasses `run_pipeline` and reimplements admission. The driver, meanwhile, ranks all selected events across the entire replay/cutoff rather than within month, and it knows future scores before routing the first event. Consequently offline E1 decisions and live replay decisions differ, and using the driver for the harm/store path would leak the future score distribution into earlier fast-lane admissions. **Minimal fix:** share one month-scoped offline decision engine for E1 and a causal thresholded engine for live replay, with an explicit mode; exercise the same policy/guard semantics through the seam and verify decision identity where the modes are meant to coincide.

15. **Major — `apps/eval/src/harnext_eval/replay/driver.py:214-223,231-258`.** **Spec:** the absolute guard is an event-volume floor and confirmation is multi-window. **Code:** the driver compares the policy's anomaly score with `absolute_floor`, counts candidate events forever per key, confirms every later candidate after the second, and never reasons about volume or window boundaries. It also applies an extra situation-dedup guard that is not part of R5's E1 definition. **Minimal fix:** expose typed policy evidence (volume, window ID, situation ID) through the seam and implement the exact E1 guards, scoped/reset by real windows.

16. **Major — `apps/eval/src/harnext_eval/types.py:46-54`; `apps/eval/src/harnext_eval/replay/driver.py:164-173`.** **Spec:** every decision log contains `decision_ts`, the baseline key whose maximum score was used, and fired feature/HBOS terms. **Code:** `RouterRecord` has only event time `t`; the driver logs the first baseline key regardless of which key produced the maximum, and its `features_fired` contains only routing/guard booleans rather than the policy's terms. **Minimal fix:** extend the shared record with decision time and policy-provided selected-key/attribution fields, populate them at routing time, and test multi-key selection.

17. **Blocker — `apps/eval/src/harnext_eval/e1/score.py:73-128`; `apps/eval/src/harnext_eval/e1/run.py:187`.** **Spec:** VUS-PR must come from the reference implementation. **Code:** this is a local approximation, and production calls it with the default `max_buffer=0`; the “volume” contains one zero-radius slice and collapses to weighted average precision. It is not VUS-PR with tolerance buffers. **Minimal fix:** call the pinned reference VUS-PR implementation with preregistered temporal buffers and validate its exact outputs against three published/reference series.

18. **Blocker — `apps/eval/src/harnext_eval/e1/score.py:131-199`; `apps/eval/src/harnext_eval/e1/run.py:174-190`.** **Spec:** affiliation P/R is from the reference implementation and is time-distance-based per situation. **Code:** this is another local approximation over row indices, with no timestamps or situation boundaries. Irregularly spaced events one row apart receive the same distance as events seconds apart, and separately injected situations can be merged into one binary interval. **Minimal fix:** use the pinned affiliation reference implementation on timestamped situation intervals and admissions, preserving situation/entity boundaries.

19. **Major — `apps/eval/src/harnext_eval/e1/score.py:245-271`.** **Spec:** report the NAB low-FN profile. **Code:** the function explicitly implements a “NAB-like” custom score with an index-count window of five, not NAB's timestamped anomaly windows/profile/reference scoring. **Minimal fix:** invoke the NAB reference scorer with the low-FN profile and preregistered anomaly windows, or remove the metric rather than label an approximation as NAB.

20. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:166-193,288-304,366-368`.** **Spec:** report `delay = t_first_admission(entity) - t_onset` (p50/p95), jitter S onsets ±5 minutes and re-score, and compute paired `Q_action(now) - Q_action(window close)` on S3. **Code:** the metric table has no delay; robustness only flips labels; onset jitter is never called; and `harm.csv` is always an empty header. This leaves the “promoting them changes the outcome” half of C1 entirely untested. **Minimal fix:** load situations/onsets, compute and summarize delay, rerun decisions/metrics after seeded onset jitter, and execute the two S3 action tasks through the E4 composite and leakage gate before writing non-empty paired harm rows.

21. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:166-193,269-283,370-404`.** **Spec:** primary recall is a paired R5−R1 and R5−R2 comparison at 2% on the monthly rule-negative population, with entity-clustered BCa bootstrap confidence intervals. **Code:** metrics are first computed separately per source/month, then the primary is the unweighted mean of those source-month recalls. No all-source monthly score, paired event/entity contrast, bootstrap, confidence interval, or cluster key is produced. Small sources/months therefore receive the same weight as large ones, and significance cannot be assessed. **Minimal fix:** form the literal monthly admission population first, retain entity-level paired outcomes, compute the named contrasts with 10,000 entity-clustered BCa resamples, and report estimates/CIs (plus Holm correction for secondaries).

22. **Blocker — `apps/eval/src/harnext_eval/e1/run.py:323-348`.** **Spec:** LF floors, random/always scorer behavior, injected non-triviality, prior-only tuning, and PREREG chronology are validity gates; broken metrics are dropped and subtle situations regenerated. **Code:** these are merely numeric fields returned with the result. A failed coverage check does not stop or invalidate the run; absence of constructed data makes non-triviality pass; no metric is compared with R5/dropped; and `check.tuning_precedes_evaluation` is hard-coded to `1.0`. The CLI manifest also leaves `prereg_ref=None` by default (`apps/eval/src/harnext_eval/manifest.py:52-76`). **Minimal fix:** implement executable gates with evidence, mark the run invalid/abort on failure, require and timestamp/hash `PREREG.md`, and implement the specified drop/regenerate actions rather than reporting unchecked booleans.

23. **Major — `apps/eval/src/harnext_eval/e1/run.py:217-405`.** **Spec:** validity includes a two-annotator sanity sample of 100 top-scored rule-negative events with kappa versus score bucket, plus the §4.2 gate for the harm tasks. **Code:** neither sample selection/annotation import/kappa nor per-task leakage-gate rows/counts exist. **Minimal fix:** write the fixed sample, ingest two blinded annotations, compute/report kappa by bucket, and run/log all three §4.2 checks for every admitted harm task.

24. **Major — `apps/eval/src/harnext_eval/e1/run.py:196-214,350-387,407-454`.** **Spec:** named outputs are actual `scores.parquet`, `metrics.csv`, `calibration.png`, `operating_curves.png`, `attribution.md`, and `harm.csv` under E1 output. **Code:** without a parquet engine, JSON is written into a file named `.parquet`; the runner writes `calibration.csv` instead of the required PNGs; charts are optional, written later in a `charts/` subdirectory, and can fall back to CSV. Empty harm and placeholder attribution files are nevertheless advertised as artifacts. **Minimal fix:** require a parquet engine/real parquet file, create the two PNGs at the named paths during a successful E1 run, and only advertise complete, non-placeholder artifacts.

25. **Major — `apps/eval/src/harnext_eval/e1/policies.py:105-108,245-256`; `apps/eval/src/harnext_eval/e1/run.py:360-365`.** **Spec:** feature attribution is the HBOS terms firing on true positives with ten case studies. **Code:** `features_fired` stores raw feature values/context plus one aggregate scorer name, not per-feature HBOS contributions; `attribution.md` merely says case studies are a future human-analysis step. **Minimal fix:** extract per-feature HBOS bin/contribution terms for each selected key, aggregate them on true positives, and populate the required ten audited cases.

26. **Major — `apps/eval/src/harnext_eval/e4/run.py:89-144,419-430`; `apps/eval/src/harnext_eval/providers/factory.py:73-88`; `apps/eval/configs/baseline-minimal.yaml:9-18`.** **Spec:** the E1 harm check is an actual fast-lane action-quality comparison on S3. **Code:** E4 resolves the configured provider, and the baseline E1 test config selects a fake reader/builder and S0; the factory therefore returns `FakeLLM`. The fake action generator is lexical and falls back to the same generic action when neither snapshot exposes recognized fields, so now/window-close can receive identical predictions and identical Q for every arm. E1 has no provider/store validation or non-vacuity check because it writes an empty harm file. **Minimal fix:** require S3 and an explicitly pinned non-fake action provider for reportable harm results (allow fake only for smoke), and fail the real experiment if predictions/Q have no cross-time variation or required gold coverage is absent.

27. **Major — `apps/eval/src/harnext_eval/e1/run.py:171-190,323-348`.** **Spec:** every quality result is reported beside tokens, dollars, and latency, and the procedure logs decision time. **Code:** `metrics.csv` has no routing decision latency/cost fields, and the check table has no usage/cost context. Event time is reused as `t`, not measured decision time. **Minimal fix:** measure policy decision latency, report admission/agent cost (zero where genuinely no model is used), and attach harm-task token/dollar/latency usage to the quality rows.

28. **Major — `apps/eval/tests/test_e1/test_policies.py:9-17`.** **Spec:** tests must establish the semantics of R0–R7 and paired determinism. **Code:** the only all-policy test asserts that each arm returns 60 finite numbers. Identical scores, entity-keyed R2, missing rules/guards, wrong LOF direction, or an R7 that does not admit everything would all pass. **Minimal fix:** add hand-built streams whose exact scores/order/admissions distinguish every arm, including multi-key max selection, cold keys, guard pass/fail, rule-floor capacity, and repeated-run identity.

29. **Major — `apps/eval/tests/test_e1/test_score_calibration.py:23-33`.** **Spec:** VUS and affiliation implementations are validated on three hand-built toy series with known reference values. **Code:** there is one perfect-prediction series, VUS is called only with `max_buffer=0`, and the affiliation assertions are only perfect/no-prediction extremes. These tests cannot detect the non-reference distance/buffer formulas. **Minimal fix:** use three non-trivial timestamped series with early/late/overlapping detections and exact values produced by the pinned reference libraries.

30. **Major — `apps/eval/tests/test_e1/test_run.py:9-25`.** **Spec:** the end-to-end test should establish required conditions, metrics, validity, and outputs. **Code:** it asserts only registration, three files, the always-flag check, and policy names. It does not require passing validity checks, correct budget rates, non-identical arm results, non-empty harm/attribution, delay/robustness/statistics, or the required output locations. On the shipped synthetic fixture, a review run produced prevalence 1.0 and identical mean recall for R0 and R2–R6, yet this test passes. **Minimal fix:** use a non-trivial constructed fixture with both positive/hard-negative situations and expected arm separations, assert every validity gate and literal primary contrast, and verify all named artifacts and non-empty required content.

31. **Major — `apps/eval/tests/test_replay/test_driver.py:134-175`.** **Spec:** the RouterPolicy seam must preserve monthly budget, rules floor, absolute volume, multi-window confirmation, selected baseline key, and causal decisions. **Code:** the seam test has only two events at a 50% budget and no rules/guards interaction. It cannot detect whole-replay ranking, future-score leakage, per-month violations, permanent confirmation counters, or wrong logging. **Minimal fix:** add a multi-month, multi-key fixture with later extreme scores and explicit windows; assert early decisions are causal and the exact budget/guard/log semantics match E1.

32. **Minor — `apps/eval/src/harnext_eval/e1/score.py:38-40`.** **Spec:** precision is the ratio with admitted events as its denominator. **Code:** when there are no admissions (notably R1 on the rule-negative subset), the function returns `0.0` rather than undefined/NA. This turns “no denominator” into measured zero precision and can bias summaries. **Minimal fix:** return NaN/NA with an explicit zero-admission count and exclude it from arithmetic summaries.

33. **Major — `apps/eval/tests/test_e1/test_features_labels.py:6`; `apps/eval/tests/test_e1/test_policies.py:5`; `apps/eval/tests/test_e1/test_run.py:4`; `apps/eval/src/harnext_eval/corpus/__init__.py:30`.** **Spec:** the E1 tests must run offline on the deterministic constructed corpus. **Code:** at final verification these modules import `harnext_eval.corpus.synthetic`, but `apps/eval/src/harnext_eval/corpus/synthetic.py` is deleted in the current worktree; the targeted suite fails during collection with five `ModuleNotFoundError` errors. **Minimal fix:** restore the owned synthetic corpus module or atomically update all imports/tests to its replacement, then rerun the complete E1 and replay-driver suite.

**Verdict.** E1 is not faithful to the specification and its results are not currently trustworthy. The primary arms are not equally or monthly budgeted, R2 and R5 do not implement the intended isolations, R5 can admit guard failures and drop its rules floor, real and constructed gold are incomplete/incorrect, the temporal metrics are non-reference approximations, the primary contrast has no paired entity-clustered inference, and the delay/harm/attribution/validity work is largely absent or placeholder. Before results can be used, the team must correct gold and corpus preflights, unify causal router semantics through the seam, implement literal monthly admissions and exact/reference scores, make all validity gates executable, add the specified statistics and harm check with a non-vacuous provider/store, and replace smoke-level tests with discriminating fixtures.
