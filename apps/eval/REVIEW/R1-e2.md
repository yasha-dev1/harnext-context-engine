# R1 — E2 state-fidelity review

1. **blocker — `apps/eval/src/harnext_eval/probes/gen_code_location.py:23-45,56-84`; `apps/eval/tests/test_probes/test_generators.py:116-135`.** The spec says the E2 code probe is asked at a `T` after the linked PR has merged and all material/gold evidence must be available by `T` (`docs/evaluation-spec.md:288`, with the no-post-`T` rule at 148-157). The generator deliberately samples `T` before the merge, derives gold from `(T, T + 14 days]`, and records post-`T` merge events as `source_event_ids`; the test explicitly requires those events to be after `T`. This makes the probe unanswerable from every legal arm and locks the leakage into the tests. **Minimal fix:** sample `T` after the qualifying merge(s), derive files only from linked, non-formatting PRs merged no later than `T` (and within the preregistered 14-day relation), reject any probe whose source event is after `T`, and invert the test assertion.

2. **blocker — `apps/eval/src/harnext_eval/e2/run.py:66-74,287-298`.** The spec's per-item leakage gate must prove that the actual events delivered to the builder before the selected SHA are all `<= T`, check the real item data, and log the result (`docs/evaluation-spec.md:148-157`). E2 passes an already filtered `[event for event in events if event.time <= T]` as the delivery log, fabricates `gold_action_time = T + 1 microsecond`, discards the gate's audit row to `/dev/null`, and then writes a reduced replacement row. The delivered-event assertion and gold-action assertion therefore pass by construction, and post-`T` code-location source IDs are not checked at all. **Minimal fix:** pass the immutable, SHA-associated builder delivery ledger and real gold/action metadata to the gate, validate every `source_event_id <= T`, preserve the gate's own row/reasons, and fail/exclude on any violation.

3. **blocker — `apps/eval/src/harnext_eval/e2/run.py:373-391`; `apps/eval/src/harnext_eval/cli.py:392-398`; `apps/eval/configs/baseline-minimal.yaml:9-18`; `apps/eval/configs/s1-templated.yaml:9-11`.** The spec defines A4 specifically as the curated S3 store (`docs/evaluation-spec.md:277`). The registry runner accepts whichever single store the corpus supplies; the CLI supplies the configured layout (and falls back to S0), so baseline-minimal runs label S0 as A4 and the S1 config labels S1 as A4. The reported primary `A4-A3` contrast can therefore contain no curated store at all. **Minimal fix:** wire A4 only to an explicitly identified S3 handle, refuse a non-S3 handle for A4, and run other layouts under their own condition names rather than relabelling them.

4. **blocker — `apps/eval/configs/s3-curated.yaml:9-13`; `apps/eval/src/harnext_eval/providers/factory.py:67-82`; `apps/eval/src/harnext_eval/providers/llm.py:58-63,98-129`.** D4 requires the fixed `claude-sonnet-5` read agent at temperature 0 (`docs/evaluation-spec.md:573`), but even the online S3 config selects the fake reader, and the provider factory therefore constructs `FakeLLM`. `FakeLLM` only recognizes a short field-cue list, always returns `UNKNOWN` for multi-source link questions, does not understand the code-location wording, and answers temporal questions with the last lexical value rather than the value as of the requested date. Thus all arms receive the same zero on the meaningful multi-source/code probes, and temporal scores do not measure temporal fidelity; the experiment can be vacuous while still producing a contrast. **Minimal fix:** prohibit fake-reader results from being treated as E2 evidence, configure the preregistered real reader for non-smoke runs, and add an explicit `non_evidentiary_smoke=true` marker for fake runs.

5. **major — `apps/eval/src/harnext_eval/e2/arms.py:90-107,287-307`; `apps/eval/src/harnext_eval/config.py:62-79`.** A1 must contain both `N=20` and `N=100` conditions (`docs/evaluation-spec.md:274`). The experiment matrix has only one arm named A1, the runner never passes `n`, and strict configuration has no `last_n` field, so production E2 can run only the hard-coded default of 20. **Minimal fix:** expose and run two named arms (for example `A1-N20` and `A1-N100`) and include `N` in answer/metric/contrast records.

6. **major — `apps/eval/src/harnext_eval/e2/arms.py:97-107`.** Every arm is defined at `snapshot(T)` and raw retrieval is over events `<= T`, but A1 uses `event.time < probe.T`; an event exactly at the cutoff is omitted while A2/A3 and retrieve-everything include it. This breaks condition parity and can make the current value wrong. **Minimal fix:** use `<= probe.T` consistently and add a boundary-time regression test.

7. **major — `apps/eval/src/harnext_eval/e2/arms.py:44-48,97-108,264-276`.** A1 and retrieve-everything are specified as the entity's history, but entity selection is case-insensitive substring matching over the subject and serialized payload. An entity such as `KAFKA-1` matches `KAFKA-10`, and arbitrary prose mentioning the key is treated as entity ownership. That contaminates material and can admit cross-entity state. **Minimal fix:** use the corpus's canonical entity keys/subject and explicit relation edges, with exact normalized equality for entity-history arms.

8. **major — `apps/eval/src/harnext_eval/e2/arms.py:163-184`; `apps/eval/src/harnext_eval/e2/run.py:378-391`; `apps/eval/src/harnext_eval/config.py:67-69`; `apps/eval/src/harnext_eval/providers/factory.py:85-95`.** A3 requires a pinned embedding model (`docs/evaluation-spec.md:276`), but a missing injected provider silently becomes `FakeEmbeddings`, the registered E2 runner never injects a provider, and configuration/factory code now permits only the fake embedding implementation. There is no possible evidentiary pinned-model A3 path. **Minimal fix:** add and construct the configured pinned embedding provider, record its immutable model/version, require it for evidentiary runs, and reserve `FakeEmbeddings` for smoke tests.

9. **major — `apps/eval/src/harnext_eval/e2/arms.py:187-244,247-261`.** A4 is supposed to let the fixed read agent start at `INDEX.md`/`OVERVIEW.md` and open files within budget (`docs/evaluation-spec.md:277`). The code performs a fixed filename heuristic before the reader runs: it follows only root links whose target text contains the entity and files whose path contains the entity, never follows links discovered in an opened entity file, and exposes no file-opening tool to the reader. Relevant curated evidence in topic/shared files is silently inaccessible, so this is not the specified navigation condition. **Minimal fix:** implement deterministic budgeted reader tool calls beginning at the entry files (or preregister an equivalent traversal policy), follow links from opened files, and log each actual open.

10. **major — `apps/eval/src/harnext_eval/providers/tokenizer.py:1-13`; `apps/eval/src/harnext_eval/agents/reader.py:32-48,109-119`.** D8 says truncation is counted with the provider tokenizer (`docs/evaluation-spec.md:577`). `count_tokens` is a regex approximation, despite its module claiming D8, so an 8k material may be over or under the actual Claude token limit and the `±10%` check is measured in the wrong units. **Minimal fix:** use the pinned reader provider's tokenizer for selection, truncation, and logged `tokens_read`; test its boundary against provider token counts.

11. **major — `apps/eval/src/harnext_eval/e2/run.py:158-199,337-368`.** The literal primary score is `macro_acc(A4) - macro_acc(A3)`, where each family has equal weight (`docs/evaluation-spec.md:291`). `_paired_contrast` instead takes the simple mean of all per-probe score differences. Those differ whenever family counts are unequal (including after leakage exclusions), and the separately generated code family receives extra probe weight in this micro-average. The reported primary delta and its CI are therefore not the named primary metric. **Minimal fix:** compute the paired statistic as a difference of family means (and bootstrap that statistic by entity), retaining equal family weight in every resample.

12. **major — `apps/eval/src/harnext_eval/e2/run.py:93-104,108-118`; `apps/eval/src/harnext_eval/probes/gen.py:29-46`.** The Exact scores block assigns exact correctness to extraction/temporal/update/abstention and `link_F1` to the multi-source family; the code-location row separately names file precision/recall and module hit (`docs/evaluation-spec.md:284-291`). The implementation invents `file_f1`, overwrites the localization grader's value with it, generates code location as a sixth family, then pools it with link F1 under `multisource` for macro accuracy. There is no specified rule that makes link F1 and file F1 interchangeable observations. **Minimal fix:** preregister and implement one explicit multi-source family aggregation consistent with the Exact scores block, while report file precision/recall and module hit as the named code secondaries rather than silently substituting file F1.

13. **major — `apps/eval/src/harnext_eval/e2/run.py:186-192`.** Section 8 requires 10,000 clustered BCa resamples (`docs/evaluation-spec.md:503`); E2 hard-codes 1,000. **Minimal fix:** use 10,000 resamples (preferably a frozen preregistered setting) and record the count in `contrasts.csv`/the manifest.

14. **major — `apps/eval/src/harnext_eval/grade/links.py:12-25`; `apps/eval/src/harnext_eval/probes/gen_multisource.py:13-27,88-96`.** Multi-source gold is emitted as identifiers such as `pr:123` and `thread:...`, but the link grader parses only ticket-like `ABC-123` keys and `#123`. A natural answer containing multiple correct PR/thread identifiers falls back to one normalized free-text string and scores zero rather than set precision/recall. **Minimal fix:** define canonical, collision-free PR/thread/ticket IDs (including repository where needed) and parse exactly those IDs into sets in both gold and predictions.

15. **major — `apps/eval/src/harnext_eval/e2/run.py:45,95-104`; `apps/eval/src/harnext_eval/grade/localisation.py:20-24,60-78`.** The E2 code probe asks for both files and modules and the spec names file P/R plus module hit. Prediction extraction accepts only slash-containing paths with a filename extension, so valid files such as `Dockerfile`, `BUILD`, or extensionless scripts and module-only answers are discarded; module hit is then inferred only from the surviving file paths. **Minimal fix:** use a typed reader output with separate `files[]` and `modules[]`, normalize arbitrary repository-relative paths, and grade both fields directly.

16. **major — `apps/eval/src/harnext_eval/probes/gold.py:41-85,88-177`; `apps/eval/src/harnext_eval/probes/gen_extraction.py:24-58`; `apps/eval/src/harnext_eval/probes/gen_temporal.py:24-60`; `apps/eval/src/harnext_eval/probes/gen_update.py:24-70`.** The validity list requires two independent implementations: Python changelog replay and SQL over the raw JIRA export, with disagreements resolved before keeping a probe (`docs/evaluation-spec.md:304`). Both implementations consume the same already-normalized `EvalEvent` objects; the "SQL" implementation serializes those objects into in-memory SQLite, and generators silently drop disagreements rather than logging and resolving them. Correlated extractor errors can therefore agree and become gold. **Minimal fix:** query the raw JIRA export independently, emit a disagreement ledger, require documented resolution, and hash the reconciled probe set.

17. **major — `apps/eval/src/harnext_eval/probes/gold.py:41-85`; `apps/eval/src/harnext_eval/probes/gen_extraction.py:24-58`.** The ground-truth catalogue includes JIRA state plus PR merged/closed, KIP vote outcome, thread response state, and Corpus S world-state dumps (`docs/evaluation-spec.md:123-130`). `PythonGold` only recognizes changelog/direct `{field,to}` transitions, and every scalar probe generator uses that replay for both corpora. There is no Corpus-S world-state path and no explicit derivation for the non-JIRA states. **Minimal fix:** add source-specific R derivations and a separate OrgForge world-state reader, then test every catalogued state kind.

18. **major — `apps/eval/src/harnext_eval/probes/gen_multisource.py:30-59`; `apps/eval/src/harnext_eval/e2/run.py:327-368`.** The spec restricts Corpus-R cross-source gold to the mandated regex joins (issue/KIP keys in commits, threads, and PR titles) and requires join precision/recall to be reported (`docs/evaluation-spec.md:127`). The generator searches issue keys in generic subject/body/data fields, does not implement commit or KIP joins as specified, and E2 writes no gold-join audit metric. **Minimal fix:** implement the exact preregistered joins, human-audit a sample, and report join precision/recall beside E2 results.

19. **major — `apps/eval/src/harnext_eval/probes/gen.py:21-49`; `apps/eval/src/harnext_eval/cli.py:316-362`; `apps/eval/tests/test_probes/test_generators.py:13-47`.** The population is 300 probes per corpus, 60 per each of five families, across at least 150 entities in the May-June R-H1 period and Corpus S (`docs/evaluation-spec.md:267`). Generation creates six independent groups of `per_family` (360 at 60), the normal `run` command defaults to only 10 per group, and neither path enforces corpus/window or 150 distinct entities; the test accepts only two entities per family. **Minimal fix:** encode the five-family/300-probe allocation (with code as a defined multi-source variation), require the registered periods/corpora and `>=150` entities before an evidentiary run, and test those invariants.

20. **major — `apps/eval/src/harnext_eval/probes/gen_abstention.py:21-56`; `apps/eval/tests/test_probes/test_generators.py:102-113`.** Abstention probes should concern a field or entity absent from the evaluated window (`docs/evaluation-spec.md:289`). Half use conspicuous invented entities and half ask for synthetic fields named `absent_field_00001`, making `UNKNOWN` obvious from the question and absent globally rather than establishing realistic window absence. All arms, including the fake model, trivially tie at 1.0; the test checks only that gold is `UNKNOWN`. **Minimal fix:** sample real schema fields/entities known to exist outside but not inside the cutoff/window, verify absence by replay/world state, and test that retrieve-everything cannot find the requested fact while questions remain natural.

21. **major — `apps/eval/src/harnext_eval/e2/run.py:341-369`.** The retrieve-everything `>=0.9` and A0 `<=0.3` conditions are validity gates, with A0-correct probes flagged and reported separately (`docs/evaluation-spec.md:305`). E2 merely stores two booleans and returns/publishes the primary contrast even when they fail; it does not flag A0-correct probes. **Minimal fix:** mark the experiment invalid and suppress evidentiary primary results when a floor fails, and write the required per-probe A0-correct flag/list.

22. **major — `apps/eval/src/harnext_eval/e2/run.py:240-370`.** The remaining explicit validity checks are absent: deterministic exact rerun identity, claim grader run twice with at most 2% disagreement/human resolution, and the 30-probe two-human pilot with pipeline-vs-human kappa at least 0.8 (`docs/evaluation-spec.md:306-307`). No inputs, artifacts, checks, or gates for any of them exist in E2. **Minimal fix:** consume frozen pilot/audit artifacts, rerun the applicable graders, emit agreement/kappa and resolution files, and refuse a full run until thresholds pass.

23. **major — `apps/eval/src/harnext_eval/e2/run.py:257-258,324-325,350-359`.** Equal-budget validity is not enforced. It only checks arms whose recorded original size reaches the budget, `all([])` reports PASS when none do, failures do not stop or invalidate the run, and there is no per-arm fill-status diagnostic. The spec requires logged fill arms to be within `±10%` of 8k (`docs/evaluation-spec.md:309`). **Minimal fix:** distinguish `not_applicable` from pass, record each arm/probe's eligible/fill/actual count, and make any out-of-range filled arm invalidate the contrast.

24. **major — `apps/eval/src/harnext_eval/e2/run.py:240-251,337-368`.** The primary is defined only at the 8k read budget (`docs/evaluation-spec.md:291,300`). `evaluate_e2` accepts any configured budget, emits no budget column in `metrics.csv` or `contrasts.csv`, and always labels A4-A3 as primary. **Minimal fix:** require exactly 8,000 tokens for the E2 primary or add budget as a condition and designate only the 8k row as primary.

25. **major — `apps/eval/src/harnext_eval/config.py:62-79`; `apps/eval/src/harnext_eval/providers/factory.py:67-82,110-113`; `apps/eval/src/harnext_eval/cli.py:370-382`.** The read model is not an independently configurable field; Anthropic silently inherits the builder model or a mutable default, the E2 seed is not passed to the reader, and the manifest records the reader provider/class rather than an immutable reader model revision or prompt hash. This fails the fixed-model/versioned-prompt reproducibility requirements (`docs/evaluation-spec.md:170,527,562-573`) and leaves real API variation uncontrolled in paired comparisons. **Minimal fix:** pin and record an immutable reader model revision and prompt hash, cache/replay one response per `(probe, arm, material hash, model)`, and record any nondeterministic retry rather than silently mixing it into paired effects.

26. **major — `apps/eval/src/harnext_eval/e2/run.py:158-215,327-369`.** Section 8 requires CIs for paired quality results and Holm-Bonferroni across secondaries (`docs/evaluation-spec.md:503-510`). E2 computes inference only for one contrast; per-family secondaries, supersession, and abstention have no clustered CIs or hypothesis correction. It also reports no dollar cost, despite the rule that every quality number be beside tokens, dollars, and latency. **Minimal fix:** produce clustered CIs for all reported quality contrasts, apply/report Holm to the secondary family, and add provider-usage dollar accounting.

27. **minor — `apps/eval/src/harnext_eval/e2/run.py:230-237,260-295,327-368`; `apps/eval/src/harnext_eval/cli.py:370-382`.** The three E2-named outputs (`answers.jsonl`, `metrics.csv`, `contrasts.csv`) are written, but the shared audit/reproducibility outputs are not faithful: the gate is written inside the experiment rather than the specified shared `eval/out/gate.csv`, failure reasons from the real gate are discarded, raw fallback rows retain blank `sha`/`last_event_id`, and the CLI writes only a run-root manifest rather than a `manifest.json` beside E2 output as required by the repository convention (`docs/evaluation-spec.md:154,311,562`). **Minimal fix:** append the full gate schema to the shared gate ledger, populate the actual fallback snapshot fields, and write/link an E2-local manifest containing all input/model/prompt/price hashes.

28. **minor — `apps/eval/src/harnext_eval/e2/run.py:310-314`.** `supersession_error` uses normalized substring containment, so a superseded value such as `Open` is counted inside a valid answer such as `Reopened`. The exact formula asks whether a superseded value is in the answer, but deterministic normalization should compare extracted answer values/tokens rather than arbitrary substrings. **Minimal fix:** parse the answer's scalar/list values and compare canonical complete values (or boundary-delimited mentions) to `superseded_values`.

29. **major — `apps/eval/tests/test_e2e3/test_e2e3.py:150-206`.** The E2 tests do not test the headline claim or formulas. The budget test proves only `tokens_read <= 30` (a short material passes trivially and it does not test provider-token counts or the `±10%` fill rule); the end-to-end fixture has only three of the required families and one entity, then asserts non-empty outputs and the contrast label without checking macro weighting, paired delta, CI, McNemar, supersession, abstention, or a leakage exclusion. **Minimal fix:** add hand-computed, imbalanced-family paired fixtures with multiple entities and exact expected metrics/10k CI inputs, plus over-budget and failing-gate cases.

30. **major — `apps/eval/tests/test_core/test_providers.py:9-41`; `apps/eval/tests/test_core/test_cli_integration.py:36-66`.** Fake-provider tests cover only a scalar latest-value lookup and missing-field abstention; they never exercise temporal, link, or code questions, so they miss that those conditions tie across all arms. The CLI integration test deliberately runs E2 with the S0/fake baseline and merely asserts that a checks object exists, not that required checks pass or that A4 is S3. **Minimal fix:** add tests that expose/forbid fake-family ties for evidentiary runs, assert the real E2 configuration, and require every mandatory validity check to pass before a primary result is emitted.

31. **major — `apps/eval/tests/test_probes/test_gold.py:16-44`.** The claimed independent-gold test builds its expected requests from `PythonGold` itself and compares it with SQLite over the same synthetic normalized events. It never uses a raw JIRA fixture, never plants a correlated normalization error, and never tests disagreement logging/resolution, so it does not test the spec's independence claim. **Minimal fix:** use raw JIRA exports parsed independently by SQL and Python, plant contradictory/malformed cases, and assert that disagreement prevents probe retention until a recorded resolution exists.

**Verdict.** E2 is not faithful to the specification and its current results cannot be trusted. The code-location probes use future gold, the leakage gate is bypassed by construction, A4 can be a non-S3 store, the configured fake reader makes substantive families vacuous, A1/A3 and population conditions are missing or mislabeled, and the primary contrast is not the specified macro-accuracy difference. Before results are usable, those blockers must be corrected; gold must be independently derived and reconciled; the real pinned reader/embedding/tokenizer and exact S3 arm must be enforced; all validity gates must actually gate the run; and the metric, inference, cost, manifest, and test coverage must be brought into literal agreement with the Exact scores and reporting sections.
