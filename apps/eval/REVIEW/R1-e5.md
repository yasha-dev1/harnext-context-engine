# R1 review — E5 cadence and economics

1. **Blocker — `apps/eval/src/harnext_eval/e5/run.py:116-119,187-189`.** The spec (§7 E5, lines 438-439) defines `W20+rules+deviation` as the full R5 router: rules plus per-entity HBOS, an absolute-volume floor, and multi-window confirmation. The E5 code only toggles two booleans and calls `run_pipeline` without a policy. The driver's default is `RulesOnlyPolicy`, whose deviation score is always zero (`apps/eval/src/harnext_eval/replay/driver.py:78-106,125`), so this arm selects tied early events rather than per-entity anomalies; it also inherits configs in which all R5 guards are disabled (for example `apps/eval/configs/s3-curated.yaml:3-7`). `_deviation_promoted` at `run.py:122-124` is a hash sampler, not R5, and is not used by the shared replay path. **Minimal fix:** construct the actual preregistered R5 policy, fit only on the permitted warm-up history, force R5's specified guards, and pass it to `run_pipeline`; remove the hash-sampling surrogate.

2. **Blocker — `apps/eval/src/harnext_eval/replay/driver.py:203-223,231-258` (invoked at `apps/eval/src/harnext_eval/e5/run.py:187-189`).** The spec requires an immediate, budgeted fast-lane decision using only data at or before each event time (§2 line 37, §4 line 146, and E5's “fast lane buys freshness only where budgeted”). The driver scores the entire selected replay first, computes capacity from the final number of rule-negative events, and then ranks all of them. An event's admission therefore depends on future events and their scores. Rules admissions are then added outside that capacity, so the total fast share can exceed `budget_pct`; E5 neither logs nor checks the realized admission share. **Minimal fix:** make routing causal with a threshold/budget controller frozen from prior data, account rules and deviations against the preregistered total admission budget (or explicitly preregister and report a separate rules floor), and emit a per-event decision/admission audit.

3. **Blocker — `apps/eval/src/harnext_eval/e5/run.py:253-267,392-410`.** The exact score (§7 E5 line 445) splits freshness by the ground-truth urgency label: revealed urgency for Corpus R and injected-situation labels for Corpus S (§4 lines 123-126). The code sets `urgent = is_rule_promoted(event)`, which is merely whether a declared rule fires. It therefore calls many revealed-urgent rule-negatives routine, calls noisy declared priorities urgent regardless of revealed gold, and never consumes Corpus S's constructed labels or cost weights. **Minimal fix:** join the frozen E1 label artifact by event ID (and the injected label artifact for S), preserve the label provenance, and split p50/p95 by that gold field.

4. **Blocker — `apps/eval/src/harnext_eval/e5/run.py:237-251`.** The spec literally defines `fresh(e)` as the time of the first snapshot **whose diff references `e.id`** minus event time (§4 line 131; §7 E5 lines 441 and 445). The implementation treats an event ID listed in a fold's usage/accounting row as proof that the fold's diff mentioned or incorporated it. Delivery to a builder is not incorporation: a builder can omit the event, mention it only in a later commit, or write no durable reference at all. **Minimal fix:** inspect successive snapshot diffs (or maintain a separately verified diff-derived mention index) and locate the first commit whose changed content references the ID; fail completeness if any event has no such commit.

5. **Blocker — `apps/eval/src/harnext_eval/e5/run.py:77-101,187-189,245-265`.** Freshness is not measured on the replay clock at the true window-close commit time. For the shared path, the wrapper defaults `commit_time` to `SnapshotRef.T_last_event`, i.e. the last event *inside* the fold, and never replaces it with the gap/max-age deadline. Gap-closed folds are consequently early by `gap_s`; max-age and final-flush folds are also mis-timestamped. `max(0, ...)` then hides impossible negative delays instead of invalidating the run, and events without a record are silently dropped at lines 253-256 despite “every event for freshness” (§7 E5 line 430). **Minimal fix:** have the classifier/replay driver return the actual event-clock close timestamp for every fold, record it immutably with the snapshot, compute signed delays, fail on negative or missing values, and assert freshness row count equals event count.

6. **Blocker — `apps/eval/src/harnext_eval/e5/run.py:287-309`.** E5 is supposed to run the frozen E2 probes and use their derived/constructed state gold at each probe cutoff. Instead, `_shared_e2` rewrites every probe's `T` to the last snapshot time without re-deriving its gold, superseded values, or source IDs. The final store may contain events after the original T, so the reader sees post-T state while being graded against stale as-of-T gold; temporal probes also cease to test their frozen cutoffs. This is direct leakage and incorrect gold derivation. **Minimal fix:** retain each frozen probe T and materialize `snapshot(T)`. If a separate final-time probe set is desired, regenerate its gold independently from the log/world-state dump at that final T and freeze/hash it before the run.

7. **Major — `apps/eval/src/harnext_eval/e5/run.py:298-309,381-388`.** The shared E2 evaluator returns leakage-gate counts, budget checks, floors, answers, and exclusions, but E5 discards everything except `macro_acc.A4`. Thus a cadence's accuracy is accepted even if probes leaked, its read budget was not within tolerance, or its E2 sanity floors failed. No E5-level `gate.csv`, exclusion count, or read-budget validity result is written or surfaced, contrary to §4.2 lines 148-157, E2 validity lines 302-309, PLAN §7, and the shared gate-reporting rule in §8. **Minimal fix:** return/retain per-probe outcomes and all E2 checks, exclude failed probes consistently across paired cadence arms, copy a consolidated gate artifact into E5 output, and make any failed leakage/budget/floor check invalidate the primary result.

8. **Blocker — `apps/eval/src/harnext_eval/e5/run.py:416-431`.** The exact primary is reported only when `acc(W20+rules) >= acc(W1) - CI`, and §8 requires paired, entity-clustered BCa confidence intervals. The code does not compute a cadence contrast or CI. It reads an arbitrary scalar `corpus.meta["e2_accuracy_ci"]`, defaults it to zero, and compares two aggregate point estimates. It cannot determine whether W1 is significantly more accurate. `price_of_freshness = not comparable` at lines 467-470 also becomes true for missing probes/arms/NaNs, not just significant W1 superiority, and reports no price. **Minimal fix:** retain paired per-probe scores, compute the entity-clustered BCa interval with the specified resampling, gate the ratio with that actual interval, and report the W1 accuracy/freshness/cost delta when the interval shows W1 is better; distinguish invalid/missing data from that conclusion.

9. **Major — `apps/eval/src/harnext_eval/e2/run.py:108-118` as consumed by `apps/eval/src/harnext_eval/e5/run.py:298-309`.** The exact E2 score is the mean over the five named families (§7 E2 line 291), but `macro_accuracy` averages only families that happen to be present after filtering. E5 performs no check for 300 probes, 60 per family, or the minimum entity coverage; a one-family fixture is accepted as `macro_acc`. Leakage exclusions can also remove an entire family and silently change the estimand between cadence arms. **Minimal fix:** validate the frozen probe population, compute over the fixed family set (with code localisation mapped as specified), and invalidate rather than renormalize when a required family is absent; pair on the identical kept-probe set.

10. **Major — `apps/eval/src/harnext_eval/replay/driver.py:153-185,191-193` (selected by `apps/eval/src/harnext_eval/e5/run.py:376-377`).** When a fast event arrives, the shared driver folds it immediately but leaves older pending batch events for that entity open. Those older events can be folded after the newer fast event at a later gap/final flush, regressing curated state and producing non-monotonic snapshot event times. The local E5 loop correctly flushes the entity before fast incorporation at `run.py:164-168`, but only W1 uses that loop. This violates identical chronological replay, state fidelity, and trustworthy final-store accuracy. **Minimal fix:** flush the affected entity's pending batch window at the fast event's replay time before the fast fold, and assert snapshot/commit clock monotonicity.

11. **Blocker — `apps/eval/src/harnext_eval/e5/run.py:62-94`.** Cost must come from provider usage records at frozen prices (§7 E5 lines 428, 445, 447). If a fold emits no provider record, `MeteredStoreHandle` fabricates one by tokenizing raw event JSON and inventing output tokens as 20% of input. S0/S1 have no builder-provider call, yet this turns them into positive-dollar “provider usage”; the `checks.cost_from_usage` flag later passes merely because the fabricated row exists. **Minimal fix:** never synthesize provider usage. Distinguish zero-cost non-provider folds from real provider calls, require authentic successful provider records for LLM-built conditions, and fail the cost-validity gate on missing/malformed usage.

12. **Major — `apps/eval/src/harnext_eval/e5/run.py:33,206-234`; `apps/eval/src/harnext_eval/cli.py:370-381`.** Prices are not demonstrably frozen. E5 silently falls back to hard-coded unversioned defaults, fills missing price fields independently, and uses a positive provider-reported `cost_usd` directly instead of recomputing from tokens at the frozen table. The CLI does not pass prices or a preregistration reference into the manifest, so `manifest.json` records `{}` for prices and no prereg ref. This violates §2 line 40, §7 E5 line 447, §8 lines 526-527, and §11 line 562. **Minimal fix:** make a complete model/date-specific price table mandatory in the preregistered config/manifest, reject missing fields, and always recompute cost from authentic input/output/cache usage using that table.

13. **Major — `apps/eval/src/harnext_eval/e5/run.py:187-189,399-412,454-459`.** The builder-run validity check is self-referential. `_shared_replay` returns `store.fold_count`; `builder_runs` is the number of rows the same wrapper creates or patches once per fold. Comparing them does not independently check the classifier's window-close count, as §7 E5 line 447 requires, and it conflates fast-event runs with batch window closes. **Minimal fix:** take independent `DriverStats`/classifier close-reason counts and the decision log, count successful provider builder invocations separately, define how fast runs enter the expected total, and compare those independent values.

14. **Major — `apps/eval/src/harnext_eval/e5/run.py:427-460`.** The primary ratio is calculated without requiring the named validity checks to pass. It can be reported while cost provenance is false, run counts disagree, pass-through calibration fails, freshness rows are incomplete, or leakage/budget checks (currently discarded) fail. Reporting booleans next to an otherwise valid-looking primary does not enforce the gates. **Minimal fix:** define one `valid_primary` conjunction over every E5/shared validity condition and emit the primary as unavailable with explicit reasons unless all gates pass.

15. **Major — `apps/eval/src/harnext_eval/e5/run.py:339-347,361-365,475-486`; `apps/eval/src/harnext_eval/cli.py:384-408`.** E5's procedure calls for replicated store builds (E5 says two seeds; §8 line 507 requires at least three for every LLM-built store), paired reporting, and between-seed spread. One `run_cadences` call handles one seed, and the CLI merely writes each seed into an isolated directory; there is no cross-seed aggregation, spread, or effect-vs-randomness check. The seed is used for directory names and E2 statistics, not passed to or logged by the builder provider, so stochastic builder variation is uncontrolled. **Minimal fix:** run the preregistered number of seeds, log provider/model determinism settings, aggregate paired cadence effects across seeds, and report accuracy/health/cost spread before permitting a claim.

16. **Major — `apps/eval/src/harnext_eval/e5/run.py:475-486`; `apps/eval/src/harnext_eval/cli.py:370-381`.** The registered experiment accepts any `CorpusHandle` and can emit an E5 result for the small generic synthetic smoke corpus. It does not require Corpus R-H1 and OrgForge S, their frozen hashes, E2 probe counts, constructed world-state labels, or the G4 prerequisites named in §6/§7/§10. The manifest call also supplies no `prereg_ref`, and there is no `apps/eval/PREREG.md` in the tree. **Minimal fix:** mark smoke output explicitly non-evidentiary, validate corpus/window/probe/label identities and hashes for claim runs, require the G4 artifacts, and refuse a claim-bearing run without a committed preregistration reference.

17. **Blocker — `apps/eval/configs/baseline-minimal.yaml:9-18`, `apps/eval/configs/s3-curated.yaml:9-12`, and `apps/eval/src/harnext_eval/e5/run.py:299-307`.** The available fake path can make E5 vacuous. The baseline uses S0 plus a fake reader. S0 stores event bodies under date/ID paths (`apps/eval/src/harnext_eval/stores/build_s0.py:56-67`), while A4 starts at INDEX/OVERVIEW and follows only entity-matching links/paths (`apps/eval/src/harnext_eval/e2/arms.py:200-243`); for ordinary IDs it therefore exposes only index links, and the lexical fake reader returns `UNKNOWN` for all cadence stores. The supplied “curated” config still uses the fake reader, and a fake S3 builder reports zero provider usage and retains only a last-build marker. Scores can consequently be identical across arms while checks pass or the primary becomes NaN. This violates PLAN line 81's requirement that fake providers be non-trivial and cannot support E5's fidelity claim. **Minimal fix:** label fake runs as plumbing-only, add a deterministic fake store/reader fixture whose answers genuinely depend on cadence and include all probe families, add an all-arms-identical non-triviality gate, and use the fixed `claude-sonnet-5` builder/read agent for claim results as D4 requires.

18. **Major — `apps/eval/src/harnext_eval/e5/run.py:350-368`.** A repeated run into the same output directory reopens the existing git store and `usage.jsonl`; no emptiness check, immutable run ID, or resume protocol exists. Prior usage rows are included in cost/run counts, while store layouts may skip already delivered event IDs, so the same nominal seed/replay can produce different metrics after a retry. This breaks deterministic paired comparisons. **Minimal fix:** require a fresh empty cadence/seed directory (or implement a validated manifest-based resume that truncates to a known checkpoint) and reject mismatched or pre-existing artifacts.

19. **Major — `apps/eval/src/harnext_eval/e5/run.py:394-449,488-499`.** The reporting contract is incomplete. `cost.csv` contains dollars but no input/output tokens or builder/read latency beside accuracy, contrary to §2 line 39 and §8 line 509. The named `pareto.png` is not written by `run_cadences` or listed in its artifacts; only an extra `pareto.csv` is written, while the CLI later places the image under `charts/pareto.png` rather than the specified E5 output path. There is also no aggregate cross-seed table/CI. **Minimal fix:** write the named `pareto.png` as an E5 artifact, add authentic token and latency columns beside every quality row, and emit an aggregate paired/seed-spread table.

20. **Major — `apps/eval/tests/test_e4e5/test_runs.py:152-160,185-203`.** The only E5 test does not actually create different cadences. Events for each subject are three minutes apart, but W5's scaled gap is 7.5 seconds (`apps/eval/src/harnext_eval/e5/run.py:104-114`), so every W5 window closes after one event and has the same run cadence as W1. Assertions merely require positive cost/runs and non-negative freshness; the latter is guaranteed by the production `max(0, ...)` clamp. **Minimal fix:** use multiple sub-gap events for the same entity, assert exact independent close/run counts, exact event-clock freshness values (including gap and cap closures), and a lower W5 cost/run count than W1.

21. **Major — `apps/eval/tests/test_e4e5/test_runs.py:164-203`.** The E5 test uses one extraction probe, fake S0, one seed, and only W1/W5. It never exercises either primary arm (`W20+rules`), R5/deviation, revealed/injected urgency, all E2 families, stale-gold leakage, the 8k budget, admission budget, frozen provider prices, the equal-accuracy CI gate, price-of-freshness reporting, failed validity gates, missing usage/events, rerun determinism, or the named `pareto.png`. It also does not assert any accuracy, so identical scores across all cadences pass. **Minimal fix:** add formula-level unit tests with hand-calculated expected CSV values and adversarial failures, plus an end-to-end paired fixture covering all six cadences, all required probe families/labels, authentic usage rows, multiple seeds, and every named validity/output condition.

**Verdict.** E5 is not faithful to the specification, and its current results cannot be trusted. The nominal “ours” arm is not R5, routing has future-dependent admission and no audited total budget, urgency and freshness use the wrong gold/clock, probe cutoffs are rewritten without re-deriving gold, provider costs can be fabricated, and equal accuracy is not established with paired entity-clustered inference. Before interpreting any result, the implementation must make routing causal and genuinely R5, derive labels/freshness/gold exactly as specified, enforce and surface all validity gates and frozen accounting, run and aggregate the required real/simulated corpora and seeds, and replace the vacuous test/fake path with fixtures that would fail each defect above.
