# R1 review — E4 context envelope

1. **blocker — `apps/eval/src/harnext_eval/e4/run.py:131-144, 430, 723-754`; `apps/eval/configs/s3-curated.yaml:9-11`; `apps/eval/src/harnext_eval/e4/tasks.py:181-195, 307-320`; `apps/builder/src/harnext_builder/harness/fake.py:25-44`; `apps/eval/out/20260830T160141Z-baseline-minimal/e4/seed-1/metrics.csv:2-6`.** **Spec:** E4 is an ablation of context handed to a fixed action agent, run three times per task, whose primary `Q` must be capable of distinguishing envelopes (§7 lines 372, 410, 414). **Code:** the runner resolves the configured reader provider, but every supplied runnable E4 profile—including the real S3 profile—configures that provider as `fake`; the special fake path then bypasses `FakeLLM.complete` with a regex extractor. Every arm contains the trigger, `_empty_gold` generally requires only its issue key, and the fake extractor cites every issue key it sees. Tasks with only Place/Text gold are still admitted, so their primary score collapses to `id_cov = 1` in every arm. Independently, the fake S3 builder writes only root `INDEX.md`/`_meta/last_build.md`, not entity OVERVIEW/timeline/facts files, so V3 and V6 can both reduce to the trigger. The checked-in run demonstrates both failures: all five run arms have `Q=1.0`, `pass3=1.0`, all four contrasts are zero, and V3/V6 have equal median size. **Minimal fix:** supply and record a fixed real action-provider/model configuration for substantive E4 runs; reserve fake providers for plumbing tests; either make fake S3 produce non-trivial entity state or mark E4 unavailable on it; require primary-score-eligible gold; and add a non-vacuity gate that rejects/report-only runs where the primary score is constant across arms.

2. **blocker — `apps/eval/src/harnext_eval/e4/run.py:738-743`; `apps/eval/src/harnext_eval/cli.py:182-188, 393-399`.** **Spec:** every envelope must be evaluated against the same fixed S3 store (§7 line 372). **Code:** `E4Experiment` accepts any `StoreHandle` from corpus metadata without checking `layout`. In a normal, non-smoke baseline run the CLI need not build S3 and falls back to the configured store (S0 in `baseline-minimal.yaml`), so the purported envelope experiment can run on S0. **Minimal fix:** require `store.layout == "S3"`, always build/load the preregistered S3 seed for E4, and fail rather than silently substituting another layout.

3. **blocker — `apps/eval/src/harnext_eval/e4/tasks.py:201-290, 293-324, 396-422`.** **Spec:** Corpus S fast tasks are injected situations with scripted correct handling and required IDs derived from world state (§7 lines 387 and 414; §4 line 129). **Code:** task construction is corpus-agnostic: even when `corpus="synthetic"`, it selects rule-promoted log events and derives pseudo-human later-event gold. There is no injected-situation/world-state path or deterministic scripted action derivation. **Minimal fix:** implement a distinct Corpus-S loader keyed by situation onset and world-state snapshots, derive the scripted handling and required IDs from that state, and reject synthetic E4 runs lacking those artifacts.

4. **blocker — `apps/eval/src/harnext_eval/e4/run.py:388-397, 470-495`; `apps/eval/src/harnext_eval/e4/tasks.py:368-389`.** **Spec:** for each sampled batch window, run the builder with Vx, apply its delta to a scratch copy, then run the entity's E2 probes and validate the delta's evidence IDs (§7 lines 388, 410-414). **Code:** batch tasks go through the fast `ActionPrediction` call, no builder or scratch copy is used, and `_batch_accuracy` merely checks whether any normalized gold string is a substring of the pre-delta envelope. Generic probes are paired only when their existing timestamp exactly equals a computed window close, which can yield no batch population at all. **Minimal fix:** sample 150 window closes per corpus, generate/select E2 probes at those closes, run an envelope-driven builder on an isolated snapshot checkout, apply the delta, and grade the resulting state through the real E2 pipeline.

5. **blocker — `apps/eval/src/harnext_eval/e4/run.py:549-574, 665-681`.** **Spec:** primary V3−V1 and V3−V6 comparisons are paired per task and must report entity-clustered BCa 95% CIs with 10,000 resamples; binary comparisons use McNemar and secondaries use Holm–Bonferroni (§7 lines 412-414; §8 lines 503-510). **Code:** `contrasts.csv` contains only `n` and an unweighted mean delta after averaging repetitions. It has no entity clustering, CI, McNemar result, p-value, practical threshold, or Holm adjustment, yet those point estimates are returned as primary results. **Minimal fix:** call the shared clustered BCa/McNemar/Holm implementations on paired task-level values, write all inference columns, and suppress conclusions when required inference or preregistered practical thresholds are unavailable.

6. **blocker — `apps/eval/src/harnext_eval/e4/run.py:359-379, 445-468`.** **Spec:** the per-item leakage gate must prove the maximum event delivered before the snapshot is at most T, reject question tokens that exist only after T, prove every gold action is after T, prove the gold action is absent from the envelope, and log the snapshot identifiers (§4 lines 148-157; §7 line 408). **Code:** E4 implements a weaker private gate instead of the shared delivery-ledger gate. It trusts `snapshot.T_last_event`, does not inspect delivered events, omits the question-only-after-T check for batch probes, and searches only gold source event IDs—not gold assignee/component/priority/reply/action values—in the envelope. An empty `decision_times` list passes `gold_after_T` vacuously. **Minimal fix:** use `harnext_eval.replay.gate.leakage_gate` with the delivery ledger, all corpus events, every batch question, every gold decision time, and serialized gold action values; require non-empty times for fast-task gold and exclude any failure.

7. **major — `apps/eval/src/harnext_eval/e4/run.py:444-469, 518-546`.** **Spec:** all comparisons are paired on identical tasks (§2 line 37; §7 line 412). **Code:** leakage is evaluated per task×variant and only the failing variant is skipped. Per-envelope metrics can therefore use different task sets, while `accepted_tasks` records a task if any arm passes. **Minimal fix:** prebuild/gate every requested envelope for a task and exclude the task from all arms if any arm fails; log exclusions once per task and assert identical task IDs across conditions before aggregation.

8. **major — `apps/eval/src/harnext_eval/agents/envelope.py:222-236`; `apps/eval/src/harnext_eval/config.py:72-79`.** **Spec:** V1 has two separate conditions, raw last-N with `N ∈ {20, 100}` (§7 line 395). **Code:** there is one variant label, `V1`, with one `raw_n` value. The production caller passes a mapping that has neither override, so all runs use 20; there is no configuration or output identity for a 100-event arm. **Minimal fix:** materialize and report distinct `V1-N20` and `V1-N100` cells (or an equivalent explicit factor) and include both in paired analyses.

9. **major — `apps/eval/src/harnext_eval/agents/envelope.py:239-255`; `apps/eval/src/harnext_eval/e4/run.py:144-149, 486`.** **Spec:** V5 is V3 plus callable just-in-time `read_state`, `search_facts`, and `recent_events` tools, isolating pull versus push (§7 line 399). **Code:** V5 text is exactly V3 and only a list of tool names is attached. The provider protocol receives no tools, no tool is executed, and `tool_calls` is falsely reported as `len(envelope.tools)` (three) rather than actual calls. **Minimal fix:** expose real snapshot-bounded tool callbacks to the agent, execute/log each call and returned material, enforce its cutoff/budget, and count observed calls only.

10. **major — `apps/eval/src/harnext_eval/agents/envelope.py:216-217, 245-247`.** **Spec:** V7 adds the relevant entity's `superseded.md` bodies to V3 as a controlled distractor (§7 line 401, in an entity-context ablation). **Code:** although `entity_files` is already computed, V7 searches `files`, the entire snapshot, so it can concatenate superseded bodies from unrelated entities. This changes more than the intended distractor and can expose cross-entity facts. **Minimal fix:** search only `entity_files` (and explicitly documented entity-global metadata if intended), with a test containing two entities.

11. **major — `apps/eval/src/harnext_eval/e4/tasks.py:84-90, 293-324`; `apps/eval/tests/test_e4e5/test_tasks_envelopes.py:78-82`.** **Spec:** real fast tasks are new Blocker/Critical issues, `[VOTE]` threads, or CVE mentions (§7 line 375). **Code:** `is_rule_promoted` is type/source-blind and treats any later priority transition to Blocker/Critical as a new fast task; it likewise accepts `[VOTE]`/CVE text in any event type. The test explicitly locks in the wrong behavior by expecting the later Blocker priority-change event as a second task. **Minimal fix:** constrain each rule to its specified event/source shape (issue creation for declared priority, mail thread for VOTE, applicable CVE-bearing events) and correct the test.

12. **major — `apps/eval/src/harnext_eval/e4/tasks.py:302-324, 373-393`; `apps/eval/src/harnext_eval/e4/run.py:577-639`.** **Spec:** E4 needs 150 fast and 150 batch tasks per corpus, sampled with per-archetype/source counts and no archetype above 40% (§7 lines 374-375, 388, 422). **Code:** task selection takes the chronologically first 150, batch selection likewise takes the first exact timestamp matches, and the only acceptance check is that more than zero tasks survived. Balance and sample shortfalls are informational flags; primary results are still returned when they fail. **Minimal fix:** implement seeded, preregistered stratified sampling; require the specified cell sizes (or record a preregistered shortfall rule); and invalidate primary reporting when balance/sample gates fail.

13. **major — `apps/eval/src/harnext_eval/e4/tasks.py:92-103, 149-159, 261-271`.** **Spec:** Place gold is the union of files from PRs whose **title carries the issue key**, merged within 14 days; test files count and only formatting-only PRs are excluded (§4 line 130; §7 lines 383, 386, 418). **Code:** `_issue_keys` scans every field in event data, so a structured field/body is enough even when the title lacks the key. `_formatting_only` also declares every all-`.md`/`.txt`/`.rst` PR formatting-only, incorrectly excluding substantive documentation changes. **Minimal fix:** join on the title field exactly, report measured join precision/recall, union all qualifying PR diffs, and exclude only PRs explicitly/independently classified as formatting-only.

14. **major — `apps/eval/src/harnext_eval/e4/tasks.py:162-170, 272-278`.** **Spec:** Text gold is the first committer comment/reply after T (§4 line 129; §7 line 384). **Code:** when no explicit committer flag or role is present, `_is_committer_reply` returns true, so the first ordinary user comment becomes gold. **Minimal fix:** require membership in a published committer identity list or an explicit authoritative committer role; treat unknown identity as ineligible, not committer.

15. **major — `apps/eval/src/harnext_eval/e4/tasks.py:181-198, 261-271`.** **Spec:** Corpus-R `required_ids` are the issue key plus linked PR/KIP keys; Corpus-S IDs come from world state (§7 line 414). **Code:** required IDs are initialized only from the trigger and never augmented when linked PRs/reviews/files are discovered. This inflates `id_cov` and is a principal reason the trigger-only fake path scores perfectly. **Minimal fix:** derive the complete required-ID set from all qualifying joins (and world state for S) before grading, and test partial citation coverage.

16. **major — `apps/eval/src/harnext_eval/grade/action.py:95-106`; `apps/eval/src/harnext_eval/e4/run.py:263-284`; `apps/eval/src/harnext_eval/e4/tasks.py:307-309`.** **Spec:** literally, `Q = mean(field_em, id_cov)` and `field_em` is the mean over available gold action fields (§7 line 414). **Code:** the grader silently drops an undefined `field_em` or `id_cov` and averages the remaining components. Because task admission allows Place/Text-only decisions, such a task can receive `Q=1` solely for echoing the trigger ID even though it made no correct action-field prediction; the row then reports `field_em=0` while reporting `Q=1`, an internally inconsistent rendering of the formula. **Minimal fix:** require at least one primary action field and non-empty required IDs for Q-scored tasks (or preregister an explicit NA rule), compute the literal two-component mean, and preserve NA rather than coercing it to zero in output details.

17. **major — `apps/eval/src/harnext_eval/e4/run.py:491-493`.** **Spec:** batch `evidence_valid` means every emitted `evidence_event_id` exists and predates T (§7 lines 411 and 414). **Code:** it merely checks that every predicted citation string occurs somewhere in the envelope text. It neither resolves IDs against the replay nor checks their timestamps, and the action schema does not contain the batch builder's `evidence_event_ids`. **Minimal fix:** grade the applied delta's evidence IDs against an event-id→time index and require `time <= T` for every ID; separately report missing, malformed, and post-T citations.

18. **major — `apps/eval/src/harnext_eval/e4/run.py:27, 297-309, 498-517, 630-663`.** **Spec:** reply quality includes a pairwise judge from a different model family in both presentation orders; a win requires both orders, and the judge is usable only after 200 judgments per corpus are calibrated against two humans at κ≥0.6 (§7 lines 384, 411, 414, 419-420). **Code:** the runner never calls `judge_pairwise_stable`, never emits `judge_win`, hard-codes both validity checks false, and writes a one-row NaN placeholder `judge_kappa.csv`. ROUGE-only fallback is allowed after failed calibration, but no calibration was attempted and the required secondary result is absent. **Minimal fix:** implement the two-order different-family judge, ingest the 200×two-human calibration set per corpus, compute κ and gate usage; otherwise explicitly mark the judge secondary unavailable rather than presenting a completed E4 run.

19. **major — `apps/eval/src/harnext_eval/agents/envelope.py:224-258`; `apps/eval/src/harnext_eval/e4/run.py:593-605, 665-681`.** **Spec:** V3 median must be at most 12k tokens and V6 median at least 3× V3 (§7 line 421). **Code:** envelope construction never consults a context budget or truncates an unbounded OVERVIEW, while the runner only records post-hoc booleans and still publishes primary contrasts when either size gate fails. 20. **major — `apps/eval/src/harnext_eval/e4/run.py:345-356, 613-629, 729-736`.** **Spec:** bot-set gold is excluded, and PR-key join precision and recall are measured and reported (§7 lines 386, 408, 418). **Code:** preloaded task files bypass derivation; bot contamination is only turned into a boolean check and never excluded. 21. **major — `apps/eval/src/harnext_eval/e4/run.py:475-517, 537-546`.** **Spec:** cost per envelope is analyzed, and every quality number is printed beside tokens, dollars, latency, and tool calls (§2 line 39; §7 lines 412, 414; §8 line 509). **Code:** runs retain input/output token counts and latency, but `metrics.csv` omits output-token totals and all dollar costs; no configured/model price is applied. **Minimal fix:** aggregate input/output tokens and provider-recorded/frozen-price dollars per task and envelope, and include them alongside every quality row and contrast.

22. **major — `apps/eval/src/harnext_eval/cli.py:384-408`; `apps/eval/src/harnext_eval/e4/run.py:499-575`.** **Spec:** LLM-built stores use at least three seeds and reporting includes between-seed spread; repeated task runs produce `pass^3` (§8 lines 503, 507). **Code:** the CLI writes an independent E4 result directory per seed but never combines them, so no E4 between-seed spread or across-seed contrast exists. 31. **major — `apps/eval/src/harnext_eval/e4/run.py:52-57`; `apps/eval/src/harnext_eval/e4/tasks.py:232-259`; `apps/eval/src/harnext_eval/grade/action.py:83-94`.** **Spec:** Category gold can contain component(s), duplicate-of decisions, and priority changes, with exact-match scoring; the typed prediction has one value for each category field (§7 lines 382 and 410). **Code:** gold derivation accumulates every distinct value observed in the time window, while the prediction schema is singular and `_set_exact` compares the singleton prediction set to the full accumulated gold set. Any task with two qualifying component/priority/duplicate values is therefore impossible to score correct even if it predicts one valid human decision. **Minimal fix:** either make category predictions lists and compare the intended unordered sets, or define the gold values as accepted alternatives and score membership; freeze that interpretation in hand-calculable tests.

**Verdict.** The experiment is not faithful to the specification and its current results cannot be trusted. The primary path can run a non-S3 store with a deterministic fake action extractor that makes `Q` identical across envelopes; Corpus-S constructed gold and the entire batch-delta experiment are absent; leakage proof, exact required-ID handling, intended V1/V5/V7 variations, judge calibration, size gating, dollar accounting, and paired clustered inference are incomplete or wrong. Before interpreting any result, E4 must be wired to a fixed three-seed S3 plus a fixed real action model, implement constructed S gold and true scratch-delta batch evaluation, use the full shared leakage gate and correct gold joins, complete every envelope condition and exact metric, enforce validity gates, and replace structural smoke assertions with hand-calculable and adversarial end-to-end tests.
