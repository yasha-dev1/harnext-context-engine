# T8 — E4 envelope and E5 cadence status

## Built

- `src/harnext_eval/e4/tasks.py`
  - selects rules-floor fast tasks for declared Blocker/Critical, `[VOTE]`, and
    CVE events;
  - derives only post-T gold into people/category/place/text with per-group
    coverage, configured bot exclusion, time horizons, merged-PR file unions,
    module gold, and formatting-only exclusions;
  - pairs E2 probes with their entity window at the exact batch close.
- `src/harnext_eval/agents/envelope.py`
  - builds V0–V8 with a byte-identical prefix, exact V3 tails/top-k limits,
    V4 actions, V5 tool list, V6 entity files, V7 superseded bodies, deterministic
    V8 position ablation, and per-section token accounting.
- `src/harnext_eval/e4/run.py`
  - typed action schema, deterministic evidence-derived FakeLLM path, three-run
    task matrix, shared T4 action/localisation/ROUGE graders, leakage gate,
    pass^3, token medians, size checks, task balance/coverage, and the four named
    paired contrasts;
  - writes `runs.jsonl`, `metrics.csv`, `contrasts.csv`, `sizes.csv`, `gate.csv`,
    `judge_kappa.csv`, and `balance.csv` and registers `e4`;
  - builds the fixed S3 store through T2/T5 when available and retains a local
    offline S3-shaped fallback for isolated T8 checkouts.
- `src/harnext_eval/e5/run.py`
  - implements W1, W5, W20, W50, W20+rules, and W20+rules+deviation with D7
    proportional gap/max-age scaling and W1's last-1,000-event restriction;
  - invokes T2's replay driver and T5's configured layout, metering every fold
    into `usage.jsonl` without double-counting T5 records;
  - computes frozen-price `cost_1k`, `runs_1k`, first-fold freshness per event,
    urgent/routine p50/p95, final-store E2 macro accuracy through T7, T4 health
    fragmentation, equal-accuracy gating, and the primary W20+rules/W1 ratio;
  - writes `cost.csv`, `freshness.csv`, and `pareto.csv` and registers `e5`.
- `tests/test_e4e5/`
  - synthetic coverage for rules task selection and four gold groups, bots,
    batch/probe pairing, V0–V8 structure and size, 3 tasks × 3 envelopes × 3
    FakeLLM runs, and two-cadence E5 cost/freshness.

## Run

```bash
uv run pytest apps/eval/tests/test_e4e5 -q
uv run ruff check apps/eval
uv run pyright apps/eval/src apps/eval/tests
```

`run_e4(...)` accepts explicit tasks/store/provider/variants for focused runs.
`run_cadences(...)` accepts a cadence subset for smoke tests; the registered
experiment runs all six conditions.

## Stubbed or deferred

- No human/judge calibration fixture exists in the offline corpus. E4 therefore
  emits `judge_kappa.csv` with `used=false`, marks the judge validity checks
  false, and uses deterministic ROUGE-L as required when kappa is unavailable.
- The shared builder contract has no envelope-driven scratch-delta entry point.
  Batch tasks are paired and receive an offline envelope-based E2 score; a real
  scratch-copy builder delta remains an explicit T11 integration item.
- T0's strict `EngineConfig` has no prices field. E5 reads frozen prices from a
  future `cfg.prices` when exposed, currently accepts `corpus.meta["prices"]`,
  and otherwise uses documented immutable offline defaults (input $3/M,
  output $15/M).

## Integration notes

- Importing `harnext_eval.e4` or `harnext_eval.e5` replaces the corresponding
  registry stub. T11 still owns CLI import wiring.
- E5 uses fold records containing event IDs and snapshot commit replay times,
  which is the spec-approved alternative to `git log -S` and avoids filesystem
  scans per event.
- The only local fallbacks are guarded imports for T2/T4/T5/T7 absence; with the
  complete workspace all shared implementations are used.
