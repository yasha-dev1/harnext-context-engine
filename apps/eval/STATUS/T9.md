# T9 E6 throughput and bursts status

## Built

- `src/harnext_eval/e6/loadgen.py`
  - replay fitting for full per-entity inter-arrival samples and summaries,
    empirical popularity, fitted Zipf exponent, type mix, Kim--Jo finite-size
    corrected burstiness B, and adjacent-interval memory coefficient M;
  - monotone timestamped steady, Poisson, calibrated Pareto ON/OFF, benign
    5x flash-crowd, anomalous hot-entity/type-shift, Zipf-hot, and optional
    worker-kill schedules;
  - deterministic bisection of the Pareto ON-period tail index against realised
    B, with convergence metadata.
- `src/harnext_eval/e6/metrics.py`
  - urgent-event 2 s SLO attainment and gap(B), D10 topology demand, batch and
    fast percentiles, drain/recovery time, lag trends, partition-lag Gini,
    cross-entity fairness, and duplicate/missed accounting.
- `src/harnext_eval/e6/run.py`
  - open-loop in-process single-/two-lane runner using T2 router-policy and
    event-clock window semantics with a deterministic constant-time fake fold;
  - lazy Kafka transport (broker-free imports) with optional processed-output
    topic timings;
  - intended-send skew measurement, HdrHistogram output, 25% warm-up, >=3
    repetitions, steady knee finder, 1.0x/1.5x burst matrix, the full topology
    grid, guard ablations, worker-kill recovery, 10 s self-amplification buckets,
    D10 checks, and 10 ms calibration;
  - registered `E6Experiment`, named CSV/HGRM artifacts, fitted-workload table,
    and working T10 chart hooks.
- `tests/test_e6/`
  - known-sequence B tests, Pareto calibration convergence, monotonicity for all
    shapes, hand-built SLO/demand/Gini metrics, a sub-five-second in-process
    sweep with histogram/knee assertions, 10 ms calibration, and live chart-hook
    generation.

## Run

```bash
uv run pytest apps/eval/tests/test_e6 -q
uv run ruff check apps/eval
uv run pyright apps/eval/src apps/eval/tests
```

The registry-facing experiment uses the bounded offline `BenchmarkConfig()` so
`eval-smoke` remains practical. A wall-clock research matrix with the fitted
mean rate and the full 10-minute flash window is available through
`BenchmarkConfig.research(fit)` and `run_benchmark(...)`.

Each experiment directory writes `knee.csv`, `hdr/*.hgrm`, `burst_slo.csv`,
`self_amplification.csv`, `demand.csv`, `guards.csv`, and `workload_fit.csv`.
`chart()` adds `e6_burst_slo.png`, `self_amplification.png`, and
`demand_curve.png` through T10.

## Stubbed or deferred

- No broker is required or contacted by offline tests. The Kafka path is fully
  lazy but was not exercised against a live broker; true agent-start latency on
  that path requires the configured output topic to emit `event_id`,
  `agent_start_ts`, lane, and optional batch-fold latency.
- Broker CPU/disk collection belongs to the deployment telemetry feeding the
  Kafka run. In-process results report no broker telemetry and do not claim the
  broker-monitoring validity check.

## Open integration questions

- None for offline integration. A production Kafka benchmark must supply the
  broker endpoints/topics and external resource telemetry.
