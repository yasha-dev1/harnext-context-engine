# Kafka benchmark review release — 2026-09-12

The [full review SPA](../benchmarks/kafka-1000-v1/review.html) contains **1,000
instances from 1,000 distinct Jira issues**, grouped into 998 issue/PR lineages.
It was opened successfully in Firefox. All tasks are from apache/kafka.

There are 800 historical questions: 100 each for assignee, status, resolution,
Closed/not Closed, priority, status history, assignment history and resolution
history. Their contract permits only Harnext MCP. The 200 coding candidates
permit Harnext MCP plus sandbox shell and contain reconstructed issue text,
a pinned base before target PR creation, visible test patches and evaluator-only
reference implementation patches.

## Validation completed

- 15,811 data checks passed, including independent recomputation of all 800
  historical answers from raw changelog records and chronology/patch-integrity
  checks on all 200 coding candidates.
- All 1,000 prompts rendered in an actual browser. Search, category filters,
  prompt downloads, detail tabs, review persistence, review export/import and
  mobile overflow checks passed. Zero JavaScript errors or external requests.
- The normalized context corpus passed schema and unique-ID validation:
  45,511 source records / 113,271 structured facts, including distractor issues
  and historical commit/PR/file relationships.
- All 48 E2 tests passed in 8.36 seconds. Targeted Ruff and Pyright checks passed.
- Regenerating from frozen inputs reproduced all five dataset exports byte-for-byte,
  including the manifest, reviewer bundle, public/private tasks and context corpus.
- The Closed category was corrected during development from a degenerate
  all-false sample to exactly 50 true / 50 false. Status and resolution answers
  were stratified for label diversity before freezing the review release.

## Deliberately pending

No agent experiments were run. User review/approval is required before experiment
execution. The 200 coding candidates passed patch application on the earlier base
files, **not** execution of Gradle tests. Their environments, base failures,
reference passes and regression sets must be admitted. Representation-specific
evidence mapping and external harness capability enforcement also need execution
gates before scientific runs. These limitations are visible per task in the SPA.

Review decisions and notes can be exported as JSON bound to this dataset hash.
Approving a row does not launch an experiment. The full
[dataset card](../benchmarks/kafka-1000-v1/README.md) documents sampling, temporal
reconstruction, scoring, source scope and remaining threats to validity.
