# T5 store variants status

## Built

- `src/harnext_eval/stores/build_s0.py` — deterministic dump layout with one
  event markdown file under `events/YYYY/MM/DD/` and a minimal rebuilt index.
- `src/harnext_eval/stores/build_s1.py` and `templated.py` — no-LLM entity
  projection with current structured fields, dated facts, append-only timelines,
  supersession history, and a current entity index.
- `src/harnext_eval/stores/build_s2.py` — builder-harness flat curation variant
  with a dedicated seed/prompt and no durable `INDEX.md` or `topics/` tree.
- `src/harnext_eval/stores/build_s3.py` — standard seeded builder layout using
  the harnext builder runner protocol directly against the git worktree, with
  rollback on harness failure and transcript usage accounting.
- `src/harnext_eval/stores/build_s4.py` and `vector_index.py` — raw-event vector
  index persisted as `embeddings.npy` plus JSON IDs/documents/metadata, exact
  cosine top-k search, historical snapshot loading, and per-fold indexed-event
  counts.
- `src/harnext_eval/stores/build_s5.py` — S3 curation followed by a per-fold
  vector rebuild over durable store-file chunks and event citations.
- `src/harnext_eval/stores/layouts.py` — S0-S5 registration through T0's
  `register_layout()` hook, per-store provider configuration, same-input event
  ledger/hash metadata, usage JSONL writing, and a minimal local fold loop.
- `tests/test_stores/test_layouts.py` — synthetic-corpus coverage for all six
  variants through T2's `run_pipeline`, S1 state/supersession, S2 layout,
  S4 historical retrieval, S5 exact-ID retrieval, snapshots, usage, and input
  hashes.

Every layout commits through `StoreHandle.fold()`, so `snapshots.csv` remains
owned and formatted by T0's store foundation. S2/S3/S5 write transcript-derived
accounting to `<store-root>/usage.jsonl`. All variants write the delivered-ID
ledger and `same_input_hash` under `_meta/` inside the versioned store.

## Use

Import `harnext_eval.stores.layouts` once to register S0-S5, construct the T0
`StoreHandle`, and optionally call `configure_store()` before replay:

```python
from harnext_eval.stores.base import StoreHandle
from harnext_eval.stores.layouts import configure_store

store = StoreHandle("S5", "acme", output_dir)
configure_store(store, harness="fake", embeddings=fake_embeddings)
stats = run_pipeline(events, cfg.engine, store)
```

Use `search_store(store, query, top_k=10, ref=snapshot)` or
`VectorIndex.from_store(...)` for S4/S5 retrieval, including immutable historic
snapshots.

## Deferred / integration notes

- The real `claude_code` harness path is wired through the same builder runner
  protocol but was not invoked because T5 verification is offline.
- The vector implementation is an exact in-process cosine index, appropriate
  for the evaluation corpora and fake provider; it is not an approximate
  nearest-neighbour service.
- No shared interfaces or T0-owned files were modified.
