# T11 integration status

## Outcome

The evaluation package now runs E1-E6 end to end through the real registry,
replay, store, grader, chart, and report modules. No `TODO(integration)` marker
remains under `apps/eval/src`.

Successful reports:

- Baseline smoke: `apps/eval/out/20260830T160141Z-baseline-minimal/report.html`
  (843,738 bytes, 11 embedded charts, completed in approximately 5m52s).
- Comparable S1: `apps/eval/out/20260830T174101Z-s1-templated/report.html`
  (924,865 bytes, 11 embedded charts, completed in approximately 2m45s).

The reports are comparable on identical frozen inputs:

```text
replay_hash = 7f48258041fc67649fb0cd8cbf81043318a5c7b7c8804373c92c38292458d67a
probe_hash  = a4f3981538d7e5492262650d5d12e7ae6e06dcdc7bf1360a1ffb714d0dc68ddf
```

Each report contains E1-E6 results, a machine-readable checks dictionary for
every experiment, the HTML pass/fail checks table, per-experiment CSV/JSONL
links, and these 11 charts: E1 calibration/operating curves; E2 family bars; E3
accuracy curve/erosion/health; E4 envelopes; E5 Pareto; E6 burst SLO,
self-amplification, and demand.

## Cross-module changes

- `cli.py`
  - imports/discovers the real E1-E6 adapters instead of executing registry
    placeholders;
  - `corpus` generates synthetic JSONL or validates/loads `--replay` JSONL;
  - `probes` calls the six-family `harnext_eval.probes.gen` implementation and
    writes its SHA-256 sidecar;
  - `stores` builds requested registered layouts through `run_pipeline()` and
    `configure_store()`;
  - `run` accepts `--all`, repeatable `--experiment`, or comma-separated
    `--experiments e1,e3`; applies every configured seed; writes resolved config,
    manifest, replay/probes, store registry, per-experiment result/check JSON,
    artifacts and charts; then calls `build_report()`;
  - store-consuming runs always build S0; E3 additionally builds S1/S4 from the
    same replay; the configured S1/S2/S3/S4/S5 is built when requested; smoke E4
    uses S3; fake-harness optional S2/S3/S5 skips are registered with reasons;
  - generated-synthetic run defaults are the comparable 120-event, 12-entity,
    10-probe/family profile; real `--replay` inputs are never downsampled;
  - top-level boolean `checks` are derived without misclassifying count-valued
    diagnostics.
- `registry.py`: removed T0's six empty `_StubExperiment` registrations; only
  real imported adapters can now be selected.
- `stores/*` integration: all layout registration/configuration is now used
  directly by CLI and E5; no local layout replacement remains.
- `e2/run.py`: replaced the guarded leakage fallback with the real replay gate
  and connected `e2_family_bars`.
- `e2/arms.py`: A4 now reads immutable snapshots through `StoreHandle.list_files`
  and `StoreHandle.read(ref, path)` instead of cloning once per probe. This kept
  traversal/budget behavior while reducing a measured 360-probe E3 cell from
  about 4.5 minutes to under one minute.
- `e3/run.py`: removed dynamic/local health stubs, calls
  `compute_store_health()` on materialised snapshots, supports a smoke-only
  erosion subset, and emits curve/erosion/health charts.
- `e4/run.py`: directly imports shared action/ROUGE/localisation graders and the
  real replay/layout modules; removed the isolated local S3 builder; preserves
  legacy count metrics while adding boolean leakage/task checks; emits the E4
  envelope chart; smoke alone reduces variants/repetitions.
- `e5/run.py`: removed local replay/layout/E2/health fallbacks; directly uses
  `run_pipeline`, `configure_store`, `evaluate_e2`, and
  `compute_store_health`; emits the Pareto chart; smoke alone uses the three
  primary cadence conditions while normal runs retain all six.
- `replay/gate.py`: added a bounded cache for immutable event token sets so E2/E3
  do not re-tokenize the same replay for every probe/store/budget. Gate semantics
  and exclusions are unchanged.
- `report/report.py`: prefers explicit boolean result checks and tolerates empty
  check/contrast CSVs (`pandas.errors.EmptyDataError`), which is valid when an
  optional comparator is skipped.
- `Makefile`: `eval-smoke` explicitly selects 120 events, 12 entities, 10 probes
  per family, and the smoke matrix, keeping the run below 10 minutes.
- `README.md`: documents the full end-to-end and staged command sequence,
  generated-synthetic versus real replay sizing, artifacts, selection flags,
  and the complete baseline-minimal engine behavior.
- `tests/test_core/test_cli_integration.py`: added CLI regression coverage for
  six-family probe generation and the replay -> S0 -> E2 -> chart -> checks ->
  report path.

## Spec items still missing or externally gated

- `PREREG.md` is absent, so preregistration timing/hashes and amendments from
  E1/E2/E3 validity cards cannot be demonstrated by code.
- E1 still writes an empty Phase-2 `harm.csv`; the S3 now-vs-window-close action
  harm experiment is not implemented. Native Parquet also remains optional
  because no Parquet engine is declared; the documented table-JSON fallback is
  used when unavailable.
- The code-location generator samples T before a PR merge and asks about files
  merged in `(T, T+14d]`, while the universal leakage gate rejects question
  tokens that occur only after T. This makes some generated code-location probes
  fail/exclude by design; the experiment card and leakage rule need a clarified
  temporal contract.
- The synthetic corpus has no independent human annotations, judge calibration,
  explicit situation-onset catalogue, or committer/revert coverage. Therefore
  E1 label-function coverage checks and E4 human-judge kappa checks can fail in
  offline reports without indicating a pipeline failure.
- E4's real batch scratch-copy builder delta remains missing because the shared
  builder API has no envelope-driven scratch-delta entry point; offline E4 uses
  the implemented envelope-based batch score.
- E5 configuration still has no first-class frozen-prices field; the runner uses
  corpus metadata or its documented immutable offline defaults.
- E6's Kafka/broker CPU/disk telemetry and live output-topic agent-start timing
  remain externally gated; the offline in-process benchmark does not claim that
  validity check.
- Full 2,000-event S0 and S4 builds rebuild cumulative index/vector artifacts at
  every sparse-event snapshot, and full E4 envelope assembly materialises many
  historical checkouts. They are correct but slow; the explicit smoke profile
  avoids this without changing real replay data.
