# T1 real corpus extractors status

## Built

- `src/harnext_eval/corpus/keys.py`: canonical `issue:`, `kip:`, `pr:`,
  `thread:`, hashed `contributor:`, and normalized `component:` keys; ordered
  `KAFKA-N`/`KIP-N` regex extraction; subject and routing-baseline assignment.
- `src/harnext_eval/corpus/pony_mail.py`: offline monthly mbox and `stats.lua`
  JSON parsing, RFC thread reconstruction, message/tag extraction, and an
  explicit injectable `fetch()` for `mbox.lua` plus `stats.lua`.
- `src/harnext_eval/corpus/jira.py`: Jira search-page parsing into created,
  per-changelog-item transition, and comment events; server-page-size-safe
  pagination; explicit injectable REST `fetch()` using `expand=changelog`.
- `src/harnext_eval/corpus/gharchive.py`: streaming hourly `.json.gz` parsing
  filtered by repository for PR open/merge/close, review, review-comment,
  issue-comment, and push events, including changed files when present; an
  explicit hourly `fetch()` downloader.
- `src/harnext_eval/corpus/build_replay.py`: normalized multi-source merge,
  ID conflict detection, event-time ordering, tenant/key assignment, canonical
  JSONL, exact-byte SHA-256 sidecar, atomic replay writes, and a
  `python -m harnext_eval.corpus.build_replay` CLI.
- `tests/test_corpus/`: 11 offline tests plus realistic Pony Mail, two-page Jira,
  and GH Archive fixtures covering key derivation, source parsing, pagination,
  ordering, CLI output, and hash stability.

## Run

```bash
uv run pytest apps/eval/tests/test_corpus -q
uv run ruff check apps/eval/src/harnext_eval/corpus/{keys,pony_mail,jira,gharchive,build_replay}.py apps/eval/tests/test_corpus
uv run pyright apps/eval/src/harnext_eval/corpus/{keys,pony_mail,jira,gharchive,build_replay}.py apps/eval/tests/test_corpus

uv run python -m harnext_eval.corpus.build_replay \
  --jira-json apps/eval/tests/test_corpus/fixtures/jira-page-1.json \
  --output /tmp/kafka-replay.jsonl --tenant kafka
```

The CLI also accepts repeatable `--input`, `--jira-json`, `--gharchive`, and
`--pony-mbox` inputs. Pony inputs share `--pony-list`, `--pony-domain`, and
`--pony-month`; GH Archive inputs use `--repo`.

## Stubbed or deferred

- Tests perform no network access. Live downloads exist only behind each
  module's explicit `fetch()` and have not been exercised against production.
- The Jira parser emits every changelog item and comment included by the
  expanded search response. Fetching separately paginated per-issue changelogs
  or comment collections, if an installation truncates those expansions, is
  deferred because T1's requested contract is search pagination with
  `expand=changelog`.
- GH Archive normally omits changed-file arrays. The extractor retains them
  when an enriched archive record supplies them; later enrichment is deferred.
