The store build is a one-off per store (shared by an arm and its research-only variant); spread over the tasks of this benchmark it often exceeds the per-trial cost — a store pays off only over many more tasks. For the engine arms the read-agent cost is the engine's: Jev as reported by the provider (OpenRouter); the chat model as reported by OpenRouter or, for a local model, API-equivalent from token counts at list price ($0.018 / $0.09 per million input / output tokens). The outer agent's cost varies up to 4× with its prompt-cache state, so compare medians and spreads over the full task set, not a few trials.

10 Limitations and deviations

  1. F5 builder cadence. Production Harnext runs its builder per entity (20-event windows); the eval hands it 250-event slices with many entity batches per instruction. The F5 store holds an entity for only ~45 % of the window's issues and ~59 % of its PRs, so F5 results understate the product; a rebuild with a per-slice completion check is planned.
  2. Coding workspaces start at the PR's merge parent. Commits merged while the PR was open are in the repository, and Claude Code shows the last five in its system prompt; for 12 of 54 coding tasks these include sibling PRs of the same ticket. It affects all arms equally. A smoke test on one task rebased to the PR's start (all 12 arms) found no difference (12/12 solved both ways, same cost), which rules out a large effect on that task only.
  3. Sample sizes. 12 coding tasks, 1–7 questions per history family (reported only per group), 29 design decisions, 14 implicit links: intervals are wide; read differences through the paired table and its p-values.
  4. Design-decision gold was proposed by an LLM from the thread text and verified automatically (quotes present verbatim in the cited messages), not by a second human annotator; strict and lenient scores are both reported.
  5. Factual-history questions are, by construction, answerable with the systems-of-record CLIs (the answerability audit requires it), so S-tools is an upper bound there; the categories where memory can add value are design decisions and implicit links.
  6. One agent (Claude Code, Haiku 4.5), one trial per task and arm; token refreshes interrupted a few trials, which were rerun (never recorded as failures).
