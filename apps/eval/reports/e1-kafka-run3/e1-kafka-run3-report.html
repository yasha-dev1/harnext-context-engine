Run 3: the budget was not the problem. The guards are.

Every finding of the independent review was fixed and registered before this run. The rule floor now costs 0.8 % of events and no longer saturates the 2 % budget. Verdict: claim C1 falsified again, for a different reason

Primary metric: recall@2 % of revealed-urgent events on the rule-negative population (839 positives, 219 subject clusters, 48 months with positives). R5 (rules share the budget), R8 (rules outside the budget) and R9 (any-key guards) all score 0.000. They are identical in every admission because the budget is no longer binding: the absolute-volume floor and the multi-window confirmation leave 256 of 384,413 rule-negative events eligible at 2 %, and none is positive.

The scorer bake-off registered for this run is unambiguous on this corpus: global HBOS (R2) beats random by 7 points with a confidence interval that excludes zero; every per-entity scorer (R3 gap, R4 HBOS, R6 LOF) sits at or below random. Per-entity keying, the design's central bet, hurts.

The rule floor is fixed and no longer the story

Run 1's rule floor flagged 2.32 % of events, more than the whole 2 % budget in 33 of 52 months. Three registered changes brought it to 0.77 %: [VOTE] fires on thread-initiating messages only, → Critical changelog transitions count as declared priority, and each (subject, rule) pair fires once per month. At 2 % the floor is now feasible in all 52 months; at 1 % it still exceeds capacity in 12 months, which is the only remaining feasibility failure.

Mechanism: the guards block the deviation layer regardless of budget

R8 gives the deviation layer the whole budget. It still fills almost none of it. The absolute-volume floor (≥ 3 events in the entity's 5-minute bucket) and multi-window confirmation (an anomalous score in the immediately preceding bucket) together pass 0.07 % of rule-negative events at 2 % and 0.73 % at 10 %. R9 relaxes the semantics so any baseline key can satisfy the guards; it changes four admissions.

What changed between run 1 and run 3

  • Finding 1 (blocker): the in-flight-release labelling function needed fields no event carries; it abstains and is excluded.
  • Finding 7 (blocker): JIRA components and the component: baseline keys are replayed as-of-event from the changelog; text provenance is measured and declared.
  • Finding 4: [VOTE] thread-start only; → Critical transitions; one firing per (subject, rule) per month.
  • Rule accounting: R8 admits rule hits outside the budget and gives the deviation layer the whole capacity; R9 adds any-key guard eligibility. Both are registered, and both equal R5.
  • Finding 3: positive-support gate (≥ 20 positive votes); the vote-cancel function excluded; positive_rate and accuracy_at_cap in the diagnostics.
  • Finding 2: four label definitions registered for post-hoc sensitivity; votes saved with the run so the table is a re-reading of run outputs.
  • Finding 6: relative sanity tolerance and same-geometry random VUS; mechanical metric-remediation record.
  • Finding 8: timestamped, subject-separated situations derived from consecutive positives drive affiliation and detection delay; row-index metrics demoted to _rowindex.
  • Finding 9: month-cluster confidence intervals as sensitivity; blind human-sanity sheet written by the run.
  • Finding 10: binary empirical calibration rate; prevalence-preserving swap next to the registered flip.
  • Infrastructure: corpus re-fetched on a new machine (same 629,458 events, new hash); GitHub client made quota-aware; policy workers spawned per month instead of forked so memory stays flat.

What this means for the thesis

C1 as designed is falsified on Corpus R. Run 1 could be read as a budget-accounting artefact; run 3 removes that reading. With the operator's rules outside the budget, per-entity deviation scoring with guards admits nothing useful at any budget, and the unguarded per-entity scorer is below random. The claim that survives is narrower and worth making: a budgeted fast lane on real engineering streams needs source-specific scorers, and on JIRA a global histogram-based scorer recovers about 9 % of later-urgent events at a 2 % budget with 0.3 % precision.

Three things remain before any of this is evidence. The human sanity sample (file ready; two annotators, kappa). A registered run 4 with per-source, guard-free scorers as the design condition, not tuned on these months. The Flink replication for the corpus preflight.
